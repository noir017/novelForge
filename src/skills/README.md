# src/skills — 技能包

这个目录放**给代理（Claude Code / 本项目的 agent）用的技能包**，不是 TypeScript 模块。里面一个 `.ts` 都没有，`npm run compile` 与 `typecheck` 都不碰它。

一个技能是一份**带触发条件的工作流说明**：什么时候该用它、按什么步骤做、判断标准是什么。它与 `src/core/context/prompts.ts` 里的提示词是两种东西：

| | 提示词（`core/context/prompts.ts`） | 技能（这里） |
|---|---|---|
| 谁读 | 被调用的模型，每次生成都注入 | 代理，需要时才读 |
| 内容 | 「你是谁、这一次产出什么、什么形状」 | 「怎么判断好坏、怎么修、改哪个文件」 |
| 长度 | 必须短，占的是作者的 token 预算 | 可以长，不进生成上下文 |

所以**方法论放技能，结论放提示词**。技能里那些「可直接粘的条款」是产出物，最终要落到 `style.md` 或 `prompts.ts` 里去；技能本身只负责说清楚为什么是这几条、以及怎么验证它生效了。

| 技能 | 一句话 |

| [chapter-review/](chapter-review/SKILL.md) | 审一章 AI 写出来的正文：定位「AI 味」与「剧情平淡」两类病灶，开出提示词层面的药方 |

## 写一个新技能

一个子目录，入口必须叫 `SKILL.md`，开头是 YAML frontmatter：

```yaml
---
name: kebab-case-名字
description: 做什么 + **什么时候该用它**（触发词写足，代理靠这一行决定要不要读）
---
```

正文写工作流，长内容拆到 `references/` 下按需读——入口文件保持能一口气读完的长度。
