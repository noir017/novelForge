# views — 只读聚合与界面快照

本目录把磁盘上的 Markdown 与工程状态聚合成上层界面需要的只读数据，**不写盘**：

- `projectView.ts`：工程树（「故事架构」六行、章节列表——**一个章号一行**，细纲与正文是同一行的两面；角色/设定是目录树；「叙事线」页签那一列由 `threads.ts` 算，「现在」是定稿到的最后一章）、细纲浮窗（`buildPlotSummaryView`：没定稿的标「计划」，定稿后正文又改过的标过期）与单章流水线视图；章的说法（「第 12 章《夜访》」）由这一层给，前端只渲染。
- `threads.ts`：叙事线一览（叙事线重做第 8 个提交）：工程页「叙事线」页签一条线一行——按主线 → 支线 → 感情线 → 人物线、同种类最近推进的在前（没推进过的排最后、按计划开始的章），一行写「种类 · 状态 · 最近第 N 章（没推进过写计划区间）· 几条伏笔没收」，另给 ⚠（断了几章、几条伏笔逾期、过了计划收束的第几章；收束了的线不报）与悬停看的意图、当前进度；最后是「未归属的伏笔 · N 条」（一条都没有不给）。**纯函数**：吃 `projectView.ts` 那一趟 `readThreads()` 读到的整本与「现在」（定稿到的最后一章），状态现算、不落盘（第 18、28 条），文案只在这里写一份。**三期的「叙事线总览」**（编辑区里的特殊标签，章 × 线的时间轴）也从这里出数据：`buildThreadsOverview(project)` 按需要（`requestThreadsOverview`，不进工程树）读一遍叙事线目录与章节、细纲两份列表（借缓存，不读一章正文），交给纯函数 `buildThreadsMatrix`——列是第 1 章到「计划或已写的最后一章」（有细纲或正文的章、任何事件、伏笔计划埋与收的章、线的计划区间都算；中间没文件的补 `none`、卷名沿用前一章；手误写出的远章号截在 `OVERVIEW_MAX_CHAPTERS` 并说原本到第几章），带卷名（`quickOpen.ts` 的 `volumeOf`）与四种定稿状态；行按种类分组、组里的先后与一行的说法与工程页一字不差（同一个 `lineOf` / `compareLines`），每条线下面是它的伏笔，最后是「未归属的伏笔」；格子只给有事件的章，偏差（计划了、那一章定稿了却没发生）与伏笔的连线（收了实线、埋了没收虚线到回收章——伏笔那一行写的与计划里收它的取晚的、逾期延到现在——、还没埋按计划淡虚线）都在这里算好，前端只画。「现在」与工程页同一个口径。二期加了写前检查要的数：`ThreadsView.watch`（`threadWatch`，按现在算，前端批量写章弹窗拿它算提醒）与读盘的 `threadReminders(project, nos)`（叙事线目录 + 定稿到的最后一章，按第一章 `asOf`；工作台、对话页与批量写章的确认框用它）。
- `pipeline.ts`：读取大纲、配置、细纲与章节，**一个章号一行**（正文按章号认，细纲**按路径配对**：正文镜像的那一份，还没有正文的按号认计划，规则在 `NovelProject.plotFor`），汇总每一章的流水线状态与新鲜度链；给全书状态机取数（`buildBookFacts`，主按钮、工程页、agent 三处共用）；算正文的落点（`chapterTargetOf`：已有正文就是它，否则落在细纲所在的子目录，连细纲都没有就跟上一章同一个子目录）；
- `workbench.ts`：读取当前创作目标，构造「当前产物」浮窗的内容（单条设定目标摊一句话、各节与暗设；还只有一句话的不摊空节，提示 `/展开`；正文目标上还没写的这一章细纲点名、却还只有一句话的设定给一句 `notice`——写前提醒，完善设定三期，`thinLoreFor`，零调用、不拦，与上游变过的 `warning` 分开；「设定」一节空着、已经写了字的章不读设定区；叙事线的两类提醒——伏笔逾期、线断了，叙事线二期，`threads.ts` 的 `threadReminders`——同一个口径，还没写的章才提，与它并在同一句 `notice` 里）；
- `cast.ts`：从各章**定稿过的**细纲（有 `sourceHash`）反向聚合出场人物索引（第 14 条）。没定稿的细纲里写的是计划出场，不算。
- `quickOpen.ts`：「转到…」（独立版 Ctrl+P）要的索引——章节（一个章号一条：章号、标题、卷目录、正文 / 细纲路径、字数）、角色卡（名字与别名）、设定、架构几件与大纲 / 文风 / 叙事线 / 全文大纲（有文件的；称呼与 `editorLabel.ts` 共用 `SETTING_DOC_LABEL` / `FIXED_DOC_LABEL`）、草稿。按需要（`requestQuickOpen`），不进工程树；章节与细纲借 `listChapters()` / `listPlots()` 的缓存，不为它多读一章（读了哪些盘写在文件头上）。
- `nameIndex.ts`：内置编辑器「名词补全」（独立版 Alt+/ 与边打边弹）的名词表——角色卡（名字、别名与名字里括号内外各一截，一个字的不要；一句话取「身份」第一句，没写取标签）、设定条目（标题、关键词、分类即目录、`loreBrief`）、设定名录里出现过还没建条目的名字（`lore.ts` 的 `unknown`：建议分类、最近一章的说明）。**不调模型**。按需要（`requestNameIndex`），前端带着手上那份的指纹（`have`）来，对得上只回指纹（`nameIndexSig`，controller 比）。读盘：卡与条目按「路径 · 大小 · 修改时间」的签名记在内存里（按工程实例），没变一份都不读，变了才整份重读（与 `listCharacters` / `listLore` 同一个解析）；未建条目借 `listPlots()` / `listChapters()` 的缓存、关掉名录的「待整合」那一步（`buildLoreIndex(…, { pending: false })`）。
- `bookFind.ts`：全书查找（独立版「编辑 → 全书查找替换…」，`bookFind` 消息，**只读**）：按范围（正文、细纲、草稿、角色卡、设定条目、其他创作文件，`model/bookFindScope.ts`）列文件——正文与细纲借 `listChapters()` / `listPlots()` 的缓存、按章号，草稿 / 角色卡 / 设定只列不读——再逐份读一次、匹配（口径 `model/bookFind.ts` 的 `fileHits`：`textFind` 去掉护住的字），给出按文件分组的结果：称呼（`editorLabel.ts` 的短标记 + 面包屑最后一段）、读到时的 hash（替换时的乐观锁）、一共几处、每一处的行列与那一行上下文，预览时带换成什么。列满 `BOOK_FIND_LIMIT`（1000）处就停、说停在哪一份上；在两份文件之间看一眼叫停；超过 2 MB 的跳过并列出来。不建索引、不缓存内容（读了哪些盘写在文件头上）。替换在 `features/bookReplace.ts`。
- `chapterIndex.ts`：内置编辑器的章节索引（`chapterIndex` 消息：章节条与上一章 / 下一章要的那几个字段）。与工程树章节那一行**同一个函数投影**（`projectView.ts` 在它上面再加定稿、草稿、⟳），数据是 controller 构建 `ViewState` 时本来就跑的那一趟流水线索引，不多读盘；controller 只在内容变了时推。
- `checkTerms.ts`：内置编辑器「写作体检」的词表（`checkTerms` 消息）：禁用词（`readBannedTerms`——`style.md` 的「禁用词表」、小说配置「全局要求」、`config.md` 的类型 / 子类型交给 `model/manuscriptCheck.ts` 的 `bannedTerms`；**写正文的 `generation/generate.ts` 的 `planWriting` 也调它**，两边同一个函数、同一份输入）+ 自定义敏感词表（`.novelforge/sensitive.txt`，`model/sensitiveWords.ts` 解析，坏行带行号）。读 `style.md` 与 `sensitive.txt` 各一次，`config.md` 由调用方给（controller 构建 `ViewState` 那一趟已经读过）；读不到当没有、绝不抛。controller 每次 `pushState` 都调、内容变了才推（`controller/check.ts`）。
- `editorLabel.ts`：内置编辑器怎么称呼一份文件（标签上的类型短标记与名字、工具栏面包屑），按 `kindOfPath` 与章节 / 细纲的文件名规则算，纯函数、零 I/O、绝不抛（输入是前端传上来的路径）。标题取文件名里的那一段，不读 H1。固定文件的中文称呼（`FIXED_DOC_LABEL`）与「转到…」的索引共用。
- `lore.ts`：设定名录（2026-10-18）。同一个路子：从定稿过的细纲**「设定」一节**聚合出已建条目（出现章、水位之后待整合的新事实——「设定」一节冒号后那句与提到它的连续性事实，工程页的 `＋N`）、**未建条目**（出现过、没有条目的名字，按出现章数排，分类取多数票）、**还没记过设定的定稿章**（「设定」一节标题不在的，补记用）。认条目先标题后关键词，人名不算。工程页刷新时由 `projectView.ts` 把已读的细纲、条目、角色卡传进来，同一次刷新里一个文件只读一次；装配器的 `lore` 层也用它算尾巴。只要出现章与未建条目的调用方（名词补全的 `nameIndex.ts`）传 `{ pending: false }`，跳过「待整合」那一步——它要拿每一章的连续性事实去对每一条条目，几百章 × 几百条时是这里最贵的一段。**待完善**（`thin`，完善设定 2026-10-19，传 `{ thin: true }` 才算，只有工程树要）：名录里唯一往前看的一块——没定稿、也还没写正文（没有章节文件或 0 字）的细纲「设定」一节点名的设定里，还没有条目的、条目还只有一句话的（`loreThin`：空的、新建设定的占位、三节全是「（未交代）」）；每个名字给分类（有条目取所在目录，没有取「设定」一节多数票）、条目路径、哪一种、要用到的章，按最早那一章升序。复用已经读进来的细纲、章节与条目，不多读盘。`projectView.ts` 把它放进工程树的 `loreThin`（一行的说明「第 12 章起要用 · 只有一句话」由这一层给）。条目里有作者的字的（三节全是「（未交代）」却没盖过机器的章、明面空着只写了暗设，`loreMaterial.ts` 的 `loreBatchExpandable` 不认的）标 `authored`：「全部展开」跳过它（三期）。写前提醒要的「这几章要用的」是 `thinLoreFor(project, nos)`：就是待完善里要用到这几章的那几条，口径一字不差，章号只留这几章的。
- `loreMaterial.ts`：一条设定的原料（完善设定，2026-10-19；从 `features/lore.ts` 挪过来，行为不变）：定稿细纲里关于它的全部记录（`recordsAbout`，建条目、整合、展开共用）、整合 / 展开写完水位记到第几章（`integrationWatermark`：第一处没定稿或定稿后正文又改过的章之前）、给模型的记录封顶 `MATERIAL_TOKENS`；展开要的两样原料 `expansionMaterial`——没定稿的细纲里用到它的地方（「设定」一节点名它的那一行，按名录同一张表认；梗概、关键事件里提到它的句子，带章号）与定稿过的记录；`loreEntryAt` 认路径上的那一条条目，文件还不在时按路径拼一条空的；条目正文是不是机器写的（`loreOwnedByMachine`，三期从 `features/lore.ts` 挪过来）与批量展开会不会写它（`loreBatchExpandable`：还只有一句话，而且空的、占位的、机器写的才写；三节全是「（未交代）」没盖章的、写过暗设的都算作者的）。纯读盘、不调模型；装配器（context/ 不依赖 features/）、名录、落盘与 `features/lore.ts` 共用。

新鲜度链：`outline.md` 里覆盖第 N 章那一节 →（`upstreamHash`）这一章的细纲 →
（`writtenFrom`，记在细纲上，定稿时刷新）`chapters/…/N-标题` →（`sourceHash`，定稿时记）同一份
细纲（`summaries/` 下与正文同样的相对路径），全靠比对 hash，零模型调用。细纲内容与 `writtenFrom` 对不上，正文挂 ⟳
（包括定稿之后又改细纲）；`sourceHash` 与正文对不上，这一章回到待定稿。

`chapters/` 是正文的**唯一真相**：`deriveStage` 先看这一章有没有字，有字就不再退回
「写细纲」。所以只有 `chapters/`、一份细纲都没有的老工程，每一章是「待定稿」或
「已完成」，不会被倒回去要求补细纲；它们缺的是架构，全书状态机会先推那一格。

`pipeline.ts` 是 I/O 聚合器；[`../model/pipeline.ts`](../model/pipeline.ts) 仍是零 I/O、零 import
的纯领域模型和状态机。不要把后者迁入 `views/`，也不要在 `views/pipeline.ts` 里复制状态判断。

## 一行同时代表一章的两面

`buildPipelineIndex` 返回的是 `Map<章号, PlotPipeline>`：细纲（`summaries/` 下，递归）与成品（`chapters/`）
各扫一遍，一个章号一条。两边都可能缺席——只有细纲是「还没写完的章」，只有成品是
「老工程里已经写好的章」，都有是正常情况。行按章号建，但细纲与正文**按路径配对**：有正文的章
只认正文镜像的那份细纲（作者在外面给正文改了名，旧细纲不冒认，这一章就是还没有细纲）；同号的正文
有两份时认路径排序第一份并记 warn。

## 读盘只读一次

工程树、流水线状态、出场索引要的是**同一批文件**，而 `buildProjectTree` 由文件监听触发
（两个壳各去抖 250ms）——**作者每存一次盘就跑一次**。三处各读各的，一次刷新就把每一章的
细纲读好几遍。

所以这里的规矩是：**同一次刷新里，一个文件只读一次**。批量入口
（`buildPipelineIndex`）负责把大纲、配置、manifest 与细纲、章节两份列表读出来，经 `context`
参数与返回值往下摊（出场索引 `buildCastIndex(project, plots)` 直接吃它的细纲列表）；
单章入口不传就自己读，行为不变。两份列表本身则由 `NovelProject.listPlots()` /
`listChapters()` 各自缓存（同构，含在途 promise 与世代号）。新增取数方时接着摊这一份，
不要再开一条读盘路径——`tests/integration/views/projectTreeReads.test.js` 会把重复读盘的
文件名打出来。
