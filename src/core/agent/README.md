# core/agent — 循环、工具、预算

**把 AI 从「执行一条命令」改成「拿着工具达成一个目标」。**

对话页原来是一问一答的单步：作者挑一个命令（讨论 / 挑刺 / 写剧情 / 拆场景…），后端装配一次上下文、调一次模型、把结果摊在气泡里等他点采纳。单步质量很好，缺的是**多步**——「把 12 到 18 章排一遍，注意跟第 9 章埋的伏笔对上」现在要作者点七次，还要自己去翻第 9 章。

这一层管的就是多步。它**与既有的单步命令并存**，不取代：点「写剧情」是确定性动作，多一次调度调用只是加钱加延迟。

| 文件 | 职责 |
|---|---|
| [loop.ts](loop.ts) | ★ 对话循环。一个回合 = 注入状态 → 压缩历史 → 调模型 → 执行工具。约 300 行 |
| [registry.ts](registry.ts) | `ToolDef[]` → `ToolSpec[]`，外加把「描述与 schema 该怎么写」钉死的校验 |
| [context.ts](context.ts) | ★ 状态注入（每回合把状态机的结论拼进 system）+ 工具结果压缩 |
| [budget.ts](budget.ts) | ★ 步数 / 调用次数 / token 三条上限 + 无进展检测 |
| [tools/](tools/index.ts) | 四个工具，全是 L1/L2 的薄包装（每个不超过 50 行） |

## 三期：一个字都不写磁盘

注册的只有 `list` / `read` / `search` / `generate`。**`write` / `edit` / `run` 不在这里**——四期才加。

这不是「还没来得及做」，是有意的顺序：

- 一期把六处散落的写盘收敛成 `workspace/` 一个网关，八条守卫做一次；
- 二期把 `generate` 拆成无状态，落盘只剩「作者点采纳」这一条路；
- 三期的 agent 因此**不需要任何新的保护代码**就能安全地跑起来——它根本没有写的口子。

四期加写权限时，保护已经全部就位。

落盘仍然是作者点那张采纳卡片（AGENTS 第 19 条：产物落盘前必须过一遍人）。

## 五条不能破的约束

### 1. agent 不判断「下一步」

每回合把 `deriveNextStep` 的结论注入 system 消息（`context.ts` 的 `buildStateBrief`）：

```
# 当前工程
《青云志》· 已发布 99 章 · 31.2 万字（规划中 1 章）
当前目标：第 100 章《北行》（.novelforge/plots/100-北行.md）
本章状态：待写剧情
下一步（由状态机算出，不要另做判断）：写剧情
  先把这一章的剧情脉络排出来：发生什么、因果怎么串、收在什么局面上。
提醒：第 12 章、第 13 章的上游产物改过，现有内容可能已经对不上（⟳）
```

label 与 hint **逐字**来自状态机，不在这里改写措辞。两处各判各的，界面上就会出现「徽章说待拆场景，agent 让你写正文」——而那种分叉没有任何测试拦得住，只会让作者不再相信界面（第 20 条）。

这也是**为什么没有 `status` 工具**：状态每回合免费送到，不花一次往返，也不给模型「要不要查一下」的选择。

### 2. 生成产物绝不回灌 agent 上下文

`generate` 返回的是：

```
已生成：剧情·生成 · 剧情 · 4/4 节，620 字
draftId: d3f2a-1
落点：.novelforge/plots/012-入宗.md
内容已经流给作者看了，没有写进磁盘——要落盘得由作者点采纳卡片。你不需要复述它的内容。
```

**一个正文字都没有。** 正文照旧流给前端气泡（作者看得见它在写什么），但不进循环——三千字正文塞回去，agent 每走一步重烧一遍，十步之后这一份正文被算了十次钱。

### 3. 工具描述里不写领域知识

「剧情不写画面、天气、动作细节或台词」那几句在 [context/prompts.ts](../context/prompts.ts) 的 `STAGE_DUTY.plot` 里，由 `generate` **内部那次调用**自己带着。

在工具描述里再写一遍：一是白烧 token（每一轮都要发一遍），二是两处迟早跑偏——而跑偏之后没有任何测试会红，只有产出会一点点变味。

工具描述只写两样东西：**坐标系**（哪个目录放什么）与**限制**（一次最多返回多少、截断了会怎么说）。

### 4. 日志不记参数值

只记**工具名与参数的键名**（第 11 条）：

```
[12:03:41] DEBUG Agent｜调用工具 generate
    参数键：target, capability, ask
```

值里可能有正文片段（`generate` 的 `ask`）、可能有整段检索词。无进展检测的指纹算的是值，但它只活在内存里。

### 5. `generate` 的 `history` 传空数组

agent 的工具调用不是作者的讨论。混进装配器，`buildContext` 的 history 层会把 `list .novelforge/plots` 当成作者提的创作要求装进 prompt。

唯一该带历史的能力是 `settle`（它要沉淀的就是一段讨论），而**这一期明确不支持它**——agent 手上没有那段讨论，喂它空历史它会凭空编一份「刚才讨论出的结论」，比不支持更糟。返回的 error 指路到对话页手动执行。

## 无进展检测：最常见的烧钱方式

模型卡在一个读不到的路径上反复重试——`read plots/012.md` 失败、想一想、再 `read plots/012.md`。每一次都是一整轮上下文的钱。

判据是**连续**同工具 + 同参数（键排序后序列化，模型两次填的键序未必一样）：

| 连续第几次 | 行为 |
|---|---|
| 2 | 回一条 tool 结果：「你刚才已经用同样的参数调过 X，结果和上次一模一样」，**不真的执行** |
| 3 | 停下循环，走收尾那一轮 |

判「连续」而不是「出现过」：先看细纲、再看场景、回头核对细纲是正常的工作方式。

## 预算触顶不静默停

`budget.exceeded()` 只报触了哪一条，停不停由循环决定。循环收到之后**给模型最后一次机会**（把 `tools` 摘掉，只让它说话）说明「做到哪了、还差什么」，再结束。

直接掐断的话作者只看到一段没头没尾的输出，不知道该从哪接着做。上下文压不下去（`buildAgentMessages` 的 `overBudget`）走同一条路。

缺省上限：20 个回合 / 10 次生成 / 20 万 token。

## 取消停在工具边界

`signal.aborted` 时不再发起下一次模型调用，也不再执行下一个工具；**正在跑的 `generate` 靠它自己的 signal 停**（`ToolContext.signal` 就是同一个）。

**已经产出的 draft 保留**——那是花过钱的东西。取消的是「接着往下做」，不是「刚才做的作废」。

流中途被取消时也要认出来：规矩的 provider 会抛 `CancelledError`，但也有直接把流收掉、正常返回的——那时手里是一段半截的回答，不能当成「模型给出了最终回答」。

## 上下文压缩

agent 自己的历史会涨（工具结果一条条累积）。四条策略：

1. **system 与最后 6 轮永不压缩**。刚发生的事必须完整。
2. 更早的 `tool` 消息只留**第一行** + 「（结果已省略，需要可重新调用同一个工具）」。留第一行是因为读工具的第一行恰好是「路径 + 总量」那句——模型据此知道自己看过什么。
3. 压缩时**打一条 warn**（第 2 条：不静默截断）。
4. 压到底仍然超预算 → 停下并如实报告，**绝不丢掉用户最初那句要求**（丢了的话 agent 会开始回答一个谁也没问过的问题）。

保护窗口按 assistant 回复数而不是消息条数切：一轮里可能有一个工具调用也可能有五个，按条数切会留下几条无源的工具结果。

## 界面

对话页输入框旁一个 **Agent 开关**（不是新页签——它跟创作是同一件事，只是执行方式不同）。开着时发送走 `sendAgent`，**不带 stage/capability**：前端捎一份过去等于让它也参与判断，两处迟早分叉。

工具调用画成气泡里的一串折叠条，排在正文上方（先查后说）：

```
🔧 search「北境」          2 处命中     320ms
🔧 read chapters/009-北行.md  4 行       40ms
✨ generate 剧情·生成      剧情 · 4/4 节 · 620 字   12.4s
```

`✨` 是花钱的那一下，一眼看得出这一串里哪几步收费。**只画摘要，不画工具的完整返回值**——一章正文几千字，摊出来会把作者真正要看的那段回答挤到屏幕外。会话里存的也只是这份摘要（`ChatTurn.toolCalls`）。

「采纳写入」仍然是现有那个按钮（吃 draftId），三期不变。一轮里生成多次时只挂最后那一份：更早的是它自己迭代的中间稿，三个采纳按钮摊在一个气泡上，作者分不清该点哪个。

## 依赖关系

`agent/`（L3）→ `generation/`（L2）→ `workspace/`（L1）→ `model/`。严格自下而上：**L1 不认识 L2，L2 不认识 L3**。

`controller/agent.ts` 是它在面板那一侧的入口（占生成位、走 `runTask`、把循环事件翻译成协议消息）。agent 层**不认识 controller**——反过来会成环。
