# 场景合同：治剧情平淡

落点是**剧情层**，不是正文层。改这三处（都在 `src/core/context/prompts.ts`）：

| 位置 | 改什么 |
|---|---|
| `buildOutputContract('plot')` 的「冲突与转折」一节 | 加下面的五条硬校验 |
| `JOB_TASK.plotSegment` | 加第 1、4 条——拆段时就得保证这一段有转折，否则细纲无从下手 |
| `STAGE_DUTY.plot` | 只在「不写画面台词」之外补一句「必须有性质变化」 |

注意别越界：这几条**只管事件与因果**，不许往里塞画面、天气、台词的要求——那是正文层的活，而 plot 层「不写具体画面」是这个项目调出来的既有约束。

---

## 五条硬校验

```
【每一段剧情必须满足】
1. 结尾局面与开头局面在「性质」上不同：某件事从不可能变成可能、
   从秘密变成被人知道、从盟友变成威胁、从有退路变成没退路。
   仅仅「赢了 / 变强了 / 学会了 / 见到了某人」是程度变化，不算。
2. 主角必须做一个有代价的选择：两个选项都有她不愿承受的后果。
   不许用「被打断」「来不及」「有人涌上来」「话没说完」回避这个选择。
3. 本段开启的悬念数 ≤ 回收数 + 1。
4. 结局取「yes, but」（要到了，但代价是……）或「no, and」（没要到，而且……）。
   纯粹的 yes 不许收段。
5. 用一句话写出「如果这一段删掉，后文哪一件事会失去前提」。答不出就重排这一段。
```

第 2 条是核心。第 5 条是自检，可以要求模型在细纲里明写出来（放「伏笔与回收」小节，或加一行「本段不可删的理由」）。

## 为什么这样定

**「赢了」不是转折。** 赢是程度变化。写多少字都不会有推进感，因为局面的性质没动。

**没有选择就没有戏。** 主角全程零欲望、零代价，读者就没有可押注的东西。一章里她只要做一个真正的决定，这一章就立住了。

**回避是最常见的失败形态。** 模型会摸到真正的戏（「她的能力不能让人知道」），然后用「有人涌上来打断」躲过去。这不是节奏问题，是逃避——所有钩子都打开了，一个都没接。这正是「推进为 0」的机制，第 2 条那三个词就是钉它的。

**钩子收支表是「字多事少」最直接的量化。** 开五个收零个，读起来就是在撒调料。

## 示范：同一件事，三种改法

原始拍子：「她越境赢了榜首」——纯 yes，没有性质变化。

| 改法 | 转折 | 性质变化 |
|---|---|---|
| **赢了，但被看见了** | 她破招的手法被某位长老看懂了 | 「藏得住」→「藏不住」 |
| **赢了，才发现自己是被允许赢的** | 对手体内那处异常是别人塞进去的，为的就是让她赢、让她显眼 | 「我赢的」→「我被安排赢的」 |
| **要赢就必须暴露，她当场选了** | 在「输掉大比」和「让人看见她的能力」之间选 | 有退路 → 没退路，且是她自己选的 |

第三种最有戏，因为它落在第 2 条上——**代价由主角自己付，而且是她自己挑的**。前两种是外部事件，第三种是人物行动。

可以把这张表连同五条校验一起给模型当范例，但要注明：**这是转折的形状，不是内容**。不然它会照抄「被看见了」。

## 与本项目结构的配合

- 剧情段不必凑成一章（正文写完由作者手动断章），所以**不要把「一段」和「一次转折」绑死**。一段可以含多个转折，但**至少一个**。
- 拆段时（`plotSegment`）上下文里有本卷已排的段一览。可以要求模型明写「这一段相对上一段，局面变了什么」——一句话，直接兑现第 1 条，而且它天然接住了「一次只拆一段」这个设计。
- 第 5 条与卷纲的「伏笔与回收」是同一件事的两个尺度。若卷纲那一层已经列了伏笔，剧情层第 3 条可以改成对着卷纲的伏笔清单核账，比自由计数更准。
