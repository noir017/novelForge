# core/model — 数据层

小说工程的数据模型与全部文件读写。所有上层功能（上下文装配、生成、摘要）都通过这一层访问数据，不直接碰磁盘。

核心约定：**数据是工作区里的普通 Markdown / JSON**，作者随时可以在编辑器里手改。因此本层的一切解析都以「容错优先」——手改文件不该让插件崩掉。

## 文件

| 文件 | 职责 |
|---|---|
| [types.ts](types.ts) | 全部数据结构：`Chapter` / `ChapterSummary` / `SummaryCast` / `CharacterCard` / `LoreEntry` / `NovelConfig`，以及摘要与角色卡的**固定小节**定义（`SUMMARY_SECTION_KEYS`：六节 + 四期的「连续性事实」；`CHARACTER_SECTION_KEYS`）。 |
| [chapterFile.ts](chapterFile.ts) | ★ 「什么文件算章节」的唯一定义：数字前缀 + 扩展名不在二进制黑名单里。纯函数无 I/O，扫描器、编辑器可编辑判定、独立版文件监听三处共用。 |
| [naming.ts](naming.ts) | ★ 称呼学（纯函数、零 I/O）：`isGenericAppellation` 判断一个词是不是泛称（代词、亲属称谓、`少女`/`丫头` 这类谁都能用的词、带修饰语的描述短语），`sanitizeAliases` 据此过滤别名。**只过滤 aliases，绝不过滤 name**——`店小二`、`家老`、`房东` 这类以泛称当正式名的角色确实存在。 |
| [identity.ts](identity.ts) | ★ 同一人聚类（纯函数）：把摘要里散落的称呼归并成人。判据是**同章共现作硬约束的贪心聚类**——同一章 cast 里各自出场的两个称呼永不合并，候选链接按「多少章这么写过」计票贪心处理。朴素并查集在这里是错的：一条幻觉别名会顺着传递闭包把主角和她孪生弟弟并成一个人。 |
| [pipeline.ts](pipeline.ts) | ★ **创作流水线的领域模型**：`Stage × Capability × Target` 三元组。四个阶段：架构 / 大纲 / 细纲 / 正文（`setting` 叫「架构」而不叫「设定」，免得与设定条目撞名）；四个能力：讨论 / 生成 / 落定（`settle` 只有细纲层有）/ 审稿（`review`，五期，只有正文层有、不进主按钮；输出形态是第三种 `report`——有结构、要校验，但不是可以落盘的产物）；`CreationTarget` 四种（`setting` 带 `doc`：配置 / 前提 / 角色图谱 / 世界观）与它的稳定字符串键。单章状态机（`deriveStage` / `deriveProgress` / `deriveNextStep`：待写细纲 → 待写正文 → 待定稿 → 已完成）与全书状态机（`deriveBookStage` / `deriveBookNextStep`：架构四件 → 大纲覆盖 → 拆细纲 → 写下一章 → 写完，带章号区间 `range`；拆细纲的区间在第一份已有细纲之前收住），以及 `commandsFor`（`/` 命令面板的命令表）。每一步带 `calls`（`CallEstimate`：通常几次、最多几次，第 4 条），`planPlotBatches` / `planWriteBatch` 给工程页弹窗与后端确认框算同一份批次切分（批量写章：已写跳过、最多 10 章；没细纲但在大纲覆盖之内的章「边写边拆」——排进 `plotBatches`、每批算一份 `blueprintCalls`，超出大纲覆盖才收住；每章多算一份写前冲突检查 `PLOT_CHECK_CALLS`（0–1 次、最多 2 次）；每拆一批细纲、批量拆细纲拆完，各多算一次排叙事线；写完即定稿时全书滚动摘要落后 `GLOBAL_SUMMARY_EVERY` 章就在那一章之后更新一次（`globalSummaryAt`，各 1 次）；两种模式「只写正文 / 写完即定稿」，另可「写完即审稿」——每章多算一份 `REVIEW_CALLS`，五期补遗 §4）；定稿那一步是「定稿第 N 章」，带 `FINALIZE_CALLS`（预计 1–3 次：摘要 + 出场角色的当前状态 + 本章推进了哪几条叙事线）；生成小说配置那一步带 `form: 'idea'`（先填一句话与规模）。写正文的三种下一步带 `writeMode`（`WriteMode`：新写 / 接着写（追加）/ 重写（覆盖审阅）；第四种 `revise` 按审稿修稿，只由报告卡发起、永远不是下一步）与 `WRITE_CALLS`（1 次，没写够时自动续写最多再 7 轮，`describeCalls` 把原因接在后面）；`describeWriteLength` 是卡片与气泡共用的「2980 / 3000 字 · 已达标」。审稿与修稿的调用次数是 `REVIEW_CALLS`（1 次，截断或不合格时重来，最多 3 次）与 `REVISE_CALLS`（1 次，被截断时接着写，最多 4 次）。老会话里的 `volume` / `scene` / `split` 由 `normalizeAction` / `normalizeTarget` 容错回落。**纯类型 + 纯函数，零 import**，所以前端可以直接 import 同一份表。读磁盘的聚合器是 [`../views/pipeline.ts`](../views/pipeline.ts)，不要混为一处。 |
| [settingFile.ts](settingFile.ts) | ★ 架构层三份文档的格式：小说配置 `config.md`（frontmatter 是类型 / 受众 / 结构 / 视角 / `totalChapters` / `wordsPerChapter`，正文七节）、故事前提 `premise.md`（四节）、世界观 `world.md`（三节）。`isSettingFilled` 各看主体小节（配置只看「核心梗概」——只写了一句话等于还没展开）；**占位文字读回来就是空串**，免得「（待补充）」被送进 prompt。角色图谱没有自己的文件，就是 `characters/` 那一组卡。文风不在这里，唯一出处是 `style.md`。纯函数无 I/O。 |
| [plotFile.ts](plotFile.ts) | ★ 一章的细纲（`.novelforge/plots/NNN-标题.md`，**平铺、细纲号 = 章号**）的格式：三节（本章目的 / 关键事件 / 章末钩子，**关键事件可以写具体场面**）+ frontmatter 的 `role` / `characters`（计划出场，只给装配器挑角色卡用、**不进出场统计**）/ `targetWords` / `upstreamHash`（大纲里覆盖本章那一节的指纹）/ `writtenFrom`（正文据以写成的细纲指纹，由正文落盘那一步记）/ `status` / `preflightOk`（一致性预检的永久放行，一行「名字：理由」，五期补遗 §2：按章记；改名留着，重新生成这一章的细纲就丢掉；不进内容指纹）/ `factCheckOk: true`（写前冲突检查的放行，作者手写；不进内容指纹）。`isPlotFilled` **只认「关键事件」**。老工程的四节细纲读进来三节全空、不崩。纯函数无 I/O，**只认 `.md`**。 |
| [outlineFile.ts](outlineFile.ts) | ★ 情节大纲按章号区间切片：认 `## 第a–b章：标题` 等写法（只认阿拉伯数字），一节最多覆盖 `OUTLINE_SECTION_MAX`（5）章——提示词里要求、写完由 `oversizedSections` 查一遍、只记说明不拦（百章实验：一节十章，细纲把同一个高潮反复演）；给出覆盖到第几章（`outlineCoverage`，散文式大纲为 `Infinity`——不拦老工程）、覆盖某一章的那一节（`outlineSliceFor`）与那一节的指纹（`outlineUpstreamHash`，细纲落盘记它、流水线判脏比它，两处同一个函数）。`isOutlineFilled` 不把模板里的 `>` 说明、括号提示、空列表项当内容。`mergeOutline` 把续写的那一段并进旧大纲：只替换与本批区间重叠的节，前言、别的节、附注原样保留。纯函数无 I/O。 |
| [structureGuide.ts](structureGuide.ts) | 故事结构指导：六种结构（三幕 / 英雄之旅 / 节拍表 / 起承转合 / 多线 / 自由）一律按累计百分比切成章号区间——上游 AI-Novel-Writer 的英雄之旅与节拍表只有一行占位，这里补上；章数少于段数时相邻段共用一章，保证连续覆盖全书。纯函数。 |
| [markdown.ts](markdown.ts) | 轻量 Markdown 结构工具：YAML frontmatter 与「## 小节」的解析/序列化，四个 frontmatter 取值兜底（`asString` / `asArray` / `asNumber` / `asNumberArray`），以及 `hasContent`（空白与占位文字不算内容）。刻意不引入 yaml 依赖，解析失败退化为忽略该行而非抛错。 |
| [fs.ts](fs.ts) | 磁盘与字符串小工具：文本读写、稳定哈希、字数统计、文件名清理、slug 生成与扫描目录忽略规则。 |
| [castParse.ts](castParse.ts) | 出场人物字段的序列化、frontmatter 解析与旧摘要小节文本反解。 |
| [continuity.ts](continuity.ts) | ★ 摘要第七节「连续性事实」（四期，D18）：`- 陈述 〔证据：「原文」〕` 的渲染与读回（手改的写法都认）；定稿时用 bigram 给每条事实在正文里找一句证据（`attachEvidence`，移植 `finalize-chapter.command.ts`，找不到依据的丢掉）；写正文时拿证据原句逐字定位、取所在段落与前后各一段（`locateEvidence`，移植 `adjacentEvidencePassages`）。纯函数、零调用。 |
| [writingSkill.ts](writingSkill.ts) | 写作技能的纯函数（移植自 AI-Novel-Writer 的 `writing-skills.ts`）：读 `SKILL.md`（上游那份手写的 frontmatter 解析，一行一个键）、六条不兼容规则（相对引用 / 脚本 / hook / 子代理 / 工具调用 / 超过 64 KiB）、建议阶段、技能名与 id（`来源:目录名`，名字可以是中文）、绑定文件 `.novelforge/skills.json` 的读写（读不懂不抛，问题记在出事的那个阶段上）、`skillStageOf`（讨论不带；规划 / 写正文 / 审稿 / 修稿）、注入那一块的说法、GitHub 地址。**零运行时 import**，前端直接用阶段名与来源名。 |
| [importText.ts](importText.ts) | 拆书的纯函数（导入原稿、从参考书学写法共用）：字节解码（BOM → UTF-8 严格解 → GB18030）、认章标题（`第X章/回/节`、`Chapter N`、序章楔子番外；`第X卷` 是卷标题，丢掉；超长或以句末标点收尾的是正文）、切章（简介、卷标题、目录里的空标题不算章，段落规整成一段一行）、没有标题时按字数切段、均匀抽样与看结构的那几章、头尾节选、篇幅统计、规模缺省（平均字数、总章数）、参考书写法技能的名字与 `SKILL.md`。**零 I/O、绝不抛** |
| [threadsFile.ts](threadsFile.ts) | ★ 叙事线 `threads.md`（七期，移植 AI-Novel-Writer 的 `narrative-thread.ts`）：一个 `## 名字` 一条线，类型 / 计划（第 a 章埋、第 b 章前收）/ 意图 / 事件行（`第 N 章 · 埋下|推进|回收|放弃：「原文」——理由`），手改的几种写法都认、认不出的行跳过。**状态不落盘**，取章号最大的事件；`asOf` 只留第 N 章之前的事件（重写前面的章时不透后面的事）。写入只有两个外科式的追加（`appendThreads` 在末尾加线、`appendEvents` 在一条线的事件末尾加行），作者写的字、BOM、CRLF 原样保留。`pickActiveThreads` 定写正文时带哪几条（细纲提到 → 区间内 → 已过回收章 → 已埋下 → 人物对上；6 条、1200 字，放不下的跳过接着试）；`verifyThreadPlans` / `verifyThreadEvents` 校验模型的输出（先校验后截；证据按 `review.ts` 的归一化逐字找、至少 4 个字）。纯函数无 I/O。 |
| [characterState.ts](characterState.ts) | ★ 角色卡「当前状态」归谁（四期，D15）：这一节空着、或 frontmatter 的 `stateHash` 与它对得上 → 归机器（定稿可以直接更新）；其余归作者（不写、挂黄 ❗）。机器写这一节的几处都要 `stampState` 盖章；`patchCardState` 只换那一节与两个字段，作者自加的小节一个字不动。 |
| [review.ts](review.ts) | ★ 审稿报告（五期）：目标冻结（`freezeGoals`：关键事件只按换行与分号切，章末钩子单列最后一项）、引文归一与定位（`normalizeQuote` / `locateQuote`：NFKC、去空白与标点，归一后不到 4 字不认；位置映射回原文，编辑器选中与 VS Code 的 `revealRange` 都用它）、宽松解析审稿 JSON、校验（`verifyReview`：普通问题引文找不到就丢，目标任何一句找不到整项待核实，「未完成」没有证据降待核实——「没写到」只能是待核实）、缺省勾选、正文改过之后重新定位勾选项（`relocatePicks`）、修稿清单（`renderRevisionBrief`，只有勾选的）与给人读的报告；报告卡编辑模式的合并（`applyReviewEdits`，五期补遗 §3：模型给的不能删、改过标 `edited`，作者加的 `origin: 'author'` 接着编号 a1…、引文可以空着，引文按同一个归一化校验）。移植自 AI-Novel-Writer 的 `review-chapter.command.ts` / `chapter-goal-review.ts` / `human-confirmed-review.ts`。**纯函数，零 import**（前端直接打包）。 |
| [plotCheck.ts](plotCheck.ts) | 写前冲突检查（百章实验复盘）：比对本章细纲与前面定稿的连续性事实，只认硬矛盾（死了的人出场、交出去的东西还在手里、终局级事件重演、境界或地点倒退）。选事实（提到计划出场的人的不论多早都带，其余只带近 12 章，≤3000 字）、提示词与校验——模型报的每一处都要带两句原文、归一之后在细纲与事实里都找得到才算，章号以对上的那一条为准。纯函数；取数与调用在 `features/plotCheck.ts`。 |
| [preflight.ts](preflight.ts) | ★ 一致性预检（五期）：本章细纲 `characters[]` 里的人，角色卡「当前状态」写着已经死了 → 一条风险；卡上判不出来（或根本没有卡）再看前面各章定稿的连续性事实，以他做主语的最近一条说了算（`factTerminal`，百章实验里没卡的人死了又被细纲排出场）。终态说法收了修真语境（尸骨无存、魂飞魄散、陨落……），后面跟「的」的不算。按分句看**句首**的终态说法（「险些丧命」「为已死的师父报仇」不算），只信写到本章之前的状态（`stateThrough ≥ N` 不判）。细纲里记过永久放行的那几个人由 `splitExempt` 分出去（五期补遗 §2）。零调用、纯函数、零 import；取数在 `features/preflight.ts`。 |

| [thinking.ts](thinking.ts) | ★ **思考深度**（不思考 / 浅 / 中 / 深 / 极限）的类型、可选值、界面说法，以及两家的字段映射（`responsesEffort` / `anthropicEffort` / `thinkingBudget`）。与 `tiers.ts` 同一套理由：纯数据 + 纯函数、零 import，所以对话页那个下拉框与两个 provider 共用同一份档位表。**「不思考」是不带任何思考参数**（不是显式关掉）——显式关的写法两家都只有部分模型认，而「不带」在所有模型上都合法，且恰好是这个功能出现之前的行为。 |
| [agentPolicy.ts](agentPolicy.ts) | ★ **Agent 的确认策略**（谨慎 / 默认 / 放手）的类型、可选值与界面说法。与 `tiers.ts` 同一套理由：纯数据 + 纯函数，所以 `config.ts`、`protocol/` 与设置页可以共用同一份，不必依赖 agent 层。**策略只管「要不要先问」，管不着保护**——八条守卫、覆盖前审阅、批量动作的「预计调用 N 次」在任何模式下都在（判定在 [agent/policy.ts](../agent/policy.ts)）。 |
| [session.ts](session.ts) | 对话会话存储：`.novelforge/sessions/<id>.json`。含当前创作目标（`target` / `stage` / `capability`）、`Attachment`（@ 引用）、`ContextDigest`（上下文明细快照）的序列化，以及旧会话的容错归一。`ChatTurn.command` 记这一轮下的是哪个命令（**按阶段具体化过的标签**，只在不是「讨论」时记），`turnPreview()` 是「这一轮说了什么」的唯一口径——命令类的轮次 `content` 本来就是空的（该说的都在产物里），气泡与历史列表都拿它，否则一片空白配一排「新对话」。`ChatTurn.segments` 是 agent 那一轮**按发生顺序**排下来的段（一段文字或一次调用，`generate` 那一次还带着 `TurnToolCall.output`——它产出的正文）：顺序是这一轮唯一存不回来的东西，改造之前存的 `content` + `toolCalls` 只画得出「所有工具 / 一整段话」。`toolCalls` 保留但**不再写入**，老会话由 `controller/serialize.ts` 归一成段。 |

## 关键设计

- **每次读盘，不缓存正文**：`read*` 方法每次调用都重新读文件（作者可能刚手改完），只有章节列表做一层缓存，由 FileSystemWatcher 主动失效。
- **目录是任意深度的**：`chapters/`、`characters/`、`lore/` 都递归扫描，作者可以按卷、按阵营分子目录整理（`plots/` 例外：细纲平铺）。隐藏目录（含 `.trash/`）与 `node_modules` 一律跳过，深度上限 8 层。
- **章节认任意扩展名，角色/设定只认 `.md`**：章节的判定在 `chapterFile.ts`——数字前缀 + 非二进制扩展名，所以 `001-楔子.txt`、`001-楔子`（无扩展名）、`004.json` 都是章节，`001-封面.png` 不是。角色卡与设定条目是插件自己的数据格式（frontmatter + 固定小节），不跟着放宽；`listFilesDeep` 收 accept 回调，两类各传各的。
- **顺序只看序号，一条轴**：章节顺序由文件名数字前缀决定，与所在层级无关；`卷一/003-x.md` 与 `003-x.md` 都是「第 3 章」。细纲号就是章号，第 N 章的细纲、正文、摘要按号互认（认号只在 `views/pipeline.ts` 的 `chapterOfPlotNo` 里做）。序号撞车时两条都留在树上，让作者看见冲突，流水线认路径排序第一份。
- **只有 markdown 家族解析 H1**：`.md`/`.markdown` 的章节标题取自正文首行的 `# 标题`（`readChapterText` 会剥掉），其余格式一律取文件名、正文一个字节不动。`extractH1` 与 `stripH1` **都只看首行、互为逆运算**——早先 `extractH1` 带 `m` 标志扫全文，会把 `.txt` 正文中段的一行 `# xxx` 认成标题却不剥掉它。改这两个函数时务必保持互逆。（副作用：角色卡/设定条目里 `# 名字` 不在首行时，标题现在回落 `frontmatter.name` → 文件名。）
- **摘要与草稿按章节路径镜像**：`chapters/012-夜入.md` → `summaries/012-夜入.md`、`drafts/012-夜入.md`。都不落索引——没有索引就没有会漂移的第二份真相。章节的改名/删除搬这两套（`fileOps.ts` 的 `carryDraft` / `carrySummary`）；细纲改名不带走任何东西（正文是作者的文件，不跟着改名）。目标已存在时**不动**（不静默覆盖）。
- **`deletePlot` 不碰 `chapters/` 与摘要**：删细纲只是放弃规划稿，正文是作者的东西，不该被顺手带走。
- **新建只出序号名**：`writePlot` / `createChapter` 的 `title` 允许为空，那时落成 `007.md` 且不写 H1——手工新建一章时还没有标题可言，凭空塞一个「第7章」进文件名只是个假标题，而它会进上下文。为此有个 `safeStem`：**空标题给空串，不给 `sanitizeFileName` 的兜底名「未命名」**，否则会得到 `007-未命名.md`。标题回落链（`extractH1` → 文件名词干 → `第 N 章`）本来就认这种名；界面上的说法统一走 `pipeline.ts` 的 `chapterLabel`，未命名时只报序号。写 H1 时用的是**清洗后的词干**而不是原样 `title`，两者一致，改名时 `renamedBody` 才认得出「这个 H1 是跟着文件名走的」。
- **正文依据的细纲指纹记在细纲上**：章节可以是 `.txt` / 无扩展名 / `.json`，是作者的东西、没有 frontmatter，所以「这份正文依据的是哪一版细纲」记在细纲自己的 frontmatter（`writtenFrom`），由正文落盘那一步写（`workspace.recordWrittenFrom`）。从没记过（作者手写的正文）就永不标脏。老工程 `manuscripts/` 里的中转站正文一个字节都不动，代码不再读。
- **草稿是纯推导出来的**：`draftRelPathFor` 把章节在**章节根之下**的那段相对路径镜像到 `draftsDir` 下，文件名含扩展名原样沿用。`ensureDraft` 按需创建、已存在原样返回（不静默覆盖）；`listDraftPaths` 一次遍历给出全部已存在的草稿，供工程页与 `@` 引用共用（每章一次 stat 会把工程页刷新的 syscall 翻一倍）。`draftsDir` 是 `chaptersDir` 的兄弟目录、不从它派生，因此改 `chaptersDir` 不影响草稿落点；`chapterSkipDirs()` 兜住 `chaptersDir` 被配成 `.` 的极端情况。
- **出场人物只有摘要那一份**：`summaries/` 里的 `cast` 是**实际出场**，也是唯一的真相（AGENTS.md 第 14 条）。从前场景卡的 frontmatter 里还有一份 `characters`（**计划**出场），刻意不进 `castIndex`——混进去会污染出场章统计与角色卡语料。细纲的 `characters[]` 同样是计划出场：**只给装配器挑角色卡用**（`context/layers/render.ts` 的 `selectCharacters`），不进 `castIndex`（D13）。
- **角色/设定的 slug 是路径**：根目录下的文件 slug 就是文件名（与改造前一致），子目录里的形如 `主角/林昭`——上下文明细里的 `character:<slug>` 因此仍然唯一。
- **摘要新鲜度按章算**：`chapters/` 里的成品写盘后重算 `contentHash`，与摘要 frontmatter 里的 `sourceHash` 比对，不一致即过期。**空章不算过期**——没有正文就无从总结，混进来会让同步摘要的确认框报一个虚高的调用次数。摘要不自动生成，只提示。`syncManifest` 按 `file` 匹配不上时会按章号兜底，因此给一章改标题（文件名跟着变）不会丢掉「已总结」的记录。
- **出场人物有两种形态，一份信息**：摘要 frontmatter 的 `cast: [林昭, 年轻守卫(那个年轻人)]` 给程序用（角色页聚合、角色卡关联），`## 出场人物` 小节给人看。写的时候从结构化 cast 渲染出小节，保证两者一致；**读的时候以 frontmatter 为准，字段缺席才从小节文本反解**（见 [castParse.ts](castParse.ts) 的 `castFromText`）——0.2.x 之前的摘要与作者手写的摘要没有这个字段，不该因此在角色页上凭空少一批人。用括号而不是嵌套 YAML 是因为本层的 frontmatter 解析器刻意只支持字符串与字符串数组，为一个字段引入真正的 yaml 依赖不值得，而括号形式作者也能直接手改。
  `castFromText` 的两条判据（名字 ≤ 8 字、不含「的了是在不没」这类虚词）是为了挡住模型把这一节写成句子的情况——按标点切开会得到一串句子碎片，全都会跑进角色页的「未建卡」组里。宁可漏掉一两个长称呼，也不能让那一组塞满垃圾；漏掉的重新生成摘要就有了（新摘要走结构化 cast，根本不经过这个函数）。
- **角色卡的 `stateThrough` / `stateHash` 是「当前状态」的归属账**（四期，D15）：前者是这一节写到第几章（0 = 开篇，角色图谱建卡时写的），后者是机器最后一次写它时的指纹。`renderCharacterCard` 原样带着它们走——清理别名、合并重复卡这些维护动作不重新盖章，作者改过的那一节不会因为换了个别名就变成「机器写的」。
- **角色卡的 `appearsIn` / `updatedThrough` 是缓存**：前者是该角色出场的章号，后者是上次「更新角色卡」读到了第几章（增量更新的依据）。真相永远是各章摘要，落在卡里只为两件事——不读全部摘要就能在角色页显示「出场 12 章」，以及日后按人物检索章节。
- **会话用 JSON 而不是 Markdown**：会话是机器记录（含 token 明细、附件快照），不期待人工编写，但仍是纯文本、可 Git。
- **选区引用存快照**：`Attachment.text` 对 selection 存当时的快照，历史对话不因原文修改而变；整文件引用每次读盘取最新。

本层只依赖 Node API 与 core 内更底层模块；`context/`、`features/`、`llm/` 依赖本层，反向不允许。
