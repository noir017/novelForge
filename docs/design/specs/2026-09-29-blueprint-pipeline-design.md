# 设计：换成「设定先行 + 一章一纲」的生成链路

日期：2026-09-29　分支：`refactor/blueprint-pipeline`（基于 `main@8100cdf`）

## 为什么改

旧链路 `大纲 → 卷 → 剧情段 → 中转站正文 → 拆章` 跑出来的正文不可用。对照 AI-Novel-Writer（GPL-3.0，思路源自 AI_NovelGenerator）的源码，判断主因在规划层，不在装配器：

1. **细纲太虚，又没有长度锚点。** 细纲被禁止写场景和动作，也不规定起讫；剧情段不按章切，`targetWords` 可以不填。模型拿到一条抽象因果链去「扩写」，写出来是梗概体的流水账。
2. **没有前置设定。** 角色卡、设定都是写完以后从摘要里反推的，等于拿模型上一次的发挥去约束它下一次的发挥。
3. **写正文时不给后续剧情作边界**，模型会提前把后面的事写掉，或者在结尾强行收束。
4. **没有审稿和修稿。**

完整对比见 `~/workspace/project-reports/novelForge-vs-AI-Novel-Writer-对比-20260929.md`。

## 新链路

```
一句话 ─▶ 设定 config.md
       ─▶ 架构：故事前提 premise.md → 角色图谱 characters/*.md → 世界观 world.md → 情节大纲 outline.md（标章号区间）
       ─▶ 细纲 plots/NNN-标题.md（一章一份，每批 5 章）
       ─▶ 正文 chapters/NNN-标题.md（直接写入；按目标字数自动续写）
       ─▶ 定稿后处理：摘要 + 角色「当前状态」
       ─▶ 审稿（逐字引证 + 本章目标逐项核对）→ 按勾选的意见最小改动修稿
```

**一条轴**：细纲号 = 章号。段号和章号两条轴、剧情段显示位次、中转站、拆章，统统删掉。

## 关键决定

| # | 决定 | 理由 |
|---|---|---|
| D1 | **删掉「卷」这一层** | 情节大纲按章号区间组织，细纲每批 5 章、带前序细纲一览，已经起到中等尺度参照的作用。卷只剩收纳用途，不值得多一层状态机和指纹链 |
| D2 | **删掉中转站 `manuscripts/` 和拆章** | 一纲一章以后没有「按自然长度写完再切」的需要。正文确认后直接落 `chapters/NNN-标题.md`，章节仍是唯一真相，第 9 条不变 |
| D3 | **细纲改成蓝图字段，并且允许具体** | frontmatter：`no` / `title` / `role`（本章在结构中的功能）/ `characters[]` / `targetWords`；正文三节：`## 本章目的`、`## 关键事件`（100–300 字，**可以写具体场面**）、`## 章末钩子`（必填）。模块名 `plotFile` / `plots/` 保留不改，因为「细纲」在中文网文里本来就指一章的纲 |
| D4 | **设定是一个独立阶段 `setting`**，下辖四个 target：`config`、`premise`、`characters`（角色图谱）、`world` | 四步前后衔接：前提 → 角色 → 世界观 → 大纲，每一步都吃上一步的产出 |
| D5 | **角色卡由角色图谱生成**，沿用现有七节格式（已经有「当前状态」「未收伏笔」两节）；定稿后只增量更新「当前状态」 | 事后从摘要反推的那条路保留，作为补漏手段 |
| D6 | **正文目标字数必填**，缺省取 `config.md` 的 `wordsPerChapter`。生成时不到目标的 80% 就自动续写，最多续 N 轮；续写没有增长就丢弃并恢复一次；最后仍不到 80% 就报「未写够」，但不丢已写的内容 | 移植 AI-Novel-Writer 的续写逻辑，**不搬它写死的 8192 单次上限**：输出上限一律用模型配置 |
| D7 | **写正文时加三道边界**：后 5 章细纲列为「禁止提前写」；上一章结尾约 1000 字 +「不许重演」+ n-gram 重演检测；提示词末尾用执行卡把本章关键事件和钩子再列一遍 | AI-Novel-Writer 验证过的做法，这里没有 |
| D8 | **去 AI 味禁令并进正文系统提示**：禁止段尾总结句，「仿佛/犹如/宛如」全章不超过 3 次，对话要分得出是谁在说，结尾不加哲理旁白 | 同上 |
| D9 | **审稿和修稿复用现有能力**：审稿是正文层的新能力 `review`，只出报告、不写文件；修稿走 `generate`，把勾选的审稿条目塞进已有的 `revision` 层，并要求最小改动，覆盖前照旧审阅 diff | 不新增落盘路径，第 3、19 条原样成立 |
| D10 | **批量写正文改成严格串行**：写一章 → 落盘 → 摘要 → 更新角色状态 → 下一章。跳过已有正文的章 | 第 N 章要读第 N-1 章的结尾和状态，不能并发 |
| D11 | **不做向后兼容**：老工程的 `volumes/`、`manuscripts/`、老格式细纲在磁盘上一个字节都不动，代码不再读它们，也不迁移 | 用户已确认旧设计可以删；第 1 条（容错不崩）照旧 |
| D12 | **agent 层保留，只改工具**：`generate` 工具的 stage/target 跟新模型走 | agent 本身与链路设计无关 |

## 上下文装配（新配方要点）

- **设定层**：一句话 + `config.md` + 已有的前提、角色、世界观。不带正文。
- **大纲层**：`config.md` + 前提 + 角色图谱 + 世界观 + 故事结构指导（按总章数算出三幕 20/55/25 等章号区间）。
- **细纲层（拆 5 章）**：设定四件 + 情节大纲 + 前序细纲一览（最近 100 章，一章一行）+ 已写章节的摘要。
- **正文层**：P0 强制：文风、本章细纲 + 执行卡、上一章结尾、后 5 章细纲（边界）、修改意见；P1：本章出场角色卡 + 主角、前提 / 世界观、情节大纲里本章所在的那一段、历史对话；P2：全书摘要、命中关键词的设定；P3：近 2 章全文；P4：更早的摘要。P0–P4 预算器与「不静默截断」明细照旧。

## 分期

每期结束：`npm run typecheck` + `npm run test:node` 全绿（e2e 要 Bun，本机没有，单独说明）。

| 期 | 内容 | 验收 |
|---|---|---|
| 一 | **数据层与状态机**：`model/pipeline.ts` 换成 `setting / outline / plot / manuscript` 四阶段；新增 `config` / `premise` / `world` 三种文档；细纲换成 D3 的格式；删掉卷、中转站、拆章、剧情段位次；workspace 的 kind / handler、views 跟着改；`sample-novel` 重做 | 老流水线的测试删掉，新状态机、细纲解析、落盘都有测试 |
| 二 | **设定 + 架构 + 细纲生成**：移植配置、前提、角色图谱、世界观、情节大纲的提示词和输出契约；故事结构指导；拆细纲每批 5 章；解析三层降级；采纳落盘 | 假模型集成测试跑通「一句话 → 前 5 章细纲」 |
| 三 | **正文生成**：新正文提示词（D7、D8）、新装配层、自动续写、重演检测、直接落 `chapters/` | 假模型测试覆盖续写、截断、重演拒绝。**真实模型验收：同一句脑洞跑到前 3 章，导出给作者读，读得下去才进四期** |
| 四 | **定稿后处理 + 批量串行**：摘要之后更新出场角色的「当前状态」；批量写正文改成串行链 | 集成测试：连写 3 章，第 3 章的上下文里能看到第 2 章更新过的状态 |
| 五 | **审稿 + 修稿**（D9） | 引证不在原文里的条目被丢弃；修稿走覆盖审阅 |
| 六 | **前端收尾与文档**：流水线条、工程页分组（卷 → 设定）、下一步按钮；README 与 AGENTS.md 第 8、18、21、22、23 条重写；清掉死代码 | 全量测试 + 手动过一遍独立版 |

前端改动随各期一起做，第六期只做收尾。

## 不做

- 知识库 / 向量检索、提示词三级覆盖、中英双语、定稿来源收据那一套：对「写得好不好」没有贡献。
- 老工程迁移。
- 任何写死的输出 token 上限。
