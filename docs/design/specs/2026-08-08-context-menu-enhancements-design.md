# 右键功能完善设计

日期：2026-08-08
状态：已评审通过

## 背景与目标

独立版的三处界面缺少常见的右键/键盘操作，本设计补齐：

1. **文件编辑页**（editor.js）：标签页右键菜单（关闭当前/左侧/右侧/其它）；正文区右键菜单（剪切/复制/粘贴/全选）。
2. **文件页**（explorer.js）：文件与文件夹的剪切/复制/粘贴，文件与文件夹均可重命名；支持 Ctrl+X/C/V，剪贴板以应用内部状态为主、相对路径外送系统剪贴板。
3. **工程页**：「角色」分组新增「更新所有角色卡」与「从头重建所有角色卡」两个批量动作。

文件页由此从只读变为可写——这是对 AGENTS.md 行为约束 #7 的**有意修订**，写入口收敛在新模块 `core/projectFiles.ts`，仍带工程根包含检查与安全约束。

## 已确认的关键决策

| 决策点 | 结论 |
| --- | --- |
| 文件页写操作范围 | 整个工程根内（含 `.novelforge/`），不限于三个管理区 |
| 文件重命名 | 文件与文件夹都可重命名 |
| 剪贴板语义 | 应用内部状态为主；复制/剪切时把相对路径以纯文本写进系统剪贴板（外送）；不解析外部剪贴板内容 |
| 批量角色卡采纳 | 总确认框里让用户选「逐张确认」或「全部直接采纳」 |
| 「更新所有角色卡」语义 | 增量：只读各卡上次更新后的新出场章节；无新章节/未出现在摘要的卡跳过并报数 |
| 批量关闭标签确认 | 逐个确认（与现有单标签关闭一致），取消一个跳过它继续其余 |
| 正文区右键菜单项 | 剪切/复制（无选中置灰）/粘贴/全选 |

## A. 后端：全工程文件操作（`src/core/projectFiles.ts`）

新模块，core 层、零 vscode 依赖。与 `fileOps.ts` 并列而非合并——`fileOps.ts` 的「锁在三个区内」是工程页的产品承诺，继续保留。

### 操作与入口

- `renameAny(project, relPath)`：重命名文件或文件夹，保留扩展名；章节 `.md` 文件的 `NNN-` 序号前缀与正文 H1 同步逻辑与 `fileOps.renameEntry` 一致（共享内部实现）。
- `moveInto(project, sources[], targetDir)`：剪切+粘贴的后端。逐个移动。
- `copyInto(project, sources[], targetDir)`：复制+粘贴的后端。`fs.cp` 递归复制（二进制安全）。
- 三个函数都返回逐项结果 `{ from, to?, ok, error? }[]`，供前端 remap 编辑器标签。

### 安全约束（违反 = toast 报错 + log.warn，绝不静默）

1. **工程根包含**：复用 `fileOps.normalizeRel`；绝对路径、`..` 逃逸一律拒绝。
2. **不静默覆盖**：目标已存在同名项 → 该项拒绝，其余项继续，逐项报错。
3. **文件夹不进自身子孙**：移动/复制的落点不能是源目录自己或其子目录。
4. **垃圾箱不搬**：源在 `.novelforge/.trash/` 内一律拒绝。
5. **落点自由**：目标目录可以是工程根内任意位置（含 `.novelforge/`），这是用户的明确选择。

### 章节联动

- 源或落点在 `chapters/` 下的改名/移动/复制，走与 `fileOps.ts` 相同的 `carryDraft` + `syncManifest` 处理（从 `fileOps.ts` 抽取共享 helper，避免两份规则漂移）。
- 章节被移出 `chapters/`：草稿留在旧镜像路径不删，记 warn 日志说明。
- 复制出的章节文件由 `syncManifest` 收编为新条目。

### 协议变更（`protocol.ts`）

- `FileAction` 增加 `'paste'`（不需要单独的 copy——剪切/复制只是前端登记剪贴板状态，真正的磁盘动作只有粘贴这一次）。消息新增字段 `relPaths: string[]`（仅 paste 使用）与 `op: 'cut' | 'copy'`（仅 paste 使用，区分移动还是复制）；`relPath` 保持单数供 rename/move/delete 使用。`targetDir` 为落点。
- 新 `OutMessage`：`filesOpDone { op: 'rename'|'move'|'copy'; results: { from: string; to?: string; ok: boolean; error?: string }[] }`。前端据此 remap 已打开的编辑器标签并清除剪切态。
- 目录刷新不另发消息：watcher 触发的 `dirListings` 重推已经覆盖。

## B. 文件页前端（explorer.js）

### 菜单项

- 文件行：剪切 / 复制 / 粘贴 / 重命名，加在现有「打开 / 在系统中打开 / 复制相对路径」之前，分隔线隔开。
- 文件夹行：同样四项，加在现有「折叠·展开 / 在系统中打开 / 复制相对路径」之前。
- 「粘贴」仅在有剪贴板状态时可用（disabled 控制）；在**文件夹行**上粘贴落进该文件夹，在文件行上粘贴落进其父目录。

### 剪贴板状态

- 模块级 `{ op: 'cut' | 'copy', paths: string[] }`。
- 每次剪切/复制，另把相对路径以纯文本 `navigator.clipboard.writeText`（多路径按行连接）写进系统剪贴板——仅外送，不读回。
- 待粘贴的行（剪切源）加暗色标记，粘贴成功或再次剪切/复制后清除。

### 键盘快捷键

- 行加 `tabindex="0"`；焦点在文件树内时 Ctrl+X / Ctrl+C / Ctrl+V 作用于焦点行。焦点判定保证与编辑器内的文本 Ctrl+C/V 互不干扰。
- 单击行仍然打开文件，同时让该行获得焦点。

### 与内置编辑器的联动

- 收到 `filesOpDone` 后，对每个成功的 rename/move：若旧路径在编辑器里开着（任一 pane），explorer 发 `openEditor` 打开新路径；editor.js 识别「搬家」场景——把旧标签的未保存草稿与 hash 原样带到新标签（localStorage 的 pending 草稿键同步改写），再静默关闭旧路径。不丢草稿、不留重复标签。
- 剪切态在 move 粘贴成功后清空；复制态保留（可在别处再粘贴）。

## C. 编辑器右键菜单（editor.js）

### 标签页菜单

右键某个标签（或标签条空白处，此时以当前激活标签为准），菜单项：

- 关闭（当前）：现有 `closeFile`，脏则问。
- 关闭左侧 / 关闭右侧 / 关闭其它：按顺序遍历目标集合，每个脏标签各弹一次确认（逐个确认）；取消某项跳过它继续其余。

菜单作用域是右键所在的那一块编辑区（主区/草稿区各自独立），沿用 `createPane` 工厂，草稿区自动获得同样能力。

### 正文区菜单

- 仅编辑模式（预览模式不出现）：剪切 / 复制（无选中时 disabled）/ 粘贴（光标处插入，替换选中）/ 全选。
- 实现优先 `document.execCommand('cut'|'copy')` 与 `navigator.clipboard.readText()` 后 `execCommand('insertText')`——保住 textarea 原生撤销栈；失败回退 Clipboard API；粘贴被浏览器拒绝时 toast 说明。
- 通过 view.js 暴露的 `__nfContextMenu` 登记，复用全局菜单引擎，不引入第二套菜单。

## D. 批量角色卡（工程页 + characterCard.ts）

### 入口

「角色」分组标题栏与分组空白处的右键菜单（现有「在此新建角色卡」之下）增加：

- 更新所有角色卡
- 从头重建所有角色卡

### 后端：`updateAllCharacterCards(project, scope: 'incremental' | 'full')`

1. **制定计划**：列出全部角色卡 → `buildCastIndex` 给每卡的出场章节；incremental 模式过滤出 `updatedThrough` 之后的新章节。无新章节、或从未出现在摘要里的卡计入跳过并报数。为每卡预估批数（复用 `planBatches` 的预算口径，导出纯函数供估算与测试）。
2. **总确认框**（modal）：「将更新 N 张角色卡（跳过 M 张：无新出场/未在摘要出现），共需通读 X 章、约 K 批，预计调用模型 K 次。」按钮：「逐张确认后开始」/「全部直接采纳并开始」/取消。同时满足「不偷偷烧 token」（先报调用次数）与采纳方式选择。
3. **单个 `runTask`**（标题「更新所有角色卡」）：逐卡串行，进度报「第 i/N 张 · 批 j/k」；停止按钮中止整轮；单卡失败不阻断（水位线语义与单卡更新一致）。
4. **审阅**：逐张确认模式复用现有 diff review；全部直接采纳模式直接写盘（用户在第 2 步已明确选择）。
5. **收尾**：toast + 日志汇总「已更新 a 张，跳过 b 张，失败 c 张」。批量模式**不自动打开**更新后的卡（区别于单卡流程，避免连开几十个标签），路径只进日志。

### 协议变更

- `CharacterAction` 增加 `'updateAllCards' | 'rebuildAllCards'`，不带 name/relPath。

## 约束修订

AGENTS.md 行为约束 #7 中「独立版『文件』页的目录列举只读，不提供任何写入口」修订为：文件页写入口仅经 `core/projectFiles.ts`，受工程根包含、不静默覆盖、垃圾箱豁免等约束；`fileTree.ts` 的列举仍只读。

## 测试计划

- **新增 `scripts/smoke-projectFiles.js`**：根内改名/移动/复制成功；同名拒绝；`..` 逃逸拒绝；文件夹移入自身子孙拒绝；`.trash` 源拒绝；章节改名/移动带草稿、同步 manifest；多项粘贴逐项报错。
- **扩展 `scripts/smoke-characterCard.js`**：批量计划计算（跳过计数、增量过滤、批数估算）——计划器以纯函数导出供测。
- **前端**：`scripts/smoke-view.js` 在 jsdom 可覆盖处补充分组菜单登记断言；编辑器/文件页交互走手动验证（F5 插件形态不受影响——editor.js/explorer.js 只在独立版加载；独立版经 Bun 起服务手测）。
- **门槛**：`npm run typecheck` 零错误；`npm run smoke` 全绿。

## 明确不做（YAGNI）

- 不解析系统剪贴板里的外部内容做文件粘贴（只外送路径文本）。
- 不在「更新所有角色卡」里给未建卡人物建卡（那是既有的「提取角色」流程）。
- 不提供文件页的删除入口（删除仍只在工程页，走 `.trash`）。
- 批量更新后不自动打开角色卡文件。
