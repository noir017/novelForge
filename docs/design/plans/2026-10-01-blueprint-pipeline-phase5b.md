## 1. 三期首跑的五处

### 1.1 续写越过章末钩子（⚑）

**现象**：三章都是第一次调用正常收尾、只写到 55–77%（1960 / 1665 / 2323 字，目标 3000）。第一次调用已经按执行卡收在钩子上了，于是不到八成的续写只能接在钩子**后面**：第 3 章在「守门人家族的标志」之后又写了 869 字，最后让第 4 章才登场的沈秋出现在巷口（即 1.2）。

**根因**：`shouldContinue` 对「正常收尾但不到八成」和「被截断」一视同仁，都往末尾追加。截断时结尾停在半句，追加没问题；正常收尾时结尾就是钩子，追加必然越过它。

**改法**（⚑ 上游没有这一步）：**收尾过早时，第一次续写先回退到结尾那一场之前**。
- 只在这种情况触发：上一轮正常收尾（不是截断、也不是 `other`），不到八成，上一轮新写的那一段至少有两段。
- 从哪儿切（`rewindPoint`）：在最后 40% 的段落里，三段一窗，用 bigram 覆盖率找跟章末钩子最像的那一窗（≥ 0.35），从窗口第一段开始切；找不到就切掉最后约 25%（最多 600 字）。至少留一半、至少切一段。三段一窗是真实正文定的：一章四五十段、一段六十来字，钩子那一幕拆在两三段里，单段的覆盖率最高也只有 0.3 上下。
- 切掉的那一截丢弃，气泡退回到切点（`io.reset`），续写那一轮的契约换成「收尾那一段已经拿掉了：把本章还没写足的事件写足，最后重新落到章末钩子上；不要越过钩子」，「还差多少字」按切完之后算。
- 可以回退几次（试跑实测：这个模型一次只写一千字上下，一章要走两三轮），但**每次只在上一轮新写的那一段里切**，前几轮接受了的不再动。回退那一轮净多的不到 300 字，或者上一轮那一段短得没法切：**不再往钩子后面续**，停下说明原因，按未写够处理。被截断照旧追加。
- Responses 协议的 `response.completed` 从前不报收尾原因，这条路上 `stop` 永远是缺席，回退一次都不会触发：改成报 `end`（试跑时发现）。
- 「接着写」（`continue`）只在**这一次新写的**那部分里切，磁盘上已有的一个字不动。
- 说明里写清切了几段、多少字（第 2 条）。

### 1.2 结尾提前写进后面几章的人（⚑）

**现象**：第 3 章续写的结尾让沈秋出场，他按细纲第 4 章才登场。后五章细纲（`plotAhead`）一直在装配里，契约里也有「不提前写后续章节」，但这一条太笼统。

**改法**：
- **执行卡点名**：后五章细纲里排了、本章与前面各章细纲都没排的人，执行卡里列一行「本章不出场：沈秋（第 4 章才登场）」。模型对点名的清单比对一句原则听话得多。纯函数 `notYetOnStage`（`model/manuscriptCheck.ts`）。
- **写完查一遍**：上面那份名单里的人（名字与角色卡别名）在新写的正文里出现了，就记一条说明（「沈秋按细纲第 4 章才登场，本章已经写到了他：『……』」），落盘卡片上看得见。⚑ **批量写章遇到这种情况也停下**（黄 ❗），口径同重演：批量没人看着，下一章要从这个人「第一次露面」写起，接不上。
- `model/manuscriptCheck.ts` 要用 continuity.ts 的 bigram，所以不是零 import 的；它不进前端打包。

### 1.3 「仿佛」超标

**现象**：规则是「『仿佛』『犹如』『宛如』全章合计不超过 3 次」，三章正文里光「仿佛」就有 9 处，第 3 章一章 4 处。这条规则只写在系统提示中间；续写那一轮也不知道前面已经用了几次。

**改法**：
- 执行卡末尾重列一条「比喻词上限」（模型对末尾最敏感，GD:657 同一个道理）。
- 续写那一轮的契约写明已经用了几次、还能用几次，用满了就是「一次也不许再用」。
- 写完数一遍，超了记一条说明。不拦、不自动改：这是文笔问题，作者手改或修稿。

### 1.4 已落盘的产物随历史再灌一遍

**现象**：同一个会话跟着主按钮一路走，配置 JSON、前提、角色图谱、大纲、细纲批次、前几章正文都还留在历史对话里，写第 3 章时又整份装进去一遍。可它们早就落盘了，有专门的层按磁盘带（设定、大纲切片、本章细纲、上一章结尾、前文全文、证据），作者落盘之后要是手改过，历史里的还是改之前那一版。

**改法**：`history` 层跳过已经写入的那一轮（`acceptedTo`）**以及发起它的那条用户消息**，明细里记「已写入 xxx，以磁盘上那一份为准」（第 2 条：跳过要看得见）。没写入的（作者点了不采纳）照旧带，那份只在历史里有。agent 那条路本来就传空历史（第 24 条），不受影响。

### 1.5 和年代不符的现代术语

**现象**：民国背景的书，角色图谱里模型写了「严重的 PTSD」，接着进了第 2 章细纲和第 3 章正文。

**改法**：
- 架构、大纲、细纲三个阶段的系统提示「通用要求」，加上正文的硬性要求，都加一条：用词要贴合故事的年代和世界观；古代、民国、架空世界不用现代医学、心理学、网络和科技术语（举 PTSD、抑郁症、多巴胺、CPU 为例），换成那个年代的人会说的话。
- 正文写完查一遍有没有连续两个及以上大写拉丁字母的缩写，有就记一条说明（「正文里有英文缩写：PTSD」）。只提示：都市、科幻题材里 CEO、AI 是正常的。

## 2. 预检永久豁免（⚑ 与上游不同）

上游（`shared/consistency-preflight.ts`）的豁免按「事实」记在库里、全书生效，还能撤销。这里：
- **按章记，记在这一章细纲的 frontmatter 里**：`preflightOk: ["沈秋：回忆里的一场"]`，一行是「名字：理由」。第 17 条要求作者的决定只能存在 Markdown 里，所以不进 SQLite。按章而不是全书：第 8 章是回忆，不代表第 12 章再排他也是回忆；宁可多问一次（五期 §8 的口径）。
- 细纲 frontmatter 不进内容指纹（`plotContentHash` 只哈希三个小节），所以记下豁免不会让正文变成「细纲改过」。**重新生成这一章的细纲会丢掉它**：重排过的出场是新的安排，要再问一次（`renderPlotFile` 本来就只写认识的字段，这里写明这是刻意的）。作者要撤销，删掉那一行就行。
- `findPreflightRisks` 收 `exempt`：豁免过的人不算风险，单独返回（`exempted`），写章卡片的说明里列出「按你记下的安排放行：沈秋（回忆里的一场）」。
- **对话页的预检卡**加一个理由输入框和第三颗按钮「记为刻意安排，照写」（填了理由才能点）。闸门协议加 `remember { label, placeholder }`，`gateResult` 加 `remember` 带回理由。点了就把这几个人连同理由写进细纲，然后照写。
- **批量**：开跑前与中途的预检都认豁免。确认框是宿主的模态框，放不了输入框，所以批量这边只有「仅本次忽略」，说明里告诉作者怎么永久放行。

## 3. 报告卡新增 / 编辑条目（⚑ 取舍）

移植上游 `ReviewReport.tsx` 的编辑模式，有几处不同：
- 报告卡加一颗「编辑」：问题条目可以改分类、严重度（严重 / 建议）、说明、引文；「新增问题」加一条作者自己写的（`origin: 'author'`，分类缺省「作者补充」，缺省勾上）。作者加的可以删；**模型给的不能删**，不想修就不勾（上游同样只给「忽略」）。目标核对那几项来自细纲，不能编辑。
- 引文对作者加的条目是可选的；给了就按归一化在正文里找，找不到就清掉并说明。作者改过引文的模型条目同样处理。修稿清单里没有引文的那一条不写「相关原文」。
- 「保存」时把整张问题表发给后端（`editReview { turnId, issues }`）。后端用纯函数 `applyReviewEdits` 校验、截断，再写回那一轮的报告与气泡正文（`renderReport`），落盘并推回。说明为空的条目丢弃，并告诉作者。
- 编辑过的模型条目标「已改」；修稿清单里作者加的标「作者补充」。

## 4. 批量「写完即审稿」（⚑ 报告放哪、顺序、停不停）

- W9 批量写章弹窗加一项「写完即审稿」（开 / 关），跟「只写正文 / 写完即定稿」分开选。`planWriteBatch` 收 `review`，每章多算一份 `REVIEW_CALLS`。
- **顺序：写 → 审 → 定稿**（⚑）。审稿对照的是「截至上一章」的角色状态与连续性事实；先定稿的话，本章刚写下的事会被当成「前文」拿来对照它自己。
- **报告放进一个新会话**（⚑）：「批量审稿 · 第 a–b 章」，一章一轮（用户轮是 `/审稿`，助手轮是报告卡）。每审完一章就落盘一次，取消了也留着审过的那几章。作者打开这个会话，在报告卡上逐章勾选、修稿，走的是对话页同一条路（修稿用对话页选定的模型、当场问、覆盖前对比）。完成提示的按钮换成「打开审稿报告」（`TaskNotice.open` 加 `sessionId`）。
- **审出问题不停**（⚑）：审稿只是意见，要人勾了才会修稿；批量停下来也没人勾。完成提示里说清「第 4 章 2 严重，第 5 章 1 建议」。**审稿失败也不停**：后面几章不靠这份报告往下写。失败记成那个会话里的一轮报错，完成提示里提一句。
- 模型：新增分档任务 `review`（审稿，缺省均衡档），不带思考深度（第 26 条）。

## 5. 真实模型试跑

`~/workspace/project-scripts/novelforge-phase5-live/run.js`：沿用三期脚本的做法，用同一个脑洞、同一个模型（`gemini-3-flash-lite`），从空工程跟着主按钮走到写完前 3 章（单步，各章定稿），然后审第 2 章、按缺省勾选修稿，修稿走合并视图交回新版。导出到 `~/workspace/project-reports/novelForge-五期补遗真实模型试跑-<日期>.md`。

报告要对照三期首跑逐项写清：
- 每章字数、续写了几轮、有没有回退、结尾是不是落在钩子上；
- 有没有后面几章的人提前登场；
- 每章「仿佛 / 犹如 / 宛如」各几次；
- 历史层跳过了哪几轮；
- 设定和正文里还有没有 PTSD 这类词；
- 审稿报告（丢了几条、目标核对）、修稿前后的 diff 处数。

预计 20–25 次调用。
