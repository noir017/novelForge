### 为什么不接 git

- **三个壳里有两个本来没有 git**：桌面版装在 Windows 上默认没有；Docker 镜像从前是 distroless（作者要求之后现在有了，但那是给作者自己用的）。要接只能把 isomorphic-git 打进去，项目至今零运行时依赖。
- **会跟作者自己用的 git 打架**：app 自动提交会把作者的提交历史刷满「自动存档」；整本退回用 checkout 会盖掉作者没提交的改动（第 3 条）；与 VS Code 的 git 抢 `index.lock`；容器里没有提交人身份。
- **一半已经有了**：`workspace/history.ts` 本来就是自己写的按文件存历史。缺的只是「整本书一起存一版、一起回去」。
- （当时还说过「Windows 的 autocrlf 会让指纹对不上」——**说错了**：`model/fs.ts` 的 `hash()` 先把 `\r\n` 归一成 `\n`，换行不影响指纹链。已向作者更正，不影响结论。）

git 强的地方（异地备份、多机同步、成熟的 diff 工具）在 app 里重写不划算，作者继续在外面用 git。两套互不干扰：存档点的目录放 `.gitignore`。

## 存法

```
.novelforge/checkpoints/
├── .gitignore                        第一次建这个目录时放，内容 `*`（同历史版本：作者删掉就是想让 git 收，之后不再补）
├── objects/3f/a9c1…（sha256 余下 62 位）  文件内容，字节原样（不转码、不压缩）；同样的内容只存一份
└── points/2026-10-20_22-30-05+0800.json   一个存档点一份清单（名字的格式同历史版本的快照，同一秒第二个带 -2）
```

清单：

```json
{
  "v": 1,
  "time": 1792505405000,
  "note": "第一卷写完",
  "auto": false,
  "files": { "chapters/第一卷/003-深处.txt": { "sha": "3fa9c1…", "bytes": 9120, "words": 3011 } },
  "skipped": ["chapters/超大的一章.txt"]
}
```

- **存哪些**：`kindOfPath` 不是 `other` 的——与历史版本同一个口径（章节、草稿、细纲、角色卡、设定、架构三件、大纲、文风、叙事线、全书摘要、技能、敏感词表）。叙事线重做之后的 `threads/` 目录换了种类也自动跟上，不用改这里。会话、工程库、回收站、历史版本、`project.json`（manifest，从章节重算）都不存。只扫章节根、草稿根与 `.novelforge/` 三处，不扫整个工程根。
- **⚑1 超过 2 MB 的单份不存**（`MAX_EDITABLE_BYTES`，与网关读写同一个上限），记进 `skipped`，界面上说出来（第 2 条：不静默丢）。
- **去重**：内容按 sha256 寻址，第二个存档点只多存这期间改过的那几份；清单本身几十 KB。
- **先写对象、最后写清单**：清单是提交点。写到一半失败，剩下的只是没人引用的对象，下一次清理时删掉。
- **⚑2 整个目录算 Novel Forge 的内部文件**（`isInternalPath`）：读当不存在、写搬删都拒、`list` 与全文检索看不见（「文件」页那一层一个文件都不藏，目录照样列得出来，点开读不到——与会话一样）。与历史版本不同（那里的快照按原路径排、点开就是一份旧稿），这里是一堆按 hash 命名的对象，点开没有意义；要看、要找回，走「存档点」面板。`watchPolicy` 挡掉它的变动（插件壳的监听只吃 `.md`，本来就碰不到）。

## 存

- **手动**：工程页页签条上的 ⚑（或「文件 → 存档点…」）→ 写一句备注（可以空着）→「存一个存档点」。**⚑3 与最近一个存档点一模一样也照样存**（作者要的是一个带名字的点；只多一份清单，不占地方）。
- **自动**：批量动作之前（下一节）。与最近一个存档点一模一样就不另存——最近那一个已经就是现在的样子。
- **同一个工程同一时刻只做一件**：存、清理、退回在进程里排队（按工程根一把锁）。另一个进程同时清理时，只删一个小时以前写下的没人引用的对象，不会删掉别处正在存的那一份。

## 看

- **列表**（新的在前）：时间、手动 / 自动、备注、这一刻全书正文多少字、多少份文件。
- **跟现在比**（点一个存档点）：逐份比 sha，分三类——改过的、存档点之后删掉的、存档点之后新建的；每份带当时与现在的字数。一模一样的只报个数。
- **单份对比**：存档点里的那一份 ↔ 磁盘上现在这份，走宿主的合并视图（`Host.mergeTexts`，独立版与桌面版有）。**⚑4 挑好之后直接写盘**（经网关 `write`，`review: false`、带打开对比时的 hash 当乐观锁）——这里没有编辑区可以放回去，合并视图里点的「写入」就是那一问。插件壳没有合并视图，只说一句。

## 退回

两种：**退回这一份**、**整本退回**。都在面板上点两下（按钮文案两段式，同全书替换），点的就是那一问。

1. **有任务在跑（批量写章之类）、或正在生成，就不退**：一边写一边退，结果谁也说不清。
2. **先自动存一个「退回到「10-20 22:30」之前」**——退回本身也能撤回。**⚑5 这一个存不下就不退回**（自动存档点存不下一律不挡别的动作，唯独这里挡：没有它，整本退回就收不回来了）。
3. 逐份写回，**字节原样**：
   - 编辑器里有未保存修改的跳过（前端随请求带 `dirty`，同全书替换）；
   - **乐观锁**：面板打开「跟现在比」时每份记下的 hash，退回时对不上（这期间别处又改过）就跳过；当时不存在的、这期间又被建出来的也跳过；
   - 写回走网关新加的 `Workspace.restoreBytes`：过守卫（越界、写不进去的三处、大小、乐观锁），覆盖之前照样给这一份存一版历史（跳过节流），然后原样写下字节。**不跑 handler 的记账**——⚑6 细纲连同 frontmatter 里的 `upstreamHash` / `writtenFrom` / `sourceHash` 一起回到当时的样子，不按大纲此刻的指纹重记（第 18 条：指纹链整本退回之后就是当时那条链）。只退回一份细纲、正文没跟着退回时，那一章可能显示「定稿之后正文改过」——那是实情。
   - 章节写完之后统一同步一次 manifest。
4. **⚑7 存档点之后新建的文件缺省不动**；面板上勾「也把存档点之后新建的 N 份搬进回收站」才搬（经 `remove` 进 `.trash/`，第 6 条）。同样带乐观锁。
5. 汇总：退回了几份、搬进回收站几份、跳过的逐份说为什么（toast + 日志），面板随后重新比一次。

## 保留与清理

- **⚑8 手动的永远留；自动的留最近 30 个**，多的删掉最旧的清单，再清掉没人引用的对象。
- 给一个自动存档点写备注就是把它**留住**（变成手动）。
- **⚑9 这一期不提供删除**：手动的不占多少地方（去重），要删可以在磁盘上删 `points/` 里那一份，下一次清理带走没人引用的对象。

## 自动存档点

**钩子在 `features/` 层**（MCP 的外部 agent 调同一个批量功能，也一样先存）：作者在确认框上点了「开始」、第一次写盘之前，调 `checkpointBefore(project, '批量写章之前（第 12–20 章）')`。

| 动作 | 位置 | 备注怎么写 |
|---|---|---|
| 批量写章（含写完即定稿、边写边拆） | `pipelineBatch.ts` `runWriteBatch`，`runTask` 回调开头 | 批量写章之前（第 a–b 章） |
| 补齐架构 | `pipelineBatch.ts` `fillSettings`，`runTask` 回调开头 | 补齐架构之前 |
| 批量拆细纲 | `pipelineBatch.ts` `runPlotBatches`，`runTask` 回调开头 | 批量拆细纲之前（第 a–b 章） |
| 全书替换 | `bookReplace.ts` 第 3 步之前，有要换的才存 | 全书替换之前（「甲」→「乙」，N 份） |
| 按目录整理设定 | `lore.ts` 作者点了「照这样整理」之后、`applyMoves` 之前 | 按目录整理设定之前 |
| 批量展开设定 | `lore.ts` `expandLoreEntries`，`runTask` 回调开头 | 展开设定之前（N 条） |
| 导入原稿 | `importManuscript.ts` 确认「导入」之后 | 导入原稿之前 |
| 从已写正文补齐 | `derive.ts` 两段各自的 `runTask` 开头（第二段与第一段之间没有别的改动就不另存） | 从已写正文补齐之前 |
| 立即同步（逐章定稿） | `summarize.ts` `syncSummaries`，`runTask` 回调开头 | 同步章节细纲之前（N 章） |

- **⚑10 比当时说的五个多了几处**（批量拆细纲、批量展开设定、立即同步）：都是一次改很多份的批量动作，与最近一个一样时不另存，多挂几处没有代价。从已写正文补齐是两段（先整理细纲、再补其余几样），第一段存过第二段就不另存——退回去就是整件事之前；代价是没法只撤第二段、留下第一段花钱整理的细纲。
- **⚑14 连着的两件事各存一个**：批量拆细纲勾了「拆完展开本批新设定」，展开那一步另存一个（拆完状态已经变了，展开本来也另问一次）；导入原稿之后接着补齐，先后存「导入原稿之前」「从已写正文补齐之前」两个。
- **⚑15 备注里的区间与份数照确认框说**：批量写章写的是实际要写的第一章到最后一章（写完即定稿时带上「写完即定稿」，写完即审稿不提）；批量拆细纲写作者选的整个范围；全书替换的「N 份」是通过核对、准备要写的份数，查找串与替换串各截到 12 个字。
- **⚑11 存不下不挡批量动作**：记一条 warn、任务日志里说一句，照常跑（第 1 条；每份文件覆盖之前的历史版本照常存）。
- 放在 `runTask` 回调里（而不是确认框之后立刻）：确认之后模型池可能「没有可用的模型」直接返回，那样存了一个没用的点。
