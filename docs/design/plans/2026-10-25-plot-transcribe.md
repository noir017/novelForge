# 按格式写、转写模型照抄成 JSON（2026-10-25：细纲试点，同日推到全部结构化产物）

## 为什么

作者实测：同一份上下文，要模型直接按 JSON 合同输出细纲，与放开写相比内容明显不同、质量更差。JSON 只是程序要的运输格式（细纲落盘还是 Markdown），不该让写细纲的模型去背。

作者定的：先拿细纲试；转写用**固定的转写模型**（不跟对话页选的、也不跟确认框上为这一次挑的模型）；转写模型没配就按默认走。

## 做法

1. **写**：细纲（写第 N 章细纲、落定细纲、对话页拆细纲、工程页批量拆细纲、边写边拆）的提示词不再要 JSON，改成按小标题写自然语言（`context/prompts.ts` 的 `blueprintFormat`）：一章一个「## 第N章：标题」，下面九个小标题——细纲七节（连续性事实除外）加「叙事线」「新角色」「设定」。各节写什么照原来的 JSON 合同搬过来，只把字段名换成小标题。
2. **转写**：新任务 `transcribe`（「转写 · 细纲整理成 JSON」，缺省快速档）把原文照抄成原来那份 `{"blueprints":[…]}`（`blueprintJsonContract` / `blueprintTranscribeMessages`）。只带合同与原文，不经装配器、不带书的上下文；温度 0、不带思考。
3. **查**：解码、章号对账照旧（`decodeBlueprints` / `checkCoverage`），另加一道「每段文字都出自原文」（`features/structuredJson.ts` 的 `unfaithfulStrings`）。
4. 后面的落盘、叙事线计划、建角色卡与设定空条目一行没改——它们吃的还是同一份 JSON。

## 定下的几处（⚑ 我按推荐定的，待作者看）

- ⚑1 **格式**：九个小标题、一章一个「## 第N章：标题」；叙事线 / 新角色 / 设定只说每条要写清哪几样，怎么写随它。
- ⚑2 **「出自原文」怎么比**：两边去掉空白、标点与符号后看是不是原文的一段（去掉行首「-」、两行并一条、拆成两条、换引号都不算改）。章号、推进 / 埋……、主角 / 反派……、男 / 女、新不新、第几章前收、分类按对应关系填，不比。
- ⚑3 **批次重试**：转写不合格（截断、解不开、漏了原文写了的章、改了字）**全程只重转一次**，说清上次哪几处不对；还不行走原来的降级链（多章对半拆、单章紧凑重建，各自重写重转）。原文就没写的章（连「第 N 章」都没有）是偷懒，直接报漏写、不重转。
- ⚑4 **单章宽松**：转写两次都不合格不报错，把原文交回去按小节读（七节读得出来，叙事线计划、新角色、「设定」一节读不出来），卡片说明里写清。同从前单章的全文兜底：作者当场过目。
- ⚑5 **不转的两种**：模型自己给了合格 JSON（没照格式写、老会话）不转；连「梗概」「关键事件」都没有的输出（「我不太确定」）不转，按解不出来走降级，省一次转写。
- ⚑6 **调用次数**（第 4 条）：单章 2 次、最多 3 次（`PLOT_CALLS`）；一批 n 章 2 次、最多 6n − 1 次（5 章最多 29 次，原来 15 次）。写细纲最多 3n − 1 次（拆半 2n − 1 + 重建 n），转写每次写完一次再加全程一次重转。
- ⚑7 **转写那一档一个可用模型都没有**（连默认模型都建不出来）：退回干活那个模型转写，日志里说一声。
- ⚑8 **对话页气泡**：转写的输出不流进气泡，只加一行「——第 6–7 章转写成 JSON（快速档：xxx）——」；链结束后气泡照旧换成规范化 JSON。
- ⚑9 **确认框**：批量拆细纲、批量写章（边写边拆）的确认框单列一行「转写 · 细纲整理成 JSON → 快速档：xxx（不跟这一次挑的模型）」，挑了具体模型也照样显示。AGENTS 第 12 条加了这一条例外。

## 试跑（gemini-3-flash-lite，2026-10-25）

写细纲与转写同一个模型，同一本书拆第 11–15 章两遍、单章第 16 章一遍：新版 3/3 成，转写都一次过、逐字一致；旧版（直接出 JSON）有 1 次漏一个引号、语法修复又改了内容被拒，整批没写进去。细纲质量在这个小模型上看不出高下。报告：`project-reports/2026-10-25-novelforge-plot-transcribe-trial.md`。

## 二期：推到全部结构化产物（同日，作者：「把全部需要 json 的步骤都改成这种模式」）

公用骨架 `features/transcribe.ts` 的 `transcribeJson`（原文是 JSON 不转、不像这一步的不转；照抄 → 「无」换空 → 每段文字出自原文 → 这一步原来的解码，不合格重转一次；转写调用失败不往外抛，照这一步原来解析失败的走法）。每一步只给合同、解码与按对应关系填的键；解码函数基本没动。工程页任务经 `poolIO.ts` 的 `poolTranscriber` 拿转写调用，生成链经 `Tally.transcribeJson`。从前的「语法修复一次、只许改标点」整套删了（转写顺带理顺语法）。

| 步骤 | 干活的模型现在怎么写 | 调用次数（原来 → 现在，预计 / 最多） |
|---|---|---|
| 小说配置 | 一个字段一个「## 小标题」，故事结构、视角写中文词 | 1 / 3 → 2 / 5 |
| 角色图谱（身份清单 + 详情） | 一人一个「## 名字」，定位 / 性别 / 叙事职责 / 关系；详情七个小标题 | 2–4 / 16 → 4–8 / 31 |
| 设定清单（清单 + 详情） | 「## 分类」「## 清单」一条一行；详情三节 | 3–6 / 封顶 12 → 6–12 / 封顶 24 |
| 展开一条设定 / 落定设定 | 八个小标题 / 一条一个「## 名字」加「还没定的问题」 | 1 / 2 → 2 / 3（批量展开每条最多 4） |
| 审稿 | 「总评」「问题」「目标核对」三节，引文用「」 | 1 / 3 → 2 / 7 |
| 写前冲突检查 | 「无矛盾」或一处一段，两句原句用「」 | 0–1 / 2 → 0–2 / 3 |
| 同步一章（细纲 + 角色状态 + 叙事线 + 故事时间） | 细纲八个小标题；状态一人一节；叙事线见下；时间一章一节九项 | 3–6 / 6 → 6–12 / 18 |
| 排叙事线 | 一条线一段「## 线名」+ 种类 / 章节 / 意图 / 伏笔 | 1 → 2 / 3 |
| 叙事线判一章（认事件 / 归并 / 当前进度） | 「## 事件」「## 新线」「## 新伏笔」一条一行，证据用「」；归并「新 → 已有：理由」；进度「【线】」一段 | 1–3 / 3 → 2–6 / 9 |
| 故事时间（补推一批） | 一章一节「## 第N章」九项 | 1 → 2 / 3 |
| 角色卡更新、提取角色、记设定、按目录整理 | 十个小标题 / 一人一个「## 姓名」/「- 名字（分类）：说明」/「## 新目录」「## 搬家」 | 1 → 2 / 3（每批 / 每章） |
| 建条目 / 整合 | 「一句话」「关键词」两行加三节 | 1 / 2 → 2 / 6 |

各步的内容要求（字数、条数、照抄名字、证据逐字、暗设只做减法、统称第 5 条……）一条没丢，只改了说法；证据与引文转写之后照旧由原来的校验对正文逐字核。确认框上凡是会转写的都单列一行「转写 → …（不跟这一次挑的模型）」。

### 二期定下的几处（⚑ 按推荐定的，待作者看）

- ⚑10 各步的格式就是上表那样；名字、证据之外按对应关系填的（定位、种类、严重程度、结论、天数、时段……）写中文词，转写时对到代码，不比原文。
- ⚑11 角色图谱的编号就是名字，关系指向名字；转写模型照抄了中文定位（「主角」）的先对回英文代码再解码。
- ⚑12 角色详情、设定清单详情全程只重转一次（同从前的语法修复）；设定清单的封顶 12 → 24，转写也算，一批要放得下「写 + 转写」才开。
- ⚑13 失败走法照各步原来解析失败的走法：配置、单章细纲、同步的细纲转不成按小节读原文（说明里写清读不出的几项）；设定清单、展开、落定转不成不给写入；审稿转不成按格式重写 1 次再转（最多 7 次）；写前比对转不成当没做成、照写；叙事线认事件转不成停在这一章挂 ❗；角色卡这一批跳过挂 ❗；记设定「设定」一节不动挂黄 ❗；建条目 / 整合这一条重写一次再转（最多 6 次）。
- ⚑14 原文明说没有的不转：写前比对只写「无矛盾」、角色状态只写「无」、叙事线三节都「无」 / 不归并——实际只调 1 次，预计里的下限仍按 2 报。反过来，原文写了条目、转写一条都没有的算不合格、重转一次（叙事线、提取角色）。
- ⚑15 同步的「设定」一节与单独记设定共用 `LORE_FIELD_RULES`（字段名换成中文：名字、分类、说明），一行一条的格式各自说（同步「- 名字〔分类〕：说明」，记设定「- 名字（分类）：说明」）。
- ⚑16 故事时间的 date、season 不放进按对应关系填的键：里面的月日、节令本来就是从原文抄的，要比。
- ⚑17 批量写章「写完即审稿」转不成时，写好的报告不留进「批量审稿」会话，只记一句报错（同从前）。

## 没做的

- 全文大纲、文风、故事前提、世界观、情节大纲、正文、修稿、删修饰本来就不是 JSON，没动。
- **二期没调真实模型**：测试全是假模型。各步的格式模型守不守、转写会不会动名字与引文、长段（角色卡的节、设定条目的正文）会不会被转写截掉一截（「出自原文」只查有没有改字，不查漏没漏），都要拿真实模型试过才知道。
- 试跑：一期用 gemini-3-flash-lite 跑过细纲（见上）；二期各步待跑。
