# Novel Forge

**把一个脑洞养成一本完整的书。**

从一句「如果……」开始，先把它展开成小说配置、故事前提、角色图谱与世界观，再排出情节大纲、拆成一章一份的细纲，最后一章一章写成正文。每一层的产物都摊在屏幕上，可编辑、可重写，**确认后才落盘**——AI 负责把上一层展开成下一层，拍板的始终是你。

写长篇卡住的地方通常不是写不出字，而是**越写越记不住自己写过什么**：小说越写越长，模型窗口装不下全文，续写时人物走形、伏笔丢失、文风漂移。所以这里同时做两件事：**往下展开**（把一个念头逐层填成成品）与**往回记住**（把已经写下的东西压成模型每次都带得动的记忆）。

具体是三件事：

1. **逐层展开** —— 一句话 → 故事架构（配置 / 前提 / 角色图谱 / 世界观）→ 情节大纲 → 细纲（一章一份）→ 正文。每一层都可以停下来讨论、重做，写到一半发现前面不成立，回上一层改了再往下走。正文按细纲的目标字数自动续写，写完还可以审稿、按审稿意见修稿。
2. **按创作阶段装配上下文** —— 定架构、排大纲、拆细纲、写正文是四件不同的活，需要的东西完全不同。工具按你当前在哪一层，只装那一层用得上的东西，并把装了什么、没装什么明明白白列给你看。
3. **整合总结** —— 每写完一章就「定稿」：照正文把这一章的细纲反向更新一遍，补上连续性事实（每条事实挂一句原文作证据），记下这一章出现了哪些设定（地点、势力、物品、概念……），把出场角色的「当前状态」更新到这一章，并认这一章在叙事线上发生了什么（哪几条剧情线往前走了、哪条伏笔埋了或收了、正文里有没有长出新的线）；再加上全文大纲、角色卡与设定名录，让「记忆」始终有限且可人工校正。

所有数据都是工作区里的普通 Markdown，可以 Git 版本管理，可以直接用编辑器改，程序挂了数据也还在。

三种用法共用同一套核心：浏览器里的[独立 Web 版](#独立-web-版不装-vs-code-也能用)、双击就开的[桌面 App](#桌面-app-windows--linux)、以及 [VS Code 插件](#快速开始)。

### 从脑洞到成书

```
一句话  →  故事架构  →  情节大纲  →  细纲  →  正文  →  定稿
如果……    配置 前提     第 1–20 章    一章一份   自动续写    照正文更新细纲
          角色 世界观   第 21–40 章…  每批 5 章  到八成      + 连续性事实 + 角色当前状态
```

**跟着主按钮走就行。** 对话页输入框上方永远只有一个主按钮，写着这本书现在该做的那一步：没有配置时是「生成小说配置」（弹出一个小表单，写下你的脑洞、总章数和每章字数），接着依次是故事前提、角色图谱、世界观，然后是「生成情节大纲（第 1–20 章）」「拆细纲（第 1–5 章）」，再往后就是「写第 1 章」「定稿第 1 章」「写第 2 章细纲」……每一步要调几次模型写在按钮旁边，点之前就知道。

**为什么先定架构。** 直接从一句话写正文，模型手上只有那句话，写到第三章人物就开始走形。所以先把这句话展开成几份短文档：配置（类型、结构、视角、规模与「全局要求」）、前提（核心冲突与悬念骨架）、角色图谱（主角、盟友与对手各一张卡）、世界观（规则、阶层、深层危机）。它们几百字到一两千字，后面每一章都带着它们写。

**大纲按章号区间分段写。** 一次写一百章的大纲，后半段会稀得像目录；所以大纲按「第 a–b 章：标题」分节，总章数超过 20 时先写前 20 章，写到哪里不够了，主按钮会变成「续写情节大纲」。六种故事结构（三幕、英雄之旅、节拍表、起承转合、多线、自由）都按总章数算好了章号区间。

**细纲号就是章号。** 细纲一章一份（`.novelforge/summaries/012-夜入青云.md` 就是第 12 章，与正文 `chapters/012-夜入青云.md` 相对路径相同，正文分卷时细纲也在同名的卷目录里），七节：梗概、出场人物、时间地点、关键事件、看点、状态变更、连续性事实（外加一节「设定」，见下文）。这一章在叙事线上计划发生什么不写在细纲里，写在叙事线里。关键事件写到具体场面——落在哪几个场面上、谁对谁做了什么——但不写成正文；看点写这一章读者最爽的那一下，也写章末吊着读者翻下一页的东西。写正文之前它是计划（连续性事实空着），定稿时照正文改写，成了这一章的档案。从大纲拆细纲每批 5 章，一批里前后有因果，又不至于长到后几章潦草。细纲里排了新角色，写入时一并建卡；排了叙事线上的推进、伏笔的埋与收，写入时一并写进各条线。

**正文直接写进 `chapters/`，写够了才停。** 写第 N 章时，模型手上有这一章的细纲、上一章结尾（并被要求不许重演）、后 5 章的细纲（被要求不许提前写）、出场角色卡、前几章定稿时留下的原文片段。一次没写够目标字数的八成，就自动接着写（最多再续 7 轮）；结尾收得太早时先退回到收尾那一段之前再续，免得接在收尾后面写进下一章的事。最后仍不够的，已写的照样留着，卡片上写明「未写够」。

**定稿是唯一要你点头的闸口。** 写完一章不会自动定稿：主按钮变成「定稿第 N 章」，点了才照正文把这一章的细纲改一遍——写偏的改成正文实际写的、没写到的删掉、一致的保留原话——并补上连续性事实（旧版细纲先复制一份进 `.novelforge/.trash/`），再更新出场角色的「当前状态」，并认这一章在叙事线上发生了什么。后面几百章靠它们记住这里发生过什么。

**剧情线记在叙事线里（可选）。** 叙事线只收剧情线，种类就四种：**主线**（全书一条）、**支线**、**感情线**、**人物线**；「玉佩的来历」这种要先埋下、日后揭开的东西是**伏笔**，挂在它所属的那条线下面，挂不上的放进「未归属的伏笔」。一条线一个文件 `.novelforge/threads/<线名>.md`，里面是意图、当前进度（一两句话说这条线现在走到哪了）、伏笔与进展（一行一个事件）。线从两头来：有了情节大纲，工程页「叙事线」页签标题旁的**从大纲排出**（1 次调用）照大纲、前提与角色图谱排出几条线和它们的伏笔；批量拆细纲开跑时一条线都没有，也会先排一次（确认框里 +1 次）。**拆细纲时带上线**：没收束的线现在走到哪、这一批（这一章）里该收的伏笔标着「本批要收」，细纲照着排，每一章在线上计划干什么（推进、人物关系的变化、走完这条线、埋或收哪条伏笔）随细纲一起写进各条线（「计划」事件，不多调模型）；重拆一章，换掉的只是那一章的计划，写入卡片上先列出来。之后每定稿一章，就认一次这一章在叙事线上发生了什么——哪几条线推进了、人物关系怎么变了、哪条伏笔埋了或收了，证据要在正文里逐字找得到才记；正文里第一次出现的线与伏笔也在这时认出来，再把动过的那几条线的「当前进度」更新到这一章。写正文时挑最多 6 条和本章有关、还没收束的线带上，一条一行写现在走到哪、本章计划、没收的伏笔，没到回收章的伏笔写明「第 b 章前不要揭开」。写之前还会零调用地提醒两件事：哪条伏笔过了计划回收章还没收、本章计划里也没收它；哪条线已经断了好几章（主线 5 章、其余 15 章）、本章计划里也没推进它——只提醒，照写不拦。工程页「叙事线」页签一条线一行，一眼看出各条线走到哪、哪条断了、哪条伏笔该收了；独立版与桌面版还能点标题旁的「**总览**」，在编辑区里看一张章 × 线的时间轴（计划的与实际发生的画在一起，计划了却没发生的标红，见[叙事线总览](#叙事线总览)）。这些文件随你改：机器只追加，「当前进度」你改过就不再覆盖（那条线上挂黄 ❗），意图与你写的字一个都不动。

每一层都可以**讨论**（直接打字就行——想挑刺、想对设定，说出来就是；AI 不动你的文件），也可以**生成**、**落定**（细纲层：把刚才讨论出的结论整理成细纲；任何一层都能落定设定：把聊定了的设定写成一批条目）。正文层另有**审稿**：逐条引原文挑出问题、逐项核对细纲里的关键事件，只出报告；你勾选之后，按勾选的条目修稿。

各层产物串成一条**指纹链**：改了大纲的某一节，那一节覆盖的几章细纲挂一个 ⟳；改了某一章的细纲（定稿之后再改也算），那一章的正文挂 ⟳；定稿之后又改了正文，定稿就对不上了，这一章回到「待定稿」，要重新定稿。已经定稿的章不会因为细纲改了被拉回「待写」——那是你认可过的文字，工具只挂一个 ⟳ 提醒，不催你重写。这件事**零模型调用、零 token**——它只是比对 hash。

老工程（从前的卷、剧情段、中转站那一套）磁盘上的 `volumes/`、`manuscripts/`、`scenes/` 一个字节都不会动——那是你的文件；工具只是不再读它们。已有的 `chapters/` 照常是章节。

**已经写了一部分？** 把整本 txt 放进工程，「导入原稿」切成一章一份；主按钮随后变成「从已写正文补齐…」，照着写好的正文把细纲、角色卡、架构与大纲整理出来，再接着往下写。想学别人的书怎么写，就把那本书放进来「从参考书学写法」。见[拆书：导入原稿与参考书](#拆书导入原稿与参考书)。

## 快速开始

```bash
git clone <this-repo> && cd novel-forge
npm install
npm run compile
```

在 VS Code 里打开本仓库，按 `F5` 启动 Extension Development Host（会自动打开 `sample-novel/` 示例工程）。

用在自己的小说上：

1. 打开一个空文件夹作为工作区
2. 命令面板 → `Novel: 初始化小说工程`
3. 点活动栏的 Novel Forge 图标 → 「设置」页点一个预设添加服务商 → 填 API Key → 点该模型的「测试」
4. 回到「对话」页，在下拉框里选模型（想让它多想一会儿就顺手调一下旁边的「思考深度」），然后跟着主按钮走：第一步「生成小说配置」会弹出一个小表单，写下你的脑洞即可

## 独立 Web 版（不装 VS Code 也能用）

同一套核心逻辑另有一个独立壳：在本机起一个 Web 服务，浏览器里操作，写作仍在你自己的编辑器里完成。

```bash
# 方式一：源码直接跑（需要 Bun）
npm run standalone                                   # 空窗口；上次没关文件夹则恢复
npm run standalone -- sample-novel                   # 打开该目录
npm run standalone -- sample-novel --no-open --port 4000
npm run standalone -- sample-novel --verbose         # 终端也打调试级日志
npm run standalone -- init [目录]                    # 终端交互式初始化（缺省才是当前目录）

# 方式二：编译成单文件可执行
npm run dist                                   # 产出 dist/novelforge（当前平台）
./dist/novelforge                              # 空窗口
./dist/novelforge sample-novel

# 方式三：npm 包
npm i -g novel-forge && novelforge             # 空窗口
novelforge sample-novel                        # 打开该目录
```

服务缺省只绑定 `127.0.0.1`、无鉴权——只服务本机作者。WebSocket 额外校验 `Origin`（只认本机同端口），挡住恶意网页跨源写入。要放到服务器上从别的机器访问，见下面的 [Docker 部署](#docker-部署放到服务器上远程访问)。配置与 API Key 存在 `~/.novelforge/config.json` / `secrets.json`（不再用 VS Code 的 settings.json / SecretStorage；插件壳首次激活时会把旧配置一次性迁移过去）。

独立版是一个 VS Code 式的工作台：左边活动栏切「对话 / 工程 / 文件 / 历史 / 日志 / 设置」，右边是**内置文件编辑器**，中间的分隔条可拖拽（双击复位）。深浅主题（外加米黄的护眼）用标题栏右上角的按钮切换，选择记在浏览器里。不带目录启动时是空窗口（Get Started + 文件 / 编辑 / 视图 / 帮助）；文件 → 打开文件夹在同一进程里开工程，不必重启服务。**每个浏览器窗口各开一个工程**，几个工程可以同时开着、互不干扰：设置 → 通用 →「新窗口中打开项目」（默认开）开着时，在已经开着工程的窗口里再打开别的工程会开一个新窗口，关掉则换掉当前窗口里的那个。窗口的网址上带着 `?project=<工程目录>`，刷新、收藏都回到这个工程；标签页、展开的目录、输入框里没发出去的草稿也按工程分开记。上次关窗口时工程还开着，下次会恢复；先「关闭文件夹」再退出则仍进空窗口。记忆在 `~/.novelforge/window.json`。

### Docker 部署（放到服务器上远程访问）

每次发版都会往 GHCR 推一份独立版镜像，amd64 / arm64 都有：`ghcr.io/noir017/novelforge:latest`（或钉版本 `:X.Y.Z`；`:edge` 是在 CI 里手动点出来的最新构建）。

镜像里服务绑 `0.0.0.0`，别的机器连得进来，所以**必须配访问令牌**（环境变量 `NOVELFORGE_TOKEN`，至少 16 位），没配就拒绝启动。用 docker compose：

```yaml
# docker-compose.yml；同目录的 .env 里写一行 NOVELFORGE_TOKEN=…（可用 openssl rand -hex 24 生成）
services:
  novelforge:
    image: ghcr.io/noir017/novelforge:latest
    restart: unless-stopped
    ports:
      - "3680:3680"
    environment:
      NOVELFORGE_TOKEN: ${NOVELFORGE_TOKEN}
      TZ: Asia/Shanghai
    volumes:
      - ./data:/data
```

```bash
mkdir -p data && sudo chown -R 65532:65532 data   # 镜像以非 root 的 uid 65532 运行
docker compose up -d
```

- **一个卷全装下**：`/data` 是容器里的家目录，配置与 API Key 在 `/data/.novelforge/`，书也放在 `/data` 下（「打开文件夹」从这里开始列）。备份它就够了。
- **登录**：浏览器打开 `http://<服务器>:3680/`，输一次令牌，记住 30 天。换令牌重启之后，旧的登录全部作废。
- **公网要套 HTTPS**：令牌在 http 上是明文传的，直连只适合内网。要经公网访问，就在前面加一层 HTTPS 反代，并且要转发 `Host`（或 `X-Forwarded-Host`）和 WebSocket 升级头（`Upgrade` / `Connection`），不然对话页连不上。
- **MCP**：`claude mcp add --transport http novelforge http://<服务器>:3680/mcp --header "Authorization: Bearer <令牌>"`。
- 不用 Docker 也行：独立版可以用 `--host 0.0.0.0` 绑到别的地址，规则一样，绑非回环地址就必须设 `NOVELFORGE_TOKEN`。只要设了令牌，即使只绑本机也照样要登录。

### 文件（资源管理器）

活动栏第三个页签，独立版专属——插件形态里这件事由 VS Code 自己的资源管理器承担。

它列的是**工程目录的原样结构**，与「工程」页那个整理过的视图不同：这里一个文件都不藏，**包括 `.novelforge/` 这类点开头的文件夹**。细纲与全文大纲（`summaries/`）、会话记录（`sessions/`）、历史版本（`history/`）、`project.json`、`style.md` 都在里面——会话、`project.json` 这类工程页上不列的文件，想手改只有这里。

- 点文件夹展开/折叠，按需加载（几百章的工程不会一进来就扫全盘）；展开状态记在浏览器里，刷新后还在
- 单击文本文件在右侧编辑器里开成**临时标签**（见下面「内置编辑器」），双击开成正常标签；图片、压缩包这类打不开的文件名字置灰，点了交系统默认程序
- 编辑器里当前编辑的那个文件在树上高亮，工具栏的 ◎ 可以定位到它；在编辑器里点路径上的某一级目录、或在标签上右键「在文件页中定位」，会切到这一页、展开到它，并用虚线框标出那一行
- 右键：展开/折叠、在系统中打开、复制相对路径

这一页**只看不改**：新建、改名、删除仍然在「工程」页做（那里的操作锁在章节/角色/设定三个区内，删除也是搬进回收站而非真删）。

### 内置编辑器

独立版右边是一个专门写小说的编辑器：多标签、两块并排的编辑区、每个文件各记各的撤销、查找替换、不会悄悄盖掉别人改动的保存与历史版本、外观与专注、码字统计、写作体检、名词补全与名词高亮、全书查找替换、叙事线总览。插件版用 VS Code 自己的编辑器，这一节说的都是独立版（两边的差别见本节最后那张表）。

下面写的快捷键都是 Windows / Linux 的；Mac 上 `Ctrl` 换成 `⌘`、`Alt` 换成 `⌥`（菜单与「快捷键一览」里会直接这样写）。全部快捷键见本节的[快捷键一览](#快捷键一览)，在编辑器里按 `Ctrl` + `/` 也能随时调出来。

#### 打开文件与标签

- **怎么打开**：在「工程」页点章节、角色卡、设定条目，或在「文件」页点任意文本文件，就在右边打开；产物落盘后也会自动打开写入的那一份。在工程页点章节行，正文开在左边主区、这一章的细纲并排开在右边。
- **能打开什么**：工程目录里、不超过 2 MB 的纯文本——扩展名是 `.md` / `.markdown` / `.txt` / `.json` / `.yml` / `.yaml`，**或者**它本身就是一份章节（数字前缀 + 非二进制扩展名，所以 `001-楔子` 这种无扩展名的章节也打得开）。别的交给系统默认程序；工具栏上的「外部打开」随时可以换成你自己的编辑器。
- **转到（`Ctrl` + `P`，或「文件 → 转到…」）**：不用回工程页翻。页面顶上出来一个输入框，打几个字就跳到一章或一个文件。焦点在左边对话输入框里时也能按；没打开工程时这个键不起作用。
  - **找章**：直接打章号——`12`、`第12章`、`第十二章`、`一百零五` 都行，那一章排第一
  - **找名字**：章节标题、角色名（包括别名）、设定标题、情节大纲 / 文风指南 / 叙事线 / 全文大纲、草稿的文件名。连着的几个字最先，其次是按先后顺序出现的几个字（`林归` 能找到「林昭归来」）；名字里都没有，再按文件名和路径找（打 `第一卷` 列出那一卷的章）
  - 每一条前面标着是什么（章 / 角色 / 设定 / 架构 / 文档 / 草稿），下面一行小字写「第 12 章 · 第一卷 · 3200 字」、角色的别名，或者文件路径；对上的字标了颜色。一次最多列 50 条，多打几个字缩小范围
  - 什么都不打时，先列最近在编辑器里开过的（每本书各记各的，记在浏览器里），再列前几章
  - `↑` `↓` 选，`回车` 打开：章节和在工程页点章节行一样，还没写正文的章开细纲；`Ctrl` + `回车`（或按住 `Ctrl` 点）开在右边第二块编辑区。打开之后光标就在正文里，可以接着写。从这里打开的是普通标签；要去的那一份正好是临时标签的话，它就此固定下来。`Esc` 或点面板外面关掉
- **标签**：没保存的标签带圆点。标签上写去掉扩展名的名字，前面一小格写它是什么——细纲、草稿、角色、设定……（正文不写），同一章的正文、细纲、草稿一眼分得开；还撞名的（比如两卷里各有一个「003-夜访」）后面淡淡写上是哪个目录。鼠标停在标签上看完整路径。
- **临时标签**（缺省开）：在「工程」页、「文件」页**单击**打开的文件，标签名字是斜体的——它是临时的，下一次单击别的文件时就在原位置换成那一个，不会越开越多。在里面打了字、保存了、双击这个标签，或者在那两页**双击**那一行，它就固定下来。改过还没保存的标签永远不会被换掉。生成落盘后自动打开的、点审稿报告引文打开的、章节条上「并排看细纲」打开的，一开始就是普通标签。每块编辑区最多一个临时标签；刷新页面后，原来斜体的那一个还是斜体的。不想要这个行为：「视图 → 单击打开为临时标签」去掉勾（记在浏览器里，不进工程）。
- **标签多了**：在标签条上滚鼠标滚轮就是左右滚，当前那个标签总会自动滚进视野。标签条最右边的「▾」列出两块编辑区里开着的全部文件（没保存的打着 ●；「叙事线总览」那个标签也在里面），点一下就切过去；底下还列着最近关掉的几个，点一下重新打开。
- **标签右键**：关闭 / 关闭左侧 / 关闭右侧 / 关闭其它，「移到另一侧」（左边的搬到右边、右边的搬到左边，没保存的内容和撤销记录一起搬过去）、「在文件页中定位」、「复制相对路径」、「重新打开刚关闭的」（左右两块各记各的），临时标签多一项「固定」。重新打开没有快捷键——浏览器不让网页用 `Ctrl` + `Shift` + `T`。
- **工具栏上的路径**写成「细纲 › 第一卷 › 第 3 章 夜访」「角色 › 林晚」这样（章节那一段写的是这一章现在的标题，与章节条、「转到…」一样——改了标题而文件名没跟着变时也对），鼠标停在上面看原始路径；点前面某一级（「细纲」「第一卷」）会在「文件」页定位到那个目录。
- **两块编辑区**：主区放正文，右边第二块放草稿或并排的细纲，各有自己的标签条、工具栏与状态栏，中间的分隔条可以拖、双击复位。保存、关标签这些快捷键作用于**有焦点的那一块**。第二块关掉最后一个标签就整块收起；窄屏（≤900px）放不下并列，它自动藏起来。同一个文件不会同时开在两块里——从另一块打开它（或标签右键「移到另一侧」）会连同没保存的内容与撤销记录一起搬过去。
- **章节草稿**：打开的是章节正文时，工具栏多一个「草稿」按钮——点它在右边开这一章的草稿，与正文并排（见[章节草稿](#章节草稿)）。
- **章节条**：打开的是一章的正文或细纲时，编辑区上方多一条：这一章写了多少、走到哪一步，「写这一章 / 接着写 / 重写 / 审稿 / 定稿」几颗按钮（按这一章的状态亮哪几颗，说明里写着调用次数），以及「并排看细纲 / 并排看正文」。条上的字数和状态随时是新的，不管左边开着的是哪一页。
- **上一章 / 下一章**：章节条两头的「‹ 上一章」「下一章 ›」，或 `Alt` + `PageUp` / `Alt` + `PageDown`。章节按章号排（文件名开头的数字，与放在哪个卷目录里无关），到头了按钮是灰的。看着正文就翻到相邻那一章的正文，看着细纲就翻细纲；这一份没改过就在原位置换掉，改过了就另开一个标签（改的东西一个字不动）。右边那一块正开着这一章的细纲（或正文）的话，它也跟着翻，光标还留在你按键的那一块。相邻那一章还没写正文、或者还没排细纲时，会直接告诉你，不会打开一个不存在的文件。
- **Markdown 预览**：`.md` 文件的工具栏上有「预览」（或按 `Ctrl` + `Shift` + `V`），再按一下回到编辑；frontmatter 单独框出来，不混进正文。**每个标签各记各的**：切到别的标签再切回来，原来在预览里的还在预览里（滚到哪也记着），刷新页面之后也一样。切换时两边滚到同一处——编辑区顶上那一行，在预览里对应的那一段停在顶上，反过来也一样；切回编辑时光标要是已经不在眼前，就放到眼前第一行的行首，免得一打字又跳回原处。`.txt` 章节没有 Markdown 可预览，按钮不出现，`Ctrl` + `Shift` + `V` 照常是粘贴。

#### 写

- **撤销 / 重做**：`Ctrl` + `Z` 撤销，`Ctrl` + `Y` 或 `Ctrl` + `Shift` + `Z` 重做（「编辑」菜单里的也一样）。每个打开的文件各记各的，切到别的标签再切回来照样退得回去；关掉标签或刷新页面之后从头记。一口气打的字算一步，回车另起一步；用输入法打字时，一次上屏算一步。编辑器替你做的改动——排版、替换、名词补全、「还原」、「用磁盘版本覆盖编辑器」、磁盘上同步进来的新版——也都能一下撤销。
- **`Tab` 缩进**：正文（章节与草稿）一级是两个全角空格，角色卡、细纲、设定这些是两个半角空格。没选中时在光标处插一级；选中几行（哪怕只选了一行里的几个字）按 `Tab`，每行行首加一级，选中的字不会被替换掉；`Shift` + `Tab` 去掉一级。
- **输入法优先**：用输入法打字、拼音还没上屏时，`Tab`、回车、方向键和各种 `Ctrl` 组合键都照常交给输入法，编辑器一个都不抢。

#### 段落与标点

这几样里说的「正文」指章节与草稿；角色卡、细纲、设定这些不算。

- **分段格式**是整本书的设置，三选一：**空行分段**（段与段之间空一行、段首不缩进，网文常见，也是缺省）、**段首缩进**（段首两个全角空格、段与段之间不空行，出版常见）、**缩进加空行**（两样都要）。在「编辑 → 段落格式」里切，当前那项打着 ✓；它记在 `.novelforge/config.md` 开头的 `paragraphStyle` 一行（写 `blank` / `indent` / `both`，或者直接写中文「空行分段」「段首缩进」「缩进加空行」都认）。切换只改这一行，已经写好的正文一个字不动——想把它们排成新格式，用下面的「一键排版」。
- **回车**按分段格式另起一段：空行分段就空一行，段首缩进就换行再缩进两格。光标后面跟着的空格会顺手删掉；在只有空白的行上回车只换行、不缩进（连按回车不会堆出一串缩进行）；在段首回车是把这一段整个往下推一行。`Shift` + `回车` 只换行、不缩进——写诗、写信、短句一行一行排时用。角色卡这些 Markdown 里回车沿用上一行的缩进，列表（`- `、`* `、`1. `）会接着往下写，在空的列表项上回车就结束列表。
- **段落快捷键**（所有文件都能用，空行不算一段；每个都能一下撤销）：
  - `Alt` + `↑` / `↓`：光标所在这一段（选中了就是选中的那几行）与上 / 下一段对调，中间的空行不动
  - `Shift` + `Alt` + `↓` / `↑`：把这一段复制一份放在下面 / 上面（正文按分段格式隔开）
  - `Ctrl` + `Shift` + `K`：删掉这一段（空行分段时连带删掉多出来的那个空行）
  - `Ctrl` + `回车`：不管光标在这一段的哪里，都在它下面另起一段
- **成对符号**：打出 “ ‘ 「 『 （ 《 【 〈 的左半边，右半边自动补上，光标停在中间；选中一段字再打左半边，就把这段字包起来。紧挨着自动补上的右半边再打一次右半边会直接跳过去，不会多出一个（输入法常常自己交替出 “ ”，这样正好对得上）；刚补完还没打字就退格，左右一起删。只在光标后面是行尾、空白或标点时才补——后面紧跟着正文时补了反而要回头删。半角括号不补。不想要可以在「编辑 → 成对符号自动补全」关掉（记在浏览器里，不进工程）。
- **一键排版**：工具栏「排版」按钮（只在正文上出现，挨着「预览」），或者「编辑 → 一键排版」。按这本书的分段格式把正文重排一遍：每个非空行是一段，去掉首尾多余的空格（半角、全角、制表符都算），段首该缩进就缩进，段与段之间原来空了几行都收成一种；`#` 开头的标题行和只有符号的分隔行（`* * *`、`※`、`◇◇◇`……）不缩进；开头的 frontmatter 原样留着。选中了几行就只排这几行，否则排整章。做完会说改了几处，一下撤销就回去。
- **半角标点转全角**：「编辑 → 半角标点转全角」。只在中文里转——前一个字是汉字或中文标点时，`,` `.` `?` `!` `:` `;` 换成全角；`3.14`、`1,000`、英文句子、`config.md` 这种文件名、网址、代码都不碰。`...` 和 `。。。` 换成 `……`，汉字之间的 `--` 换成 `——`，括号里有汉字（或者像 `(1)第一条` 这样挨着汉字）时一对一起换成全角；直双引号只在同一行里成对、中间有汉字时才换成 “”，单引号不动（英文的 `don't` 会把配对搅乱）。同样是选中几行就只转这几行。

#### 查找替换

在**这一份文件**里找；要在整本书里找，用下面的[全书查找替换](#全书查找替换)。

- `Ctrl` + `F` 打开查找条（选中了一行之内的几个字时直接填进去），`Ctrl` + `H` 连替换那一行一起打开；「编辑」菜单里也有「查找」「替换」。每块编辑区各有一条，只找这一块里当前的文件
- 边打字边从光标往后找，所有找到的地方都标上底色，当前这一处颜色更深，条上写着「第几处 / 一共几处」
- `Enter` 或 `F3` 下一处，`Shift` + `Enter` 或 `Shift` + `F3` 上一处，到头了绕回来；`Esc` 关掉，光标回到正文里刚找到的那一处
- 「Aa」区分大小写，「.*」按正则表达式找（写错了条上会说一句）；按正则替换时可以用 `$1`、`$2` 引用括号里的那一段
- 「替换」换掉当前这一处、跳到下一处（光标还不在某一处上时，第一下只是选中它，看清了再按）；在替换框里按 `Enter` 也一样。「全部替换」一次换完并告诉你换了几处，`Ctrl` + `Z` 一下全部退回
- 焦点在左侧对话输入框里时，`Ctrl` + `F` 还是浏览器自己的查找；在预览里按会先切回编辑。超过 30 万字的文件照样能查能换，只是不画底色

#### 保存、冲突与历史版本

- **保存**：`Ctrl` + `S`（或工具栏「保存」、「文件 → 保存」），存的是有焦点那一块的当前文件；「文件 → 全部保存」存所有改过的。工具栏「还原」丢弃修改、重新读盘（有修改时先问一句，放弃之后还能 `Ctrl` + `Z` 撤销回来）。
- **保存状态看状态栏**：右下角那一格写着「● 未保存」→「保存中…」→「已保存 14:32」（这次打开页面以来最后一次存成的时刻）。存成了不弹提示条；撞上冲突、出错照样弹。点了保存 10 秒还没回音（多半是和服务器断线了，页面顶上会出现红色的重连条），这一格会说「还没收到回音，连上后会自动发出」——编辑器里的内容一直都在，连上之后那次保存自动发出去，整个页面的状态也会重放一遍。
- **自动保存**（缺省关）：「文件 → 自动保存」，开着时打 ✓，状态栏上多一枚「自动保存」。开着时：停笔 2 秒（用输入法打字、拼音还没上屏不算停笔）就存当前这一份；切到别的标签时存刚离开的那一份；切到别的窗口、或者把浏览器页签藏到后面时，所有改过的都存。这个开关记在浏览器里，不进工程。
  - 它照样带着「磁盘上是不是还是那一份」的核对：撞上冲突就**停下这一份的自动保存**（那一枚写「自动保存已暂停」），等你在冲突条上选了再接着存，绝不替你强制覆盖；磁盘上已经没有了的文件也不替你重建
  - **注意**：正文一保存，已经定稿的章就会回到「待定稿」（定稿记的是正文的指纹）。开着自动保存时，在定稿过的章里改一个字，停笔两秒它就回到「待定稿」了——想先改着看看、不急着动定稿状态的话，先把自动保存关掉
- **关标签时问一句**：有未保存修改的标签关掉之前（标签上的 ×、中键、`Ctrl` + `W`、「文件 → 关闭编辑器」），会问「保存 / 不保存 / 取消」。选「保存」要等这一份真的存成了才关；撞上冲突、出错就不关，冲突条留着让你取舍。一次关好几个（右键「关闭其它 / 左侧 / 右侧」）时，没保存的那几份合在一个对话框里问一次，列出是哪几份：「全部保存 / 全部不保存 / 取消」。对话框里 `Enter` 选主按钮，`Esc` 取消。`Ctrl` + `W` 在浏览器里多半被浏览器拿去关整个网页（有没保存的内容时浏览器会先问），桌面版里才是关标签。
- **刷新与离开页面**：刷新页面不丢未保存的修改（存在浏览器本地；磁盘上的内容变过就丢弃并提示，不拿旧的盖新的）。带着未保存内容关掉浏览器页签或刷新时，浏览器会先问一句。
- **磁盘上的改动会同步进来**：定稿写回细纲、批量写章、外部 agent 改了文件、你在别的编辑器或 git 里动了文件，开着的标签会跟着变——
  - 没改过的标签：直接换成磁盘上的新版，不切标签、不抢光标；正看着的那一份状态栏会说「磁盘上有新版本，已载入」，`Ctrl` + `Z` 可以退回换之前的样子
  - 改过的标签：你的修改一个字不动，标签上挂一个「!」，切过去能看到冲突条，处理办法见下一条
  - 磁盘上已经没有了（被删、被改名）：标签名划掉、挂红色「!」，冲突条上说「磁盘上已经没有这个文件」。编辑器里的内容还在；这时按保存，会先问你要不要在原路径重新建一份（如果是在别处改了名，新名字那边已经有一份，重建会多出一份）
  - 什么时候查：每次磁盘上有变动、以及你切回这个窗口的时候
- **不静默覆盖**：保存带内容指纹的乐观锁。文件在你编辑期间被别处改过（你在别的编辑器里改了、或者插件写入了内容），保存会被拒绝，冲突条上给三个选择——**「对比合并…」**（排在第一个）：左边磁盘上的、右边编辑器里的，逐处挑用哪边、结果格可以手改，点「放回编辑器」之后编辑区换成挑出来的那一份（一下撤销就回去），冲突条收起；这时它仍是未保存的，照常 `Ctrl` + `S` 就行，不必强制保存（开着自动保存的话，因为撞冲突停下的自动保存也接着走；之后磁盘上再变，照样会提醒你）。或者整份二选一：「用磁盘版本覆盖编辑器」「用编辑器内容强制保存」（还会再确认一次）。磁盘上已经没有这个文件时没有可合并的，「对比合并…」不出现。同一个工程开在两个浏览器窗口里、两边都在改同一份文件时也一样：一边存了，另一边改过的标签挂冲突条，不会拿着旧的那份把它盖掉。
- **历史版本**：每次覆盖一份已有的稿子之前——编辑器里保存、重写或修稿落盘、定稿写回细纲、全书替换、外部 agent 的 `edit`——磁盘上的旧内容会先存成一版，放在 `.novelforge/history/` 里（见[目录结构](#目录结构)）。工具栏「历史」按钮或「文件 → 历史版本…」在编辑区右边打开一栏，列出这份文件存下的各版（「3 分钟前 · 14:32」、多少字、比编辑区里现在这份多或少几个字），正文同时看得见：
  - 点一版先看开头几行；「**对比…**」左边这一版、右边编辑器里现在的，逐处挑，放回编辑器；「**恢复这一版**」直接把编辑区换成它。两样都**不写盘**：换进来之后是未保存的，一下撤销就回去，存不存由你。放回编辑区之前，磁盘上现在那一份会先存成一版（与最近一版一样就不重复存），所以放回的内容存下去之后，被它盖掉的那一版照样在列表里。**开着自动保存时，恢复（或对比之后放回）会很快写回磁盘**——停笔 2 秒就存；存之前那一版已经进了历史，可以再恢复回来
  - 「**现在存一版**」把磁盘上**现在**这一份先存下来（编辑器里还没保存的修改不在里面——要留住它们，保存就行，保存时被覆盖的旧内容同样会存一版）
  - 只给工程里的稿子存：章节、草稿、细纲、角色卡、设定、架构三件、大纲、文风、叙事线、全文大纲、敏感词表；工程根下的随手记、`README` 这些不存，按钮也是灰的
  - 不会存出几百份：与最近一版一字不差的不存；最近一版不到 10 分钟、而且这次只是零星小改（300 字以内）的也不存——所以自动保存、边写边存都只会隔一阵子留一版；整章重写、修稿、一键排版、定稿这种大改总是存。每份文件最多留最近 50 版，再多就删掉最旧的——这些是程序自己另存的副本，不是你的文件，删它们和「删除一律进回收站」那条不冲突（你的文件一个字节都没动）
  - 第一次存的时候会在 `.novelforge/history/` 里放一个 `.gitignore`（内容是 `*`），Git 默认不收这些快照；想连历史版本一起提交，删掉它就行，之后不会再补回来
  - 存快照出了问题（磁盘满了之类）只记一条日志，保存照常进行
  - 插件版没有这一栏，但快照照样会存：在 VS Code 的资源管理器里打开 `.novelforge/history/<那份文件的路径>/` 就能看到按时间命名的各版

#### 外观与专注

标题栏「视图」菜单里的「外观」「专注」两组。这些设置都记在浏览器里，不进工程，换一本书也还是这样。

- **字号**：光标在编辑区里时按 `Ctrl` + `=` 放大、`Ctrl` + `-` 缩小、`Ctrl` + `0` 还原（缺省 15，最小 12、最大 32）；「视图 → 放大字号 / 缩小字号 / 还原字号」也一样。光标在别处（左边的对话框、页面空白处）时这几个键还是浏览器自己的整页缩放。
- **外观设置**：「视图 → 外观设置…」在右上角开一个小面板，改了当场就能看见，不用点确定：
  - **正文字体**：宋体（缺省）、黑体、楷体、仿宋、跟随系统。用的是你电脑上装的字体——没装的会退回到同类的字体（装了「霞鹜文楷」的话，楷体用的就是它）
  - **字号**、**行距**（拖滑块）
  - **版心宽度**：一行最多放多少字（30 / 35 / 40 / 45 / 50 / 60 / 70 字），屏幕宽的时候那一栏放在中间，读起来不用左右甩头；「铺满」（缺省）就是占满编辑区。预览也跟着同一套字体、字号、行距和版心
  - **主题**：深色、浅色、护眼。护眼是米黄底、深棕字，整个界面一起换（标题栏右上角那颗按钮也能切，按一下换下一套：深色 → 浅色 → 护眼）
  - 没有单独的「段间距」：空行分段时段与段之间就是那一行空行（跟着行距变），段首缩进的格式本来就不空行
  - 「恢复默认」把字体、字号、行距、版心放回缺省，主题不动。`Esc` 或「关闭」收起面板
- **专注模式**（`F8`，或「视图 → 专注模式」）：只留正文——左边的侧栏、标签条、工具栏、章节条都藏起来，底下的状态栏淡成一行（鼠标移上去才看清；字数那一格照样点得开码字统计），标题栏只剩菜单。左右两块编辑区都开着时只专注你正在写的那一块。冲突提醒、查找条、历史版本那一栏、全书查找替换照样会出来。`Esc` 或再按 `F8` 出来（码字统计、外观面板、查找条这些开着时，`Esc` 先收它们）；刷新页面后还在专注模式里。
- **全屏**：「视图 → 全屏」，整个页面占满屏幕，`Esc` 退出（浏览器自己的 `F11` 也行）。浏览器不支持时这一项是灰的。桌面版在 Linux 上是真的全屏；在 Windows 上目前只是把页面撑满窗口、窗口本身不会变成全屏，那时用窗口的「最大化」加专注模式代替。
- **打字机滚动**（「视图 → 打字机滚动」）：光标所在那一行始终停在编辑区中间附近——打字、回车、方向键移动之后自动滚过去，写到最后一行也一样，眼睛不用一直往屏幕底下追。用输入法打字时等字上屏了才滚；用鼠标滚轮往上翻看前文时不会把你拽回来，接着打字才回到光标那里。
- **段落聚焦**（「视图 → 段落聚焦」）：正文里光标所在的那一段照常显示，其余的段落变淡。按这本书的分段格式认哪里是一段：空行分段就是空行隔开的一块，段首缩进就是从有缩进的那一行起。只对正文（章节与草稿）起作用；超过 30 万字的文件不做（整篇照常显示）。

#### 码字统计

底部状态栏从左到右是：文件名、字数、写作体检（见下一节）、行列位置（在预览里写「预览」）、保存状态。字数那一格就是码字统计：

- 平时写「全文 3,120 字」；选中一段时写「选中 120 字 / 全文 3,120 字」。数法与工程页一样：中文一个字算一个，英文一个词算一个，标点和空白不算；章节开头那行 `# 标题` 也不算。字符数（连标点空白一起）在鼠标停上去的提示里
- 开着某一章的**正文**时，写成「3,120 / 4,000 字，还差 880」，后面一条细细的进度条，写到八成换成绿色（这一章算写够了的线），超了就写「超出 120」。目标就是写正文时用的那个数：细纲里写的目标字数，没写就是小说配置里的每章字数，两样都没有就不显示。字数跟着你打字当场变，不用先保存。细纲、草稿、角色卡这些不显示目标
- **点一下这一格**弹出码字统计：本章字数与目标、**本次码字**（从打开这个页面起你码了多少字、写了多久、每小时多少字）、**今日码字**（这本书今天一共码了多少）、本次按文件分开的明细，还有「重新开始计时」。`Esc` 或点别处收起
- **怎么才算码字**：只算你亲手打的字——键盘打的、输入法上屏的、名词补全里挑了补上的都算，退格删掉的会扣回去；粘贴、一键排版、查找替换、对比合并、恢复历史版本、磁盘上同步进来的新内容都不算。撤销跟着那一步走：撤销自己刚打的字，那几个字就扣回去；撤销一次粘贴，码字数不动
- **时长只算在写的时候**：停笔超过 2 分钟，中间那段不计时，去倒杯水回来速度不会被拉低。写够 1 分钟才报速度
- **今日码字**记在浏览器里（每本书各记各的），刷新页面、同时开好几个窗口都接着累计，不会重复算，也不会互相盖掉；过了半夜就从零开始算新的一天。它不往工程目录里写——换一台电脑、清了浏览器数据就没了。浏览器不让记的时候只算这一页
- 「视图 → 统计」里选状态栏上还显示哪几项：「距目标」（缺省开）、「本次码字」「今日码字」（缺省关），开着时字数后面跟着「· 本次 +356 字 · 今日 1,820 字」；「视图 → 重新开始计时」让本次码字从现在起重新算（今日的不受影响）。这几个开关记在浏览器里，不进工程

#### 写作体检与名词补全

**写作体检**（只看正文：章节与草稿）：写的时候把这本书不该用的词直接标在正文里，状态栏上一格告诉你一共几处。**不调模型、不花钱**，只是按词表在正文里找字，也不会替你改字。

- **标出来的四样**，样子各不相同（深色、浅色、护眼三套主题下都看得清）：
  - **敏感词**（实线下划线加一层淡底色）：你自己的敏感词表里的词，见下面。英文不分大小写
  - **禁用词**（红色波浪线）：文风指南里「禁用词表」那一节括起来的词、小说配置「全局要求」里写着禁止的词、古代 / 修真这类题材里不该出现的现代说法（能量、神经、频率……）——**与写正文时模型写完之后数的是同一份**，在这里标出来的，就是生成时会提醒你「用到了这本书不该用的词」的那几个
  - **比喻词**（黄色波浪线）：「仿佛」「犹如」「宛如」「如同」……全章合计超过 3 次（写正文时给模型定的上限）才标，没超不标
  - **英文缩写**（蓝色点线）：PTSD、CPU 这种两个以上大写字母的缩写，只是提醒——都市、科幻里的 CEO、AI 是正常的，故事的年代用不上才改
- **状态栏「体检」那一格**：「体检 3」是一共 3 处（比喻词算超出的那几个），没问题时写「体检 ✓」；开着的不是正文时不显示。点一下弹出体检面板：按类列出命中的词和次数，**点一个词就跳到它在正文里的位置并选中**，再点跳到下一处（面板上写着「2/5」），到底了从头再来。`Esc` 或点别处收起
- 打字时当场跟着变；几万字的章节也不卡（两万字以上隔一小会儿才重查一次，已经标着的会跟着字挪）。用输入法打字、拼音还没上屏的时候不查——拼音字母不会被当成英文敏感词
- 「视图」菜单「统计」后面那一组：「**体检高亮**」（缺省开，关掉之后正文里不画，状态栏那一格照样数）、「**状态栏显示体检**」（缺省开）、「**编辑敏感词表…**」。两个开关记在浏览器里，不进工程
- 与查找、段落聚焦同时开着时互不干扰：查找画的是底色，体检画的是下划线，段落聚焦管的是字的深浅。超过 30 万字的文件不画（面板里照样数、照样跳）

**敏感词表**：发布平台不让出现的词，你自己维护，放在 `.novelforge/sensitive.txt`。体检面板底下或「视图 → 编辑敏感词表…」打开它——还没有的话先建一份带说明的模板（不会盖掉已有的）。格式：

```text
# 井号开头的行是注释，空行不算
某平台
赌博 => 博戏
Free Money
```

- 一行一个词；`词 => 替换词` 给出建议的替换（只认半角的 `=>`）。英文不分大小写，全角字母当半角
- 有替换词的，体检面板里那一行多两颗按钮：「**替换本处**」换掉选中的那一处、接着选中下一处（还没选中时第一下只是选中，看清了再按）；「**全部替换**」把这份文件里的都换掉。两样都只改编辑区里这一份、一下 `Ctrl` + `Z` 就退回，存不存由你；不动别的文件
- 写错的行（`=>` 前面没有词、后面没有替换词、一行两个 `=>`、一个词超过 32 个字、和前面某一行重复）会跳过，不报错，面板里会说「第 N 行没看懂」，鼠标停上去看为什么
- 保存它和保存别的文件一样（会留历史版本）；存了之后体检马上按新词表标
- **现在只用于编辑器里的体检**：写正文时模型看不到这份词表，也不会替你避开它们；它也不在细纲、正文的指纹链上，改了它不会让任何一章挂 ⟳

**名词补全**（`Alt` + `/`，或「视图 → 名词补全」）：写到角色名、地名、门派、法宝这些名字时按一下，光标下面弹出一个小框，挑一个就补上，不用每次都把「太上忘情诀」打全，也不怕把「沈怀山」打成「沈怀珊」。

- **名字从哪来**：角色卡的名字和别名、设定条目的标题和关键词，还有设定名录里「出现过 · 未建条目」的那些名字。不调模型、不花钱。新建或改了角色卡、设定，下一次弹出来就是新的
- **列哪些**：光标前已经打了几个字（比如「沈怀」），就只列以它开头的名字；什么都没打、或者打的字对不上任何名字时，列出全部，**这一章里刚出现过的排在最前面**
- 每一行写着名字（打过的字标了颜色）、类型（角色，或者设定所在的目录：地点、门派、物品……）和卡或条目里那一句简介。对上的是别名时写成「老沈 → 沈怀山」，选它插进去的是「老沈」——你打的就是这个叫法
- `↑` `↓` 选，`回车` 或 `Tab` 插入：已经打的那几个字换成整个名字，光标停在名字后面，`Ctrl` + `Z` 一下就撤回。`Esc` 收起。框开着时接着打字它会跟着筛；打了标点、点了别处、切了标签、滚动页面时收起
- **边打边弹**（缺省关）：「视图 → 边打边弹名词补全」打上勾以后不用按键——打出某个名字的**头两个字**、还没打完整时，框自己弹出来。这时**回车照常换段**（框顺手收起），要插入名字按 `Tab`；接着打别的字它就自己收起。名字已经打完整了、只打了一个字时不弹（不然「林」「沈」这种常用字一打就弹）。这个开关记在浏览器里，不进工程
- 用输入法打字、拼音还没上屏时不弹，也不抢任何键
- 只在正文、草稿、细纲、角色卡、设定条目、情节大纲和叙事线里有；小说配置、故事前提、世界观、文风、敏感词表这些不弹
- 补全插进去的字算你码的字（「本次 / 今日码字」照算），撤销了就扣回去

**名词高亮**（缺省开，「视图 → 名词高亮」开关）：正文里出现的角色名、设定名标出来，一眼看得出这一段提到了谁、哪里。名字和名词补全是同一份（角色卡的名字和别名、设定条目的标题和关键词、设定名录里「出现过 · 未建条目」的名字），同样不调模型。

- **怎么标**：角色名一种淡底色，设定名另一种淡底色；名录里出现过、**还没建条目**的名字画一条虚下划线——看到它就知道这个名字还没有条目
- **鼠标停在名字上**一会儿，旁边弹出一个小框：名字、类型（角色，或者设定所在的目录）、卡或条目里那一句简介；你写的是别名时会说「这里写的是『阿昭』」。移开、打字、滚动就收起
- **`Ctrl` + 点击**名字（Mac 上是 `⌘` + 点击）：在这一块编辑区打开它的角色卡或设定条目。按住 `Ctrl` 指着能打开的名字时，鼠标变成手形。还没建条目的名字没有文件可开，会提示一句
- 认名字的规矩：长的名字优先（「林昭阳」不会被认成「林昭」）；只有一个字的名字或别名不标（不然「道」「气」这种设定会满屏都是）；英文名要整个词对上；角色卡、设定条目自己那一份里不标它自己
- 和写作体检标在同一处时，体检的下划线照画；和查找的高亮叠在一起时，查找的颜色盖过它
- 只在正文、草稿、细纲、角色卡、设定条目、情节大纲和叙事线里标，和名词补全一样；超过 30 万字的文件不标。新建或改了角色卡、设定，保存之后就按新的标。这个开关记在浏览器里，不进工程

#### 全书查找替换

`Ctrl` + `Shift` + `F`，或「编辑 → 全书查找替换…」；`Ctrl` + `Shift` + `H` 直接把光标放进替换框。在整本书里一起找、一起换，比如「把人名林晚全书改成林婉」。面板占的是左边侧栏的位置（和 VS Code 的「搜索」一样），右边的正文一点都不挡；点左边活动栏上任一页签、面板上的 ×、或按 `Esc` 收起，结果留着，再打开还在。

- **找**：打字停一下就开始搜；「Aa」「.*」两颗开关和单个文件的查找条是同一套（正则里也能用 `$1`）。下面一排勾选**在哪找**：正文（缺省只勾这一项）、细纲、草稿、角色卡、设定条目、其他创作文件（情节大纲、小说配置、故事前提、世界观、文风指南、叙事线、全文大纲）。编辑区里选着一行之内的几个字时按 `Ctrl` + `Shift` + `F`，直接拿它来搜
- **结果**按正文、细纲……分组，一份文件一行：「第 3 章 夜访」「细纲 · 第 3 章 夜访」「角色 · 林晚」这样的称呼和一共几处，下面每一处一行上下文，找到的字标着颜色。点一处就在右边打开那份文件、选中那几个字（那份文件的查找条也亮着同一个词，`F3` 接着往下跳）；点文件那一行收起 / 展开
- **搜的是磁盘上存着的内容**：编辑器里改了还没保存的文件，结果上标着「未保存」——列的是磁盘上那一份，替换时也会跳过它
- 一次最多列 1000 处，多了会说「只列了前 1000 处」、搜到哪一份就停了；多打几个字缩小范围。超过 2 MB 的文件不搜，也会说出来。搜得慢的时候点「停止」
- **换**：填好替换框，点「**预览替换**」——每一处都画成「旧的划掉、新的跟在后面」，每一处、每个文件前面都有勾，缺省全勾；「林晚霞」这种不该换的就勾掉。确认之后点「**替换所选**」，按钮先变成「再点一下：替换 N 个文件 M 处」，再点一下才真的换
- 换完会告诉你**换了几个文件几处、跳过了哪些、为什么**：编辑器里改了没保存的跳过（先保存或放弃修改，再换一次）；预览之后在别处改过的跳过（不会拿预览时的内容盖掉新改的），重新预览一次就行。然后自动再搜一遍，列出还剩下的
- **每个改过的文件都可以在「历史」里找回替换前那一版**（打开那份文件，点工具栏上的「历史」）——换之前每一份都先存了一版。跨好几个文件的替换**没有一步撤销**，历史版本就是退路。已经开在编辑器里、没改过的标签会自动换成新内容
- **不会动的东西**：细纲、角色卡、设定开头那段 frontmatter 里程序自己记的账（指纹、章号、字数、状态……）不搜也不换——搜「3」换成「三」不会把它们弄坏；名字、别名、标题、出场人物照样换。细纲的「关键事件」、角色卡的「当前状态」这些小节的**标题行**也不换（换了程序就认不出那一节了），情节大纲里「第1–5章」那一截同理
- **会不会让章节挂 ⟳**：细纲和正文在同一次替换里**都**改了（全书改名就是这样），那一章不会因此挂 ⟳、定稿过的也不会退回「待定稿」；只改了细纲、正文没跟着改的，正文会挂 ⟳；只改了正文、细纲没跟着改的定稿过的章，回到「待定稿」；改了大纲、细纲没跟着改的，细纲挂 ⟳——这几种换完都会在汇总里列出是哪几章
- **角色改名**：角色卡里的名字或别名换了，文件名不会跟着改（`林晚.md` 还叫 `林晚.md`）——认人看的是卡里的名字和别名，不看文件名；汇总里会提一句，想改文件名就在工程页右键「重命名」。出场统计、设定名录这些会按新的名字重新算

#### 叙事线总览

工程页「叙事线」页签标题旁的「**总览**」，或一行右键「**在总览里看**」，在编辑区里打开一个不对应文件的标签「叙事线总览」：一张章 × 线的时间轴，一眼看出每条线走到哪、哪条伏笔该收了、计划的事哪一章没发生。不调模型，全是从叙事线文件与章节现算的。

- **横着是章**：从第 1 章画到计划或已写的最后一章（细纲、正文、计划里提到的回收章都算）。列头写章号，底下一道颜色说这一章定稿没有：绿的定稿了、蓝的写了还没定稿、灰的只有细纲；分卷的书上面多一行卷名。一条绿色竖线标在「定稿到第 N 章」那里。
- **竖着是线**：按主线、支线、感情线、人物线分组，每条线下面缩进列它的伏笔，最后是「未归属的伏笔」。线名前的 ● ○ ✓ ✕ 和工程页一样是进行中、计划中、已收束、已放弃；有 ⚠ 的鼠标停上去看是什么。
- **线的格子**：○ 只有计划（拆细纲时排的），● 只有实际（定稿时认出来的），◉ 计划了也发生了；**红圈**是计划了、那一章也定稿了，却没有发生——最该回头看的就是它。线的计划区间画一条淡底。
- **伏笔一行**：埋 ● 到收 ◆ 之间连一条线；还没收的虚线延到计划回收的那一章（那一格一道竖线），过了还没收的整条标红；弃了画 ✕；还没埋的按计划画一条淡虚线，计划的埋与收画空心。排细纲时把回收推迟到更晚一章的，虚线延到晚的那一章。
- **鼠标停在一格上**看那一章这条线上计划了什么、实际发生了什么，带原文证据。**点一格或列头**打开那一章（正文在左、细纲在右，还没写的打开细纲）；**点线名、伏笔名**打开那条线的文件。左边一列与表头不动，横着滚看后面的章。
- 开着时你保存了文件、定稿了一章，它自己跟上；标签右键或右上角「刷新」也行。刷新页面后这个标签还在。

## 桌面 App（Windows / Linux）

不想开终端、不想面对浏览器地址栏的话，还有一个桌面壳：双击图标就是一个普通桌面应用。
不带工程也能启动（空窗口 Get Started）；上次关窗口时工程还开着则恢复。打开/关闭文件夹
走页面里的 File 菜单，不重启窗口、不杀 sidecar。

```bash
npm run app:dev      # 开发运行（需要 Rust 工具链）
npm run app:build    # 出安装包（Linux: AppImage / deb，Windows: NSIS）
```

它是**一层纯壳**：里面装的就是上面那个独立 Web 版的单文件可执行，壳负责把它悄悄起起来、
把窗口导航过去、退出时收掉。所以界面、功能、数据落点与独立 Web 版**完全一致**——
文件仍是工作区里的普通 Markdown，仍然可以用你自己的编辑器改、用 Git 管。

换工程用标题栏「文件 → 打开文件夹…」。服务起不来时闪屏给出原因和「查看日志」
（壳看到的进程输出在 `<应用日志目录>/sidecar.log`，与网页里那个「日志」页不是一回事）。

Windows 安装包必须在 Windows 上构建（sidecar 能交叉编译，Tauri 的 Rust 壳不能），
见 [.github/workflows/app.yml](.github/workflows/app.yml)。细节与已知坑见
[src/shells/desktop/README.md](src/shells/desktop/README.md)。

### 工程页

顶上一行是五个页签：**概览**（定稿进度黄条、「故事架构」与「文风与摘要」两组）、**章节**、**角色**（连同「出场人物 · 未建卡」）、**设定**（连同「待完善」「出现过 · 未建条目」）、**叙事线**，最右边是刷新。切页签不重新拉数据，切回来还停在上次滚到的地方；数据刷新了也停在原来那一页。每页里是可折叠的分组（「出场人物 · 未建卡」「待完善」「出现过 · 未建条目」只在确有时出现）。行上只有内容——图标、名字、字数与状态——**操作都在右键菜单里**，和文件管理器一样；例外只有「去生成」「去写这一章」两颗按钮，各只有一颗。

动作都在分组的右键里：三个批量入口——**补齐架构**在「故事架构」组，**批量拆细纲…**、**批量写章…**在「章节」组（要调模型，动手前都先问或先开表单）；新建细纲、新建章节文件在「章节」组，新建角色卡、新建设定在「角色」「设定」组（这两页里分组下面的空白处右键也一样），新建文件夹在「章节」「角色」「设定」三组与各文件夹的右键里（「章节」组的建在 `chapters/` 下，用来分卷；这一组按章号平铺，空的卷目录在这里看不见，把章节挪进去之后新的一章会跟上一章落进同一个卷目录）。

- **故事架构** —— 六行：小说配置、故事前提、角色图谱、世界观、设定清单、情节大纲，行首圆点说填过没有（`●` 填过、`○` 待生成），组标题写着填了几件（`5/6`），情节大纲那一行写着覆盖到第几章。**第一件还没填的那一行在行尾有一颗「去生成」**：小说配置那一行打开一句话表单（已经写了正文时是「照已写正文生成」：只定规模，补充要求可以留空），其余几行把对话页切到那一层（主按钮就是生成它）。点名字在编辑器里打开那份文件；角色图谱与设定清单没有自己的文件，没填时点它进入那一层，填过之后点它切到「角色」「设定」页签。**设定清单**照世界观排出 12–30 条核心设定（地点、势力、能力体系、关键物品、制度与概念），连同一套按这本书的题材起的分类目录一起建出来（两步：先清单、再每 6 条补正文，3–6 次调用）；已经写了正文的书不需要它（算填过），那种书的设定从定稿里长出来。分组标题右键有「从一句话生成小说配置…」「补齐架构（只补空白）」与「从已写正文补齐…」。
- **章节** —— **一个章号一行**，细纲与正文是同一行的两面：`第12章 夜入青云　待写正文　2980 / 3000`。
  - 行首圆点说定稿没有（`●` 已定稿，细纲与正文对得上；`○` 还没定稿，或定稿之后正文又改过；`·` 还没写正文）；状态徽章说这一章该做哪一步（待写细纲 / 待写正文 / 待定稿，已完成的不挂）；字数写成「写了多少 / 目标多少」，后面的「· 草稿」表示有草稿；细纲在正文写完（或定稿）之后改过、或者大纲里覆盖这一章的那一节改过时挂一个 ⟳。
  - **下一个该写的章在行尾有一颗「去写这一章」**——全书只有这一行有。点了把对话页切到这一章当前该做的那一步；真正花钱的那一下仍是对话页的主按钮。
  - 点名字**打开这一章**：正文在主编辑区，细纲并排在旁边（独立版是两块编辑区，插件用 `ViewColumn.Beside`）。右键有「打开正文 / 打开细纲 / 进入这一章 / 细纲 · 正文（各带完成度，点了直接切到那一层）/ 定稿（定稿过的写「重新定稿」）/ 草稿」，以及重命名与删除。**没有「移动到…」**：顺序由章号决定。
  - **鼠标悬停在行上会浮出这一章的细纲**：悬停约半秒后出现，按小节分块（空着的小节不显示）；还没定稿的标「计划」，定稿之后正文又改过的标「已过期」；没有细纲时说一句（有正文的章会提示右键「定稿」照正文整理一份）。**鼠标可以移到浮窗上去**——那样它会一直留着，长细纲可以滚动，也能选中复制；移开才收。浮窗始终夹在窗口内，屏幕矮时自动翻到行的上方或压低高度改用滚动。
  - 在**分组标题**上右键有「新建细纲（接在最后一章之后）」「新建章节文件（直接粘正文用）」「导入原稿（选一本 txt）…」与两条批量动作「批量拆细纲…」「批量写章…」。
  - 分组还空着、或者下一章还没有细纲时，组里写着「下一步：……」——就是对话页主按钮那一句——旁边一颗按钮直接可点（打开一句话或拆细纲的表单，或者把对话页切到那一层）。
- **角色** —— 副标题除标签别名外，还给出「状态截至第 K 章」（定稿时把「当前状态」更新到了哪一章）。这个人在定稿过的细纲里出场了几章写在后面（「出场 12 章」），上次更新角色卡之后又出场了几章，会以 `＋N` 标在行尾。右键除「打开」与三个类文件操作外，多两项：**更新角色卡**（只读新增的那几章）与**重新通读全部 N 章**，详见下一节。分组标题右键有「更新所有角色卡」「从头重建所有角色卡」，以及**提取/更新角色卡（挑几章正文）…**——挑几章正文一次扒出一批角色，新角色直接建、已有的走对比，不依赖定稿。定稿时如果「当前状态」那一节被你改过，工具不会覆盖它，而是在这张卡上挂一个黄色 ❗，右键「对比第 N 章给出的状态…」看机器那一版要不要用。
  在**分组标题**上右键另有两条不调模型的整理动作：**清理别名**——删掉 aliases 里不是专属称呼的词（`她`、`姐姐`、`少女`、`这位小姐` 这类泛称，以及被误填成别名的其他角色的名字）；**查找并合并重复角色卡**——同一个人被建成两张卡时（定稿过的细纲里一会儿写「方源」一会儿写「古月方源」就会这样），逐组问你保留哪一张，其余的搬进 `.novelforge/.trash/`。两者都只改文件头部的 frontmatter，**你手写的正文一个字都不会动**。
  如果有两张卡抢同一个称呼，这一组顶部会出现一条黄色提示——出场统计只会算给其中一张，另一张必然是错的，而这件事光看界面看不出来。
- **出场人物 · 未建卡** —— 定稿过的细纲里出现、但还没有角色卡的人物（没定稿的细纲里排的是计划，不算），按出场章数从多到少排。右键「创建角色卡」会建一张卡，并通读他出场的那几章把档案填出来（动手前问一句）；点名字不做事——扫列表时手一滑不该在角色区多出一张空卡。在分组标题上右键还有「给全部 N 人建卡」，一次把这一组清空（动手前会报清人数、章数与预计调用次数）。这一组只在确实有这种人时出现。
- **设定** —— 地点、势力、物品、概念这类要前后一致的东西，一样一条。**目录就是分类**：每本书自己定、可以嵌套（`宗门/正道/青云宗.md` 的分类是「宗门/正道」），把文件拖到别的目录就是改分类。一行是标题、一句话简介（条目 frontmatter 的 `brief`，没写就是正文第一句），右边是它在定稿里出现在哪几章（`第 3–57 章 · 12 章`）；条目落后于正文时挂 `＋N`（之后又有 N 章写到了它、还没整合进条目）。几百条时用组标题旁的**筛选框**按标题、一句话或关键词找，命中的目录自动展开。
  - **待完善**（排在设定组和「出现过 · 未建条目」之间，只在确有时出现）：还没写正文的细纲里打算用到、条目却还只有一句话的设定（条目是空的、只有新建时的占位、三节全是「未交代」，或者干脆还没有条目），按最早要用到的那一章排：`天机阁〔宗门〕· 第 12 章起要用 · 只有一句话`。右键「**展开…**」把它往前想细（见下）；还没有条目的先按细纲里写的分类建一条空的再展开。不调模型就列得出来。组标题右键「**全部展开（K 条，预计 K 次调用，最多 2K 次）**」一次展开这一组：没有卡片，**写完直接落盘**，所以只写空的、只有占位的、和机器写的三节「未交代」（设定清单起步时留下的那种）；三节「未交代」是你手写的、或者你只写了暗设的，一律跳过（确认框与完成提示里都列出来），要展开就单条展开、先对比。建议拆出去的子条目照样建成空条目，但不在同一批里接着展开；「还没定的问题」批量没处放，不留——要看问题就单条展开。每条 1 次，JSON 语法坏了修一次、解析不了重来一次，两样合计最多再 1 次；走「故事架构」档。
  - **出现过 · 未建条目**（紧跟在待完善后面，只在确有时出现）：定稿里出现过、还没有条目的名字，按出现章数排。右键「建条目」调一次模型，拿定稿细纲里提到它的那几句写成一条（不重读正文）；「新建这条设定」建一份空的，不调模型。组标题右键「给出现 2 章以上的 M 个建条目」一次建完。
  - 设定组右键按待办给：「**补记设定**」（这个功能之前定稿的章还没记过设定时，一章一次）、「**整合设定**」（把定稿里的新内容并进挂着 `＋N` 的条目，一条一次；条目是机器写的可以选直接采纳，你改过的一律先给你对比；只并不删你写的字）、「**按目录整理…**」（让模型照本书的目录树给条目归类，先出一份搬家清单给你看，点了「照这样整理」才搬，只搬文件不改内容）。挂着 `＋N` 的那一行右键还有「整合这一条」。
  - **展开一条设定**（每一条右键都有「展开…」，预计 1 次调用，JSON 坏了修一次、最多 2 次）：排细纲时想先把要用到的地方、势力、规矩想细，就展开它。先问你一句要求（可以空着），然后在对话页把目标换成这一条、生成一次：模型看得到这一条现有的内容、**已排细纲里打算用它的地方**（带章号）、定稿里已经确立的事（不许推翻）、相关的几条设定与世界观，写出一句话、关键词、三节正文与可选的「暗设」。卡片上另外列出**还没定的几个问题**（只给你看，不写进任何文件——在对话里接着答就是）和**建议拆出去的子条目**（点写入时一起建成空条目，之后再分别展开）。条目原来是空的就直接写，原来有内容的先给你对比；写进去的算机器写的，以后整合可以直接按正文改。对话页的目标是一条设定时，直接打字就是聊这一条，`/展开` 是生成。
  - **暗设**：条目可以多写一节 `## 暗设`（≤200 字，不算进三节的 600 字），放读者还不知道的真相——真实身份、来历、规则背后的原因。**排大纲、排细纲、聊设定时带上**（标明读者还不知道），**写正文、接着写时不带**，正文阶段你 @ 引用这条设定也不带，免得提前说漏。哪一章要揭开，就在那一章细纲的关键事件里写明「揭开：……」，正文是从细纲知道这件事的。整合时，正文已经揭开的挪进前三节；原来有暗设、整合完没了的，就算是机器写的也先给你对比。
- **叙事线**（单占一个页签，排在设定后面）—— **一条线一行**，按主线 → 支线 → 感情线 → 人物线排，同一种里最近推进过的在前：`林昭与沈青 · 感情线 · 进行中 · 最近第 12 章 · 2 条伏笔没收`；还没推进过的写计划区间。有问题的另起几格标出来：`⚠ 断了 15 章`（进行中的线这么多章没有动静：主线 5 章、其余 15 章）、`⚠ 1 条伏笔逾期`（过了计划回收的那一章还没收）、`⚠ 过了计划收束的第 40 章`。这些都按「定稿到的最后一章」现算，不落盘。最后一行是「未归属的伏笔 · N 条」。点一行打开那条线的文件，鼠标停在名字上看意图与当前进度；某条线的「当前进度」你改过、定稿时没覆盖，那一行挂黄 ❗。页签标题旁有「**从大纲排出**」（已经有线时是「从大纲补充」）：先弹确认框，写明 1 次调用；还没有情节大纲时不给，排线失败的红 ❗ 也挂在这里。独立版与桌面版标题旁还有「**总览**」：在编辑区里打开[叙事线总览](#叙事线总览)（不调模型）；一行右键「**在总览里看**」打开它并标出这一行。VS Code 插件里没有内置编辑器，这两样不出现。把一行伏笔挪到别的线下，就是在文件里剪贴。
- **文风与摘要** —— 全文大纲（原「全书摘要」，写着覆盖到第几章：只有「主线进展」一节，写已经写完的部分主线是怎么一步一步走过来的；伏笔与人物关系的变动记在叙事线里，往后的计划是情节大纲。老工程里那份另外三节「已收伏笔 / 未收伏笔 / 人物关系变动」留在文件里、不再读，下次更新只写主线）与文风指南两行，全文大纲带「重建」，文风指南带「从正文提取」「从参考书学」。行内的这几个链接鼠标移到行上才亮。这几行是工程的固定文件，**不能**重命名或删除。分组副标题给出定稿覆盖情况（如「已定稿 62/76 章 · 14 章待定稿」）。

**出错的行会挂一个感叹号。** 角色卡、章、设定条目一旦生成失败，那一行的名字前面会出现 ❗，鼠标移上去说清楚发生了什么：**红色**表示这次整体失败、磁盘上的东西一个字都没改（比如模型没按要求返回 JSON，角色卡原样不动）；**黄色**表示部分完成，或者写出来了但需要你看一眼（批量写章写出来的这一章开头重演了上一章、把后面几章的人提前写了进来、或者没写够八成）。浮窗里能看到时间、原因与建议，鼠标可以移进去选中复制。这个标记会**一直挂着直到那一项成功为止**，成功之后自动消失——你不必守着日志页，也不会因为错过一条 toast 就拿着一张没更新的角色卡继续写下去。（完整记录仍然在日志页，那里能翻到每一批的细节。）

有写了正文还没定稿的章（或定稿之后正文又改过）时，「概览」页顶部会出现黄条，写清有几章、这些章的连续性事实与出场人物不会进入上下文，以及「已定稿多少 / 共多少章」，并画一条进度条；点「立即同步」把这几章逐章定稿（和单章「定稿」一样三步：照正文更新细纲、更新出场角色的当前状态、认这一章在叙事线上发生了什么；确认框里写明调用次数），跑起来后由页头的任务条接手。**这条提示只长在工程页**——对话页那点宽度留给正文；人在别的页时，活动栏「工程」上的小圆点负责留个记号。工作区还不是小说工程时，这一页显示初始化入口。

#### 三个批量入口

都在分组右键里（补齐架构在「故事架构」组，另两个在「章节」组），**都只补空白**：已经有的一律跳过，不问也不覆盖（一次弹几十个对比框没人看得完，跳过是那条路上唯一安全的做法）。要重做某一章，去对话页单独重做。动手前的表单或确认框都写清要调几次模型、走哪一档，还可以只为这一次换模型、换上下文详细度（见[确认框上临时换模型与详细度](#确认框上临时换模型与详细度)）。

- **补齐架构** —— 配置 → 前提 → 角色图谱 → 世界观 → 设定清单，缺哪件补哪件，按顺序一件一件来（每件都吃前面几件的产出），一件失败就停。小说配置要有「一句话」可以展开；已经写了正文的，配置、前提与世界观照正文整理，不需要一句话。想连细纲、角色卡、大纲一起补，用「故事架构」组右键的**从已写正文补齐**（见[拆书](#拆书导入原稿与参考书)）。
- **批量拆细纲…** —— 选一段章号（缺省从下一个该写的章起 5 章，不越过大纲覆盖的范围），已有细纲的章跳过，每批 5 章一次调用，一批失败就停。一条叙事线都还没有时，开拆之前先从情节大纲排一次（表单与确认框里 +1 次；没排成不挡拆细纲）。拆的时候带上叙事线，拆出来的每一章在线上的计划随细纲写进各条线（跳过的章原来的计划不动）。表单上实时写着跳过几章、分几批、预计与最多几次调用。另有一项「**拆完展开本批新设定**」（缺省「否」）：选「是」，拆完把这一次细纲里新引入、顺带建成空条目的设定一起展开（同「全部展开」的规矩）——新设定有几条要拆完才知道，所以拆完会再弹一次确认框报次数，取消了只是不展开。
- **批量写章…** —— 选一段章号（缺省从下一个该写的章起 3 章，最多 10 章）与模式：**只写正文**，或**写完即定稿**；另可勾「写完即审稿」，每写完一章先审一遍，报告放进一个新会话「批量审稿 · 第 a–b 章」，你回头在报告卡上逐章勾选、修稿。
  - **一章一章串行写**：后一章要接着前一章的结尾写，写完即定稿时还要读前一章更新过的角色状态。
  - 写不出来就停；写出来但开头重演了上一章、把后面几章才登场的人提前写了进来、或者没写够八成的，照样落盘，然后停下、挂黄 ❗，等你看过再继续。
  - 开跑之前做一次一致性预检：细纲把角色卡上写着已经死了的人排进了某一章，就先问你一句（「仅本次忽略，照写」）。
  - 要写的几章细纲里点名、却还只有一句话的设定（就是「待完善」里的那几条），表单说明里提一句「区间里 K 条要用到的设定还只有一句话」——只是提醒，不拦，也不顺带展开。叙事线同样提醒两件事：写到区间里哪一章时有伏笔过了计划回收章、区间里的计划又都没安排收它；哪条线写到哪一章时就断了好几章、区间里也没安排推进。
  - 任务条上有「写完这一章就停」：这一章照常写完、落盘（定稿），然后收工。

#### 任务条

批量写章、定稿、同步细纲、重建全文大纲、提取角色卡/文风这类要连着调几十次模型的动作，会在页签上面出现一条任务条，**五个页签都看得见**——从对话页点的定稿，切到工程页照样看得见进度：**任务名 · 当前那一章 · 第几项/共几项 · 百分比 · 已用时 · 停止**。

- 计时每秒自己走，不等后端推——一次模型调用可能安静一分钟，秒数停住会让人以为卡死了。
- 不知道总量的阶段（比如提取文风的「分析中」）画一条来回扫的条，不给假的百分比。
- 「停止」立刻中断，已完成的部分**保留**（同步细纲是一章一写盘的，停在第 30 章，前 30 章的细纲就已经照正文更新好了——角色状态与叙事线在细纲之后按章号逐章补，没补到的章挂黄 ❗，右键重新定稿就补上；批量写章停下时，正在写的那一章不落盘）。批量写章另有「写完这一章就停」。
- 做完时弹一条提示，按钮直接打开产物：「打开第 N 章」，批量审稿时是「打开审稿报告」。
- 刷新页面或重连后任务条自动接上，任务不会因为你关了标签页而消失。

同一时刻可以有多个任务并存，各占一行。

### 日志页

第四个页签。上面说的每一步都在这里留痕，用来回答「刚才那 76 章卡在哪了」：

| 能做什么 | 说明 |
|---|---|
| 按级别过滤 | 调试 / 信息 / 警告 / 错误，默认「信息及以上」。逐章请求这类细节在「全部（含调试）」里 |
| 关键字过滤 | 对来源、消息、详情一起匹配 |
| 展开详情 | 带 ⏵「详情」的行可以点开，里面是耗时、文件路径、失败原因、堆栈等 |
| 加载更早 | 往前翻**重启之前**的日志。日志页平时只显示本次会话的几百条（存在内存里，关掉就没了），更早的存在 `.novelforge/novelforge.db` 里，保留 30 天。点一次往前翻一页，翻到头按钮会变成「没有更早的了」 |
| 复制 | 把**当前筛选出的**日志按纯文本复制，方便贴进 issue |
| 清空 | 清掉**内存缓冲**（库里的历史不动，仍然翻得到）。会留一条「日志已清空」——「日志是空的」和「日志被清过」是两回事 |
| 自动滚动 | 默认开。翻上去看东西时不会被新日志拽回底部 |

两条安全约定：

- **日志里绝不出现 API Key**。所有文本都过一遍脱敏，`sk-…`、`Bearer …`、`api_key=…` 一律抹成「…〔已隐去〕」。可以放心整段复制出来求助。
- **不记 prompt 与正文全文**，只记条数、字数与 token 估算。一次续写的 prompt 有十万字，记下来会把此前所有日志挤没。

日志只存在内存里（最近 800 条），不落盘、不上传，关掉进程就没了。插件版另外把同一份日志写到 VS Code 的**输出面板**（「Novel Forge」通道，命令 `Novel: 显示输出面板日志`），可以和其他扩展的日志并排看；独立版则打在启动服务的终端里（`--verbose` 连调试级一起打）。

其它页面（对话、历史、设置）以及独立版的编辑区，右键给一个「刷新」。

#### 文件夹与文件操作

章节、角色、设定三个区都能像文件管理器一样用：**建文件夹、往里塞东西、随便嵌几层**。文件夹默认折叠，点一下展开，折叠状态记在界面上，刷新数据不会把你收好的树又摊开。（细纲不在其中：它镜像正文的路径、跟着正文搬，所以走章节那一行的右键——见下。）

新建有两个入口：在分组标题或分组空白处右键「在此新建…」落在区根目录（「角色」「设定」页里分组下面的空白处也算；「章节」组是「新建细纲」「新建章节文件」，以及建分卷目录的「在此新建文件夹」）；**在某个文件夹上右键，落点就是那个文件夹**。

新建细纲**不问标题**：文件按纯序号命名（`007.md`），接在最后一章之后、与上一章放在同一个子目录（分卷的书写到第二卷时就落在 `.novelforge/summaries/第二卷/`，之后写的正文照它落进 `chapters/第二卷/`），建完直接把你送到这一章当前该做的那一步——刚建出来是空的，所以那一步是「写第 7 章细纲」。标题要等细纲排完、知道这一章到底发生什么之后再起，走「重命名」（或对话页顶上那支 ✎）。

任意文件或文件夹上右键，还有这三个操作：

| 操作 | 说明 |
|---|---|
| 重命名 | 章节的 `NNN-` 序号前缀自动保留，只让你改标题部分。正文首行的 `# 标题` 只在它原本与文件名一致时跟着改——你要是单独改过它，那是你手写的东西，改名不动。草稿与细纲跟着搬 |
| 移动到… | 弹出同一个区里的目录列表（含根目录）选落点 |
| 删除（移到回收站） | 搬进 `.novelforge/.trash/`，保留原来的相对路径，随时能手动捞回来。文件夹连里面的东西一起搬，删之前会告诉你里面有多少个文件 |

**细纲的改名与删除是另一回事**：细纲镜像正文的路径（见[目录结构](#目录结构)），改名改的是标题——还没写正文时文件名跟着标题走、章号前缀不动；已经有正文时文件名跟着正文不动，只改细纲里的标题。正文从不因为给细纲改名而改名。删除细纲只把细纲搬进回收站，**这一章的正文不受影响**；定稿过的细纲同时是这一章的档案（连续性事实、实际出场都记在里面），删了它们也一起进回收站。工程页那一行有正文时，「删除」落在正文上、细纲留着（它退回这一章的计划）；只剩细纲的行才删细纲。细纲没有「移动到…」：单挪它就与正文对不上了。章节（或整个卷目录）改名、移动时，草稿（见下）与细纲都跟着搬；新位置已经有同名的就不动旧的，提示你自己去合。

几条不会被打破的规矩：**不跨区**（章节挪不进角色目录，任何操作也出不了工程目录）、**不覆盖**（目标位置已有同名文件就直接报错退出，绝不悄悄盖掉）、**不真删**（一切删除都是搬进回收站）。

改名与移动都**不会让这一章的产物变旧**：跟着改的只有 frontmatter 与标题行，参与新鲜度判断的指纹一个字节都不碰——给一章起个名字不该让它写好的正文显示「上游已变更」。

章节分子目录不影响任何逻辑：章节序号仍然全书连续。

### 章节草稿

每一章都可以有一块**和正文并排的涂改区**：放废弃的段落、备选的写法、给自己的批注。草稿是普通文本文件，跟着工程走、可 Git、可手改，和别的东西一样。

在章节上右键点「新建草稿」（已有草稿时显示「打开草稿」），或者在内置编辑器里打开正文后点工具栏的「草稿」按钮。**首次点的时候才创建**——不会给一个已经二百章的工程凭空撒二百个空文件。

草稿存在工程根的 `drafts/` 下，路径镜像章节在 `chapters/` 之下的那一段，文件名（含扩展名）原样沿用：

```
chapters/001-楔子.md        →  drafts/001-楔子.md
chapters/第二卷/003-夜访.md  →  drafts/第二卷/003-夜访.md
chapters/005-手记.txt       →  drafts/005-手记.txt
```

几条要记住的：

- **草稿不进 LLM 上下文。** 装配器任何阶段都不读它——想让模型看见，就在 `@ 引用` 里手动挑（草稿单列一组，只列已经建过的）。
- **绝不覆盖。** 第二次点「打开草稿」只是打开，不会把你写的东西换成模板。
- **草稿跟着章节走。** 章节改名或移动，草稿一并搬过去；如果新位置已经有草稿了，两份都留着并提示你自己去合。
- **删章节不删草稿。** 确认框里会说明草稿留在哪儿。
- 草稿**不是**可管理区：它不出现在工程页的树上，也不能在界面上重命名/移动/删除——它的位置由章节路径推导，直接改它只会让下次点「打开草稿」建出一个新的空文件。要清理就在文件管理器里删。
- 草稿字数不计入章节字数，也不影响定稿状态。

### 对话怎么用

对话页从上到下分四块：**流水线条**（我在哪一章、走到哪一步）、**工作区卡**（我正在改的那份东西）、消息区、**下一步**（我接下来该干什么）。

打开一章的正确方式是**在工程页点「去写这一章」或右键「进入这一章」**，或者在输入框旁的下拉框里选它。选中之后界面会自动落到**这一章当前该做的那一层**：还没排细纲就落细纲层，细纲排好了就落正文层。你不需要自己判断该从哪儿接着做。

#### 流水线条

顶上一行只报你在哪：`第 4 章《夜入青云》`（**信息条不是按钮**，切层靠下面那两格；这一章走到哪只在下面那一行报一次）。右侧两个小按钮：**✎ 给当前这一章的细纲起名/改名**（新建出来的细纲只有序号，起名就在这儿），**＋ 开始一段新对话**。下面一行是这一章的两层与定稿状态：

```
细纲 ●  正文 ◐ ⟳   待定稿
```

- 状态点是**实打实算出来的**：正文写到目标字数的一半就是「进行中」，不是一个存在文件里的状态字段（那种字段在你手删半段正文之后就开始撒谎）。
- **⟳ 表示上游改过**。改了细纲，这一章的正文就挂上它；改了大纲里覆盖这一章的那一节，细纲挂上它——不是错误，是提醒你回头看一眼。手写的产物永远不会挂 ⟳（拿一个凭空的过期标记催你重做，你会学会无视所有标记）。
- 定稿只报状态（未写正文 / 待定稿 / 已定稿），不是一层：它是写完之后的一步。

两层都可以点——**流水线不是单行道**。写正文时发现细纲不成立，点回细纲层改了再回来，比自己去 `.novelforge/summaries/` 里翻文件快得多。目标是架构或大纲时这一行只剩名字。

#### 工作区卡

流水线条上挂着一个入口，写着「当前产物 · 正文」（只写是哪一层，章名在上面那行），鼠标移上去（或点一下钉住）浮出**当前这一层的产物本身**：架构层是那份文档，大纲层是开头一段，细纲层与正文层是这一章细纲的各节（空着的不摊；正文层另报字数与目标字数——三千字正文摊在浮窗里没人读，要读点「打开」）。聊到第十轮它还在——回头确认「这一章到底要收在哪」不用往上翻。还没写的这一章细纲里点名的设定还只有一句话时，入口挂一个淡色的 ◌，浮窗里提一句「本章要用的 天机阁、九层楼 还只有一句话，写之前可以先展开」——不调模型、不拦，主按钮照旧是写这一章。叙事线的两件提醒（伏笔逾期、线断了）也在这里提一句，口径一样。

#### 下一步

输入框上方只有**一个主按钮**，写着这本书现在该做的那件事，旁边的说明里写着要调几次模型：

| 当前状态 | 主按钮 |
|---|---|
| 还没有小说配置 | 生成小说配置…（先弹出一句话表单：脑洞、总章数、每章字数） |
| 前提 / 角色图谱 / 世界观缺哪件 | 生成故事前提 → 生成角色图谱 → 生成世界观（一件一件推） |
| 没有大纲，或下一章超出了大纲覆盖的范围 | 生成情节大纲（第 1–20 章）/ 续写情节大纲（第 21–40 章） |
| 下一章还没有细纲 | 拆细纲（第 N–N+4 章） |
| 选中的这一章细纲还空着 | 写第 N 章细纲 |
| 有细纲、没正文 | 写第 N 章 |
| 正文还没写够目标字数的八成 | 接着写 |
| 细纲在正文之后改过 | 重写第 N 章 |
| 正文写够了、还没定稿（或定稿之后正文又改过） | 定稿第 N 章 |
| 这一章都齐了 | 落到下一章的那一步 |

**点了就跑，不必先输入什么**——该说的都在架构、大纲与细纲里了。输入框里有字就当补充要求一起带上（「多写点雨里的细节」）。次数写在动手之前：写一章是「预计 1–2 次调用，最多 9 次」（开着删修饰时写完再删一次；没写够时自动续写），定稿是 1–3 次（照正文更新细纲一次，有出场角色卡时再一次，有还没收的叙事线时再一次）。**单章写完不会自动定稿**——要你点那一下。

**写完删修饰**（设置 → 上下文管理，缺省开）：开着时正文按目标字数的 1.2 倍去写，一章写完，同一个模型再过一遍，只删名词前堆的形容词、动词前的程度副词这类多余修饰——不加字、不动对白，删坏的段落自动退回原文，删完不到目标字数的八成就把删得最多的段退回去。对话页点「写入」之后会弹出删前 ↔ 删后的逐段对照，删错的段可以退回原文（VS Code 插件里没有这一步，直接用删后的）。

写正文的提示词只给篇幅的大概（「约 N 字，不必精确」），够不够由续写按实际字数判断；另要求多让人物开口——交代、对峙、讨价还价写成对白，续写时已写部分对白偏少（不到四分之一的段）会被点名提醒。

其余动作收在 **`/` 命令**里：**在输入框里直接打 <kbd>/</kbd>**（和 Cursor、Claude Code 一样），候选列表就浮在输入框上方；也可以点输入框下面那颗「/」。接着往下打字就是过滤，中文和拼音首字母都认（`/ld` → 落定细纲）。<kbd>↑</kbd><kbd>↓</kbd> 选，<kbd>Enter</kbd> 确认——命令变成输入框里的一枚标签，那几个字符自动收走，剩下的空间留给补充要求。按 Enter 执行，用完即清：命令是一次性的选择，不是模式。各层的命令：

| 层 | 命令 |
|---|---|
| 架构 | `/生成这份架构文档`；目标是一条设定时 `/展开` |
| 大纲 | `/生成情节大纲` |
| 细纲 | `/写细纲`、`/落定细纲` |
| 正文 | `/写正文`、`/审稿` |
| 每一层 | `/落定设定` |

**`/落定细纲` 只有细纲层有**，它是「先跟人聊、聊出结论再落文件」的那条路：跟 AI 来回讨论几轮这一章该怎么走，谈拢了打 `/落定细纲`，它把讨论中**已经达成的结论**整理成细纲——不会塞进被你否掉的方案，也不会临时发明新走向；还没定下来的地方留空并在细纲之外说一句。为此这条命令装配上下文时**会把整段讨论都带上**（历史预算从三成抬到六成，优先级提到最高）：要沉淀的就是那段对话，按常规由远及近截掉等于把结论截没了。另一条入口是 **`/写细纲`**：你在输入框里描述这一章的走向，它按你说的填，你没说到的地方顺着已有设定与前后章补上。改写也不是另一条命令：目标已经有内容时再点「生成」，你输入框里的话就是修改意见，它会在那一版的基础上重做。

**`/落定设定` 哪一层都有**（`/ldsd`，预计 1 次调用，JSON 坏了修一次、最多 2 次）：排细纲、写正文时边聊边把地点、势力、规矩想定了，打 `/落定设定`，它把这段讨论里**已经定下来的设定**写成一批条目（最多 12 条）——新提出来的建新条目，改了已有设定的给出合并后的完整版（讨论没碰的部分照抄，人名不算设定）。和落定细纲一样带上整段讨论（历史预算六成），讨论里提到的已有条目整条带进去（含暗设），好让它合并；没提到的只带一句话。写入前的卡片落在「设定名录」上，列出**会新建**哪几条、**会更新**哪几条，以及**还没定的几个问题**（只给你看，不写进任何文件——接着聊、再落一次就是）。新条目直接建在分类目录里；已有条目一律逐条先给你对比（原来只有一句话的也是），放弃哪一条那一条就原样留着。写进去的算机器写的；更新已有条目时「整合到第几章」不动——这是在原有内容上并进讨论结论，不是整条换新。这一轮跑完回到你原来停着的那一章（那一层）。外部 agent 经 MCP 不能落定（它手上没有你们的讨论）。一句都没聊过、输入框也空着时不调模型。

`/` 在中文正文里是普通字符（日期、比值、网址），所以只有「整个输入框就是一个 `/词`」才当成在下命令——`子时 3/4 刻` 和 `/ 这是一句话` 都不会弹面板。面板里会写文件的命令后面挂一枚「写文件」标签：点它们要花钱，而且会在磁盘上留下东西；`/审稿` 挂的是「只出报告」。命令都可以留空发出——消息气泡里显示的是 `/写细纲` 这样的命令名，不是一片空白。

**直接打字就是讨论。** 没挑命令时，你说的话按当前阶段的「讨论」发出去：想聊、想挑刺、想跟设定对账，直接说。

**多步的活交给外部 agent（MCP）。** 「第 9 章里主角说过他没去过北境吗」「把第 5–8 章写完并定稿」这类要读好几份文件、分几步做完的事，用 Claude Code、Codex 之类的通用 agent 接进来做。独立版启动时会在同一个端口上挂一个 MCP 入口，终端日志里那一行就是接入命令：

```
claude mcp add --transport http novelforge http://127.0.0.1:3000/mcp
```

服务配了访问令牌时（[Docker 部署](#docker-部署放到服务器上远程访问)），接入命令末尾再加 `--header "Authorization: Bearer <令牌>"`。

它拿到的是和对话页同一套工具（读、搜、生成、写、改、工程动作），落在你**最近操作的那个网页窗口开着的工程**上；同时开着几个工程时，可以在地址后面加 `?project=<工程目录>` 把它钉在某一个工程上（如 `http://127.0.0.1:3000/mcp?project=D:/books/北境`），那个工程得在某个窗口里开着。它调 `generate` 产出的正文流进对话页里一个标着 MCP 的气泡，**不回到它那里**；要不要落盘照样在对话页当场问你，你点了才写，它等你答完才继续。改一段文字、装 / 绑写作技能这类没有 diff 可看的动作，动手前也先在对话页问你；覆盖已有内容照旧先让你逐行过目。「下一步该做什么」它从同一个状态机拿结论（附在工具结果末尾）。审稿它不做——在正文层打 `/审稿`。VS Code 插件暂时没有这个入口。

输入框下面还有：**模型**（切换即时生效，预算按新模型的窗口重算）、**思考深度**、**当前章**。目标字数不在这里：只认细纲里的 `targetWords`，没写就取小说配置的每章字数。

**思考深度**有五档：不思考 / 浅思考 / 中思考 / 深思考 / 极限思考。它**跟着这个会话走**，不是一条全局设置——排一份大纲值得让模型想透，改一个错别字不值得，而这两件事往往就是相邻的两个会话。点「新对话」时它跟着继承（多半是换个话题接着做同样难的事），关掉面板再回来还在。

缺省是**不思考**：思考的 token 按输出计费，一句「帮我看看这段」可能因此贵好几倍，所以得你主动选。选了之后模型想的那段过程会流进气泡上方的「思考过程」折叠块——它**不是正文**，采纳写入章节时只取正文。

同一个档位在两家的接口上是两套字段（OpenAI 的 `reasoning.effort`、Anthropic 的 `output_config.effort` 或老模型的思考预算），插件替你映射；某个模型不认最高那一档时会自动降一档重发，而不是给你一句报错。**只有对话页这条路吃这个档位**——工程页的批量任务（批量写章、同步细纲、全文大纲、角色卡、设定）一律不带，不然一次同步七十六章的账单会翻好几倍。

#### 写一章：看得见进度，也看得见问题

写正文时气泡上方有一条进度：「第 2 轮 · 已写 1860 / 目标 3000 字」。一次没写够八成就自动接着写；结尾收得太早（已经收了尾，却还不到八成）时，先把结尾那一截拿掉（按比例切最后约四分之一，最多 600 字）、把这一章还没写足的事件写足，再按细纲约定的结束状态重新收尾——不会往收尾后面硬接。写完的卡片上写明「2980 / 3000 字 · 已达标」或「未写够（不到目标的八成）」，已写的不会丢。

卡片上还会写出这几样，**不拦你，但说清楚**：

- **重演**：开头把上一章最后一场又演了一遍——标红，写出重合的原句，「写入」要点两下。
- **后面几章的人提前登场**：后 5 章细纲里才排的人，在这一章写到了。
- **比喻词超标**：「仿佛」「犹如」「宛如」全章合计超过 3 次。
- **英文缩写**：民国背景里冒出 PTSD 这种词时提醒一句（都市、科幻题材里的 CEO、AI 当然正常）。

写之前还有一次**零调用的一致性预检**：细纲把角色卡「当前状态」里写着已经死了的人排进了这一章，先亮一张卡——「先不写」「仅本次忽略，照写」，或者填一句理由「记为刻意安排，照写」（回忆、幻象、托梦都算），理由记进这一章细纲的 frontmatter（`preflightOk`），以后写这一章不再为这个人亮卡。同一次预检还看叙事线：伏笔过了计划回收章还没收、线断了好几章，本章计划里又没安排的，写进那张卡的说明里（没亮卡时写在写入卡片的说明里）——只提醒，不拦。叙事线只记定稿过的章，前面还有没定稿的章时会注一句「提醒可能不准」。

#### 审稿与修稿

在正文层打 `/审稿`（或独立版章节条上的「审稿」），一次调用出一份报告，不改任何文件：

- **问题**按严重 / 建议分组，每条带一句**逐字引文**——点引文，编辑器里就选中那一句（并把它滚到视口偏上三分之一处）。引文在正文里找不到的条目直接丢掉（模型编的「问题」最容易让你去改一段根本不存在的话），丢了几条写在报告底下。
- **目标核对**：本章细纲的关键事件冻结成一张清单，逐项判「已完成 / 未完成 / 待核实」。判「完成」或「未完成」都得给得出正文里找得到的引文，给不出就降成待核实——「正文里没提」只能是待核实。
- 严重、建议、未完成缺省勾上，待核实缺省不勾。点「编辑」可以改条目、加一条你自己的（「新增问题」）；模型给的不能删，不想修就不勾。

勾好之后点「按勾选的 n 条修稿」：只把勾选的那几条连同整章原文交给模型，要求改动越少越好；被截断时最多续 3 次，改完比原稿短太多就报错、不出卡片（修稿是拿它覆盖一章已经写好的正文，半截比没有更糟）。写入之前先对比：独立版是一张段级合并视图，逐处「采用新版 / 保留原文」，中间的结果可以手改，手改过的那一处不会被「采用」冲掉，顶上写着「已处理 k / n 处」；插件用 VS Code 的 diff 编辑器。

#### 落盘：当场问你一句

产出结构化产物时，**生成一结束就在对话里问你要不要写进工程**——一张卡片，写清落点与分量：

```
🔒 把这份产物写入到「第 12 章《夜入青云》 · 细纲」
   细纲 · 6/7 节
   叙事线计划：林昭与沈青 推进；埋〈玉佩的来历〉（新伏笔，进「未归属的伏笔」）
   [ 写入 ]   不采纳
```

回复本身可以直接点进去改，**改完再点「写入」，落盘的就是你改过的那一版**。目标已经有内容时按钮是 **[覆盖并写入]**，点了还会再让你对比一遍新旧两版。点「不采纳」就一个字都不写，气泡末尾留一行「未采纳」，翻回来看得出这一轮产出过什么、你没要。细纲里排了还没有卡的新角色时，卡片上会列出写入时一并新建哪几张；排了叙事线上的计划时，卡片上列出会写进哪几条线（重拆一章时写明「原来的 N 条整组换掉」），认不出是哪条线的那几条另起一行说没写进去。

**只是讨论的回复不会问**——一段闲聊没有该落的地方；审稿报告也不问，它随会话保存，不写文件。每条回复下面折叠着这次的上下文明细，点开就知道带了什么、丢了什么。明细标题行末尾的 **「复制完整上下文」** 一下就把这一轮发给模型的全部消息（系统提示、带下去的历史、这一轮的话）原样复制出来，拿去别处核对或复现都行；一轮里续写过几次的，复制的是第一次调用那一份。这份消息存在会话文件里，所以长会话的文件会明显变大；这个按钮出现之前的回复只存了清单，没有它。

> 这一问和外部 agent 动手前那一问长得一模一样、在同一个位置：**要动你的磁盘，一律先在对话里问**。

### 引用上下文（Cursor 式）

两种方式往当前这轮对话里塞内容：

- 点输入框下面那颗 **@**（或在输入框直接敲 `@`）——列出所有章节、角色卡、设定条目，也能浏览工作区任意文件。
- 在编辑器里选中一段文字，点输入框下面的 **加入选区**。VS Code 里也可以按 <kbd>Ctrl+Shift+L</kbd>（macOS 为 <kbd>Cmd+Shift+L</kbd>），或右键「将选中文本加入对话上下文」；独立版取的是内置编辑器当前那块编辑区里选中的字（Markdown 预览里不算），没选中时弹一个框让你粘贴一段原文。

引用会以标签形式挂在输入框上方，发送前可以逐个移除。**选区存的是快照**——你选的时候是什么样，历史记录里就一直是什么样，之后改了原文也不会让过去的对话跟着变；整文件引用则每次都读最新的。

### 对话历史

发出第一条消息后自动保存到 `.novelforge/sessions/<id>.json`，跟着工程走，可以提交到 Git。空会话不落盘，历史列表里不会堆一排没说过话的占位。

## 目录结构

初始化后的工作区：

```
chapters/                    正文。**唯一真相**：定稿照它更新细纲，上下文里的前文也从这里取
├── 001-楔子.md               细纲号 = 章号：第 1 章的细纲是 .novelforge/summaries/001-楔子.md
├── 002-客栈里的女人.md
└── 第二卷/                   可以分子目录收纳，随便分几层；章号仍然全书连续
    └── 003-夜访.md
drafts/                      章节草稿，路径镜像 chapters/，按需创建
├── 001-楔子.md
└── 第二卷/
    └── 003-夜访.md
.novelforge/
├── project.json             章节索引（每章的文件、字数与内容指纹）
├── config.md                小说配置：frontmatter 是规模参数与分段格式（`paragraphStyle`），正文八节（一句话 / 核心梗概 / 核心卖点 / 世界观要点 / 金手指 / 主角档案 / 全局要求 / 参考作品）
├── premise.md               故事前提（一句话前提 / 核心冲突链 / 爽点循环 / 悬念骨架）
├── world.md                 世界观（规则与漏洞 / 阶层与资源 / 深层危机）
├── outline.md               情节大纲，按「第 a–b 章：标题」分节，可以只覆盖到一部分章
├── style.md                 文风指南 —— 写正文时必注入
├── threads/                 叙事线（可选）：一条剧情线一个文件（<线名>.md：意图、当前进度、伏笔、进展），
│                            挂不上线的伏笔在「未归属的伏笔.md」；排线时建，定稿时追加事件、更新当前进度
├── skills/<名字>/SKILL.md    本工程的写作技能（可选，手放；见「写作技能」）
├── skills.json              每个阶段绑了哪份写作技能（在设置页「技能」里绑）
├── sensitive.txt            敏感词表（可选）：一行一个词，`词 => 替换词`；只给内置编辑器的写作体检用（见「内置编辑器 → 写作体检」）
├── characters/<名字>.md      角色卡（同样可分子目录，如 characters/主角/林昭.md）
├── lore/<分类>/<条目>.md      设定条目：目录就是分类，每本书自己定、可以嵌套（如 lore/宗门/正道/青云宗.md）；frontmatter 有 keywords、brief（一句话）、updatedThrough（整合到第几章）；正文是概要 / 规则与边界 / 现状三节，可选第四节「暗设」（写正文时不带）
├── summaries/               细纲，一章一份，路径镜像 chapters/（扩展名换成 .md）；定稿照正文更新的也是这一份
│   ├── 001-楔子.md
│   ├── 002-客栈里的女人.md
│   ├── 第二卷/
│   │   └── 003-夜访.md
│   └── global.md            全文大纲（原全书摘要：已经写完的部分主线怎么走过来的；没有数字前缀，不是细纲）
├── sessions/                对话历史，一次会话一个 .json
├── novelforge.db            失败记录与日志历史（SQLite，可随时删，见下）
├── history/                 历史版本：覆盖一份稿子之前存下的旧内容（见「内置编辑器 → 历史版本」）
│   ├── .gitignore           内容是 `*`，Git 默认不收；想收就删掉它
│   ├── chapters/001-楔子.md/                   每份文件一个目录，名字就是那份文件的相对路径
│   │   └── 2026-10-18_14-32-05+0800.txt       每一版一个文件，名字是它被覆盖的时间；最多留 50 版
│   └── .novelforge/summaries/001-楔子.md/     细纲、角色卡这些也一样
└── .trash/                  工程页删掉的东西搬到这里，可手动找回
```

**`chapters/` 是这条链的终点。** 正文直接写进这里，它就是这本书的唯一真相：定稿照它更新细纲，上下文里的前文从它取，工程页那一行的字数也报它。草稿与细纲都跟着章节的路径走：`chapters/第二卷/003-夜访.md` 的草稿在 `drafts/第二卷/003-夜访.md`，细纲在 `.novelforge/summaries/第二卷/003-夜访.md`；在工具里给章节改名、挪进别的子目录时两样都跟着搬——所以起个名字不会让写好的东西凭空消失。

**细纲带 frontmatter，章节不带。** 细纲长这样：

```markdown
---
no: 12
title: 夜入青云
targetWords: 3000           # 没写就取小说配置的每章字数
upstreamHash: …             # 生成时大纲里覆盖这一章那一节的指纹
writtenFrom: …              # 正文据以写成的细纲指纹，正文落盘时记、定稿时刷新
sourceHash: …               # 定稿时正文的指纹，定稿之后才有
cast: [林昭, 沈青(沈姑娘)]    # 定稿时记的实际出场，给出场统计用，定稿之后才有
generatedBy: novel-forge
---
# 第12章 夜入青云
## 梗概          ← 3–5 句：这一章发生什么，因果怎么连
## 出场人物      ← 林昭、沈青
## 时间地点
## 关键事件      ← 一条一件事，按发生顺序，3–6 条、合计 100–300 字；可以写到具体场面，但不写成正文
## 看点          ← 一条一行：读者最爽的那一下，章末吊着读者的东西
## 状态变更
## 连续性事实    ← 计划时空着，定稿时生成
## 设定          ← - 青云宗〔宗门/正道〕：这一章确立的规矩（只是出现就只写名字）
```

**「设定」一节**一行一个东西，`名〔分类〕：这一章新确立的定义或规则`。写之前是这一章打算用到、要引入的设定（排细纲时顺手写上，新引入的会随细纲一起建一条空的设定条目）；定稿时改成正文里实际出现的——名字必须真在正文里、说明要在正文里找得到依据，找不到的说明会清空。设定名录（工程页的出现章、`＋N`、「出现过 · 未建条目」）就是从各章定稿过的这一节里算出来的。它**不进细纲的指纹**：补记、改它都不会让正文挂 ⟳。会变的状态（谁拿走了、毁了没）照旧写在连续性事实里，名录会按条目的名字去那里认。

**写之前是计划，定稿之后是档案。** 拆细纲写出来的是计划：「出场人物」写的是打算让谁登场，只用来挑角色卡、提醒「后几章才登场的人」、做一致性预检，不算进出场统计；「连续性事实」空着——每条事实要挂一句正文里的原话，没有正文就无从挂起。定稿时模型拿着这份细纲与正文，把七节照正文改写一遍，同时记下 `sourceHash` 与 `cast`，从此它就是这一章实际写成的样子（见[定稿后的细纲](#定稿后的细纲)）。

界面上那个 ⟳ 就是靠 `upstreamHash` 与 `writtenFrom` 比对出来的；定稿对不对得上，靠 `sourceHash` 与正文现在的指纹比对。手写的细纲（没有 `upstreamHash` 与 `writtenFrom`）永远不会被标 ⟳。细纲删掉「新增伏笔」那一次（叙事线重做，伏笔并进了叙事线）指纹变了：在那之前写过正文的章会各挂一次 ⟳，重新定稿就消；老细纲里那一节留在文件里，不读。「这一章的正文依据的是哪一版细纲」「定稿时正文是哪一版」都记在细纲这一侧，因为 `chapters/` 下的文件是你的东西——可以是 `.txt`、可以没有扩展名、可以没有 frontmatter，插件写进去的只有正文本身。

老工程直接把已有的章放进 `chapters/` 就行：没有细纲不影响，`chapters/` 里有文件就算写过那一章，可以直接定稿（定稿时照正文整理出一份细纲）、直接进上下文。稿子是一整本 txt 的，用工程页的「导入原稿」切成一章一份；之后「从已写正文补齐」把新链路上缺的东西照正文整理出来（见[拆书](#拆书导入原稿与参考书)）。从前那一套（卷、剧情段、中转站）留在磁盘上的 `volumes/`、`manuscripts/`、`scenes/` 一个字节都不会动，工具只是不再读它们。从前单独放细纲的 `.novelforge/plots/` 也一样：不读、不显示、不删，那里面还没写正文的章要重新拆细纲；`summaries/` 下原有的单章摘要（包括按卷分子目录的）直接当成定稿过的细纲读（见[定稿后的细纲](#定稿后的细纲)）。

**分子目录只是收纳。** 章节的顺序永远由文件名前面的数字决定，跟它在第几层没关系——`第二卷/003-夜访.md` 就是第 3 章。分子目录不重置编号，全书连续编号。细纲跟着正文分：`summaries/` 下的子目录与 `chapters/` 一一对应，文件名前缀仍是章号。

**细纲按相对路径对应正文。** 正文 `chapters/第二卷/003-雪夜.txt` 的细纲就是 `.novelforge/summaries/第二卷/003-雪夜.md`——相对路径相同，扩展名换成 `.md`，和草稿同一套镜像。还没写正文的章只有细纲，按文件名前缀的章号认；照它写正文时，正文落在细纲所在的那个子目录、沿用细纲的文件名（细纲是还没起名的 `030.md` 而标题已经有了，正文就叫 `030-标题.md`，细纲跟着改名）。正文与细纲都还没有的新一章，跟上一章放在同一个子目录。在工具之外直接改了正文的文件名，旧细纲不会被认过来——那算一章新的，旧细纲留在原处。同一个章号有两份正文时（手改文件名撞了号）流水线取路径排序第一份，并在日志里记一条警告。**还没写正文的章只有计划是正常的**——没有正文就无从定稿，工具不会为此催你。

**章节不挑扩展名。** `chapters/` 下凡是「数字前缀 + 不是二进制文件」的都算章节：`001-楔子.md`、`001-楔子.txt`、`001-楔子`（没有扩展名）、`004.json` 都会出现在章节列表上，从别处导入的稿子不用先改名。图片、Office 文档、压缩包、音视频这类打开必然是乱码的会被挡在外面——往 `chapters/` 里丢一张 `001-封面.png` 不会凭空多出「第 1 章」。

只有 `.md` / `.markdown` 的章节会把正文首行的 `# 标题` 当成章节标题（并在注入上下文时剥掉）。其余格式的章节标题一律取自文件名，正文一个字节都不动——`.txt` 里写一行 `# 什么什么` 就只是正文里的一行字。

角色卡与设定条目不跟着放宽，仍然只认 `.md`：那是插件自己的数据格式（frontmatter + 固定小节）。

**`novelforge.db` 是可以删的。** 它只存两样东西：**失败记录**（哪张角色卡/哪一章/哪条设定生成失败了，工程页上那个红色感叹号就是读它）与**日志历史**（让日志页能看到重启之前的记录，超过 30 天自动清理）。你的作品内容一个字都不在里面——正文、细纲、全文大纲、角色卡、设定永远是纯 Markdown。删掉它不会丢任何内容，只是丢掉这些历史痕迹，下次需要时会自动重建。它已经在 `.gitignore` 里（连同 WAL 模式产生的 `-wal` / `-shm` 两个附属文件），不会进版本库。

> 从 0.1.x 升级：元数据目录由 `.novel/` 改名为 `.novelforge/`。插件启动时检测到旧目录会问一次是否重命名，不会静默改动。

### 角色卡格式

```markdown
---
name: 林昭
aliases: [阿昭]        # 纲要里出现别名也能命中
tags: [主角]           # 标 "主角" 的角色始终注入
gender: 男             # 性别；写正文时跟着名字进上下文
firstAppear: 1
lastSeen: 3
appearsIn: [1, 2, 3]   # 出场的章（由定稿过的细纲自动聚合，可手改）
updatedThrough: 3      # 上次更新角色卡时读到第几章
stateThrough: 3        # 「当前状态」更新到第几章（定稿时写）
stateHash: …           # 机器最后一次写「当前状态」时那一节的指纹
---

# 林昭

## 身份
## 外貌
## 性格          ← 最重要，决定模型能不能把这个人写像
## 语言习惯      ← 对保持角色声音最关键
## 人物关系
## 当前状态      ← 由定稿维护；预算不足时优先保留
## 暗设          ← 读者还不知道的事；排大纲、细纲时带，写正文时不带
```

小节名固定。预算紧张时角色卡会降级为只保留「身份 / 当前状态 / 暗设」三节（写正文时没有暗设，就是前两节）。

**「暗设」写这个人读者还不知道的事**——身世、秘密、真实目的，写真相本身，不超过 120 字。它和设定条目的「暗设」是同一个规矩：**定架构、排大纲、拆细纲时整份带**（标着「暗设（读者还不知道）」），**写正文、接着写、重写、审稿时都不带**，正文阶段你 @ 引用这张卡也不带，免得提前说漏；哪一章要揭开，就在那一章细纲的关键事件里写明「揭开：……」。什么时候揭开、在哪埋下铺垫，是叙事线里伏笔的事；暗设只管真相是什么。排叙事线时各人的暗设会交给模型，好据此排伏笔。更新角色卡时，正文里已经揭开的会从暗设里拿掉、写进相应的节。这一节从前叫「未收伏笔」：老卡里的「未收伏笔」不再读，留在文件里，要用就自己挪进「暗设」。

**性别写在 frontmatter 的 `gender` 上。** 名字看不出性别时，写正文的模型只能猜——「陆清河」一猜就是男的。角色图谱在排人的时候就定下每个人的性别，细纲带出的新角色、从正文建卡与更新角色卡也会补上；装配时它跟着名字一起进上下文（`【陆清河（女）】`），预算再紧只带三节也在。卡上已经写了的，机器永远不改；写错了直接改这一行。

`appearsIn` 与 `updatedThrough` 是插件自己维护的两个字段：前者是这个人出场过的章，后者是上次更新角色卡时读到了哪一章（增量更新的起点）。**它们只是缓存**——真正的出场记录始终在定稿过的各章细纲里（frontmatter 的 `cast`），插件每次刷新工程页都从它们重新聚合；还没定稿的细纲里「出场人物」写的是计划，不算。手删掉这两行不会丢数据，只会让下一次「更新角色卡」变成全量重读。

**「当前状态」归定稿维护。** 每定稿一章，就用一次调用把本章出场角色的「当前状态」更新到这一章，记下 `stateThrough` 与这一节的指纹 `stateHash`。下次定稿时如果这一节和 `stateHash` 对不上——说明你手改过——就不写，在那张卡上挂一个黄色 ❗，右键可以对比机器给出的那一版再决定用不用。写下一章时，装配器据此知道角色状态截至第几章（还没定稿的前一章会在明细里说清）。

### 更新角色卡

角色行右键有两个更新入口：

| | 读哪些章 | 什么时候用 |
|---|---|---|
| **更新角色卡（新增 N 章）** | 只读 `updatedThrough` 之后这个人出场的章 | 日常。写了几章之后把新进展补进档案，最省 token |
| **重新通读全部 N 章** | 这个人出场的所有章 | 角色卡被改乱了、或者想彻底重来 |

出场章由定稿过的细纲自动关联，你不用再手输章号——所以**这个功能依赖定稿**：某个角色在定稿过的细纲里一次都没出现，菜单里会直接说「未在定稿中出现，无法自动更新」，先把那几章定稿（或者点工程页顶上黄条里的「立即同步」）即可。

主角可能在几十章里出现，一次装不进上下文窗口。插件会按输入预算把这些章切成若干批，**并在动手前告诉你要调几次模型**：

> 全量重建「林昭」的角色卡：需要通读 34 章，分 4 批，预计调用模型 4 次。现在开始？

后一批看得到前一批已经归纳出的内容，是逐批精炼同一张卡，不是各写各的然后拼起来。分批过程中任务条上有进度，可以随时停止（已归纳的部分不会写坏原卡——最后一步才落盘，且照旧走 diff 确认）。

角色卡会在**每次续写时注入上下文**，所以它必须精炼。更新用的提示词给每一节都定了字数上限，并明确要求优先写好「性格」和「语言习惯」，外貌和人物关系写个梗概就行；「暗设」里已经在正文中揭开的会被拿掉、写进相应的节。反复更新十几次也不会让角色卡膨胀成一篇论文。

## 上下文是怎么装配的

这是插件的核心。**每一层带的东西不一样**——定架构时读三章正文既没用又昂贵，而写正文时前几章是必需的。带多少由[上下文详细度](#上下文详细度)定，下面的章数、字数都是缺省那一级「详细」的值：

| 阶段 | AI 是谁 | 带什么 | 明确不带 |
|---|---|---|---|
| **架构** | 网文策划编辑 | 配置 / 前提 / 世界观、角色图谱一览、已有角色卡 | 正文原文、大纲 |
| **大纲** | 策划编辑 | 架构四件、**按总章数算好章号区间的故事结构指导**、大纲全文、全文大纲、设定一览与更早各章的细纲（没定稿的标「计划」） | 正文原文 |
| **细纲** | 剧情编剧 | 架构四件、**大纲里覆盖这几章的那几节**、前序细纲一览（最近 100 章，一行一章）、前 3 章与后 1 章的细纲、结构指导、设定（分类表与已有条目一览，新章照抄已有的名字）；单章时还有本章细纲 | 正文原文 |
| **正文** | 作者 | **文风指南、全局要求、本章细纲、上一章结尾（不许重演）、后 5 章细纲（不许提前写）、执行卡（放在最后）**；出场角色卡、前提与世界观、大纲里本章那一节、进行中的叙事线；**定稿原文片段**、全文大纲、命中关键词的设定；近 2 章正文；更早各章的细纲（没定稿的标「计划」） | —— |
| **审稿** | 审稿编辑 | **这一章正文全文、本章细纲（关键事件冻结成目标清单）**、后 5 章细纲（标「非既定历史」）；出场角色卡、架构、上一章结尾；前几章定稿留下的连续性事实 | 历史对话、文风 |
| **修稿** | 作者 | **整章原文 + 勾选的审稿意见、文风、全局要求**；本章细纲、出场角色卡、上一章结尾、后 5 章边界；定稿原文片段 | 写一章的那套法则、篇幅合同、执行卡 |

前三层不带正文原文，token 因此降一个数量级。几处刻意的安排：

- **写正文时文风指南与本章细纲永远保证注入**。前者是「读者感觉不到换人执笔」的唯一保障，后者少了的话，模型手上只有文风与前文的尾巴，会自己编一段剧情出来。
- **执行卡放在消息最末**：本章必须写到的事件、哪几个人这一章不出场、比喻词还剩几次——模型对最后读到的东西最听话。
- **定稿原文片段（evidence）**：定稿过的细纲里每条连续性事实挂着一句原文证据，写新一章时拿这句话回到那一章的正文里逐字定位，带所在段落与前后各一段——前 5 章全取，更早的只取提到本章角色的，最多 12 章、6000 字（「精简」不带）。细纲是转述，原文才是事实。只认定稿之后正文没再改过的章：改过的那一章事实不作数，上一章是这样时明细里会写明；你手改过细纲里的事实、证据句在正文里找不到时，退回那条事实的文字，也在明细里写明。
- **进行中的叙事线（threads）**：`threads/` 里还没收束、和本章有关的线，最多 6 条、1200 字，一条一行写这条线现在走到哪、本章计划、没收的伏笔——本章有计划的线排最前，其次是主线、计划收束章就在附近的、最近推进过的；伏笔里本章该收的、已经逾期的排最前，没到回收章的写「第 b 章前不要揭开」，还没到埋的不提。计划中、还没到开始那一章的线不带；状态按「写到这一章时」算，重写前面的章时后面几章才发生的事不算。放不下的在明细里写明。审稿时另带一节「没收的伏笔」，对照着查本章该收的写到没有、没到回收章的有没有提前揭开。拆细纲（生成、讨论、落定）也带叙事线，按这一批的章号区间挑：没收束的线全带（这一批原来有计划的在前，还没到开始那一章的写明不要提前开），没收的伏笔另列，这一批或更早该收的标「本批要收，最晚第 b 章」「已过第 b 章，还没收」排最前；线与伏笔各自按详细度封顶。
- **写作技能**：给这个阶段绑了一份技能的话，它排在消息最前面，作者事实和输出格式都排在它后面、说了算；放不下就整份不带，明细里写明（见下面「写作技能」）。
- **`/落定细纲`、`/落定设定` 时历史对话的预算从三成抬到六成，且提到最高优先级**。这两条命令要沉淀的就是那段讨论，按常规由远及近截掉等于把结论截没了。落定设定时讨论里提到的已有条目整条带，名额放宽到 12 条（一次落定的上限），不受详细度那一档的整条名额限制。
- **设定先排序、再分两种形态带**：几百条设定的书不能命中就整条塞。本章细纲「设定」一节点名的、你这次的话与本章细纲里提到的（接着写时还有本章已写的末尾）**整条带**——一句话、正文，再加上条目整合之后、本章之前定稿里关于它的新内容（条目落后于正文时照样拿得到新的那几句）；前两章定稿里出现过的、以及排大纲细纲时其余的已有条目（按出现章数）**只带一句话**，让模型照抄已有的名字。整条带几条、一句话带几条、一共多少字跟着[上下文详细度](#上下文详细度)走（缺省 6 / 40 / 5000 字），超了的降级或不带都写在明细里。回头重写前面的章、条目又已经整合到后面时，明细里会提醒它可能含之后才发生的事。条目里的「暗设」只在架构、大纲、细纲这几层带（标明读者还不知道）；正文层与接着写时整条只带明面三节，去掉了暗设的在明细里注一句。展开一条设定时另有两样材料：已排细纲里打算用它的地方、定稿里关于它的记录（合计有上限，放不下的写在明细里）。
- **已经写入的产物不随历史再带一遍**：同一个会话跟着主按钮一路走，前面落过盘的配置、大纲、细纲、正文都有专门的层按磁盘带；历史里那一轮跳过，明细里写「已写入 xxx，以磁盘上那一份为准」——落盘之后你手改过的话，历史里的还是旧版。

每一层内部按优先级填预算：

| 层级 | 内容 | 预算不足时 |
|---|---|---|
| **P0** | 系统提示、你这一轮的话、**@ 的引用**、本层产物（正文层：文风、细纲、上一章结尾、后 5 章边界、执行卡） | 永远保留；引用超限时截断 |
| **P1** | **本会话历史对话**、出场角色卡、架构与大纲切片、进行中的叙事线 | 角色卡先降级为「身份+当前状态+暗设」（写正文时只有前两节），其余整块丢弃并标注 |
| **P2** | 定稿原文片段、全文大纲、设定 | 丢弃并标注；设定先降级为一句话 |
| **P3** | 最近 N 章完整正文（默认 2 章） | 降级为该章细纲（没定稿的标「计划」）→ 丢弃 |
| **P4** | 更早各章的细纲（默认最近 60 章；没定稿的标「计划」） | 由近及远填充，填满即止；更早的合成一条「不带」写在明细里 |

预算 = `contextWindow - maxOutputTokens - 512`。完整的配方表见 [src/core/context/README.md](src/core/context/README.md)。

**引用为什么在 P0**：你特意点了它，就不该被自动装配挤掉。但单条封顶预算的 35%，超出从头部截断——@ 一个大文件不能把前文全挤没。

**历史对话怎么带**：作为真正的多轮消息发出（role 交替），不是塞进一段「以下是我们之前的对话」。整体封顶预算的 30%（随上下文详细度，15%–40%）、单轮 12%，由近及远填充；单轮过长时取结尾，因为越靠后越接近当前进度。

**角色卡怎么选**：本章细纲「出场人物」里的（没定稿时是计划出场）→ 你这句话里出现姓名/别名的 → 前两章出场的（读前两章定稿过的细纲的「出场人物」）→ 标签含「主角」的。取并集去重。

### 上下文详细度

设置 → 上下文管理 →「上下文详细度」，四级，**级别越高每次带的前文与设定越多、越贵**。它是全局设置：对话页、工程页批量、外部 Agent 都按它装；改了下一次生成就生效。工程页那些动作动手前的确认框上可以只为这一次换一级，不改这里（见[确认框上临时换模型与详细度](#确认框上临时换模型与详细度)）。**任何一级都不改调用次数**，只改每次带多少。

| 项 | 1 精简 | 2 标准 | **3 详细（默认）** | 4 完整 |
|---|---|---|---|---|
| 写正文时带前几章全文 | 不带 | 1 章 | 2 章 | 3 章 |
| 上一章结尾 | 1000 字 | 1500 字 | 1500 字 | 2000 字 |
| 更早各章的细纲（正文、大纲阶段） | 最近 5 章 | 最近 20 章 | 最近 60 章 | 不限 |
| 定稿原文片段 | 不带 | 6 章内 3000 字 | 12 章内 6000 字 | 20 章内 10000 字 |
| 近几章的连续性事实（细纲、续写、审稿、写前检查） | 6 章 | 8 章 | 12 章 | 20 章 |
| 进行中的叙事线 | 3 条 | 4 条 | 6 条 | 8 条 |
| 拆细纲带的叙事线：线 / 没收的伏笔 | 4 / 6 条 | 6 / 10 条 | 8 / 14 条 | 12 / 20 条 |
| 细纲阶段：前序细纲一览 / 前后几章细纲 | 30 章 / 1+1 | 50 章 / 2+1 | 100 章 / 3+1 | 不限 / 5+2 |
| 对话历史最多占预算 | 15% | 20% | 30% | 40% |
| 角色卡 | 只带身份、当前状态、暗设（写正文时没有暗设） | 整张 | 整张 | 整张 |
| 提取文风 / 提取角色缺省勾几章 | 1 / 1 | 2 / 2 | 2 / 3 | 3 / 5 |
| 参考书学文风抽几章 | 3 | 4 | 5 | 8 |
| 排叙事线带多少大纲；定稿时最多送几条线 / 几条伏笔去认 | 4000 字；6 / 8 条 | 6000 字；9 / 12 条 | 8000 字；12 / 16 条 | 12000 字；16 / 24 条 |

写正文那一次的上下文大致这样涨（128k 窗口、每章约 3000 字的假工程实测，估算 token；真实工程还有设定、文风与叙事线，再多几千；实际计费的 token 多半比估算少三四成）：

| 写到 | 精简 | 标准 | 详细 | 完整 | 这个开关出现之前 |
|---|---|---|---|---|---|
| 第 30 章 | 约 0.9 万 | 约 2.7 万 | 约 3.9 万 | 约 4.4 万 | 约 3.9 万 |
| 第 100 章 | 约 0.75 万 | 约 2.5 万 | 约 6.7 万 | 约 10.5 万 | 约 9.9 万 |

- **「详细」就是这个开关出现之前的样子**，只多一条：更早各章的细纲最多带最近 60 章。从前这一层没有上限，写到七八十章会把整个窗口填满。更早的前情由全文大纲接着。
- **少带的都写在明细里**：「第 1–7 章 · 细纲——上下文详细度「精简」只带最近 5 章的细纲」这样合成一行，不会一章一行刷屏。装配清单的标题行末尾写着这一次按哪一级装的。
- **不随级别变的**：后 5 章细纲（「不许提前写」的边界）、本章已写的末尾、你 @ 的引用、`/落定细纲` `/落定设定` 时的历史（固定六成）；定稿、全文大纲、角色状态、建卡、设定扫描——它们的输入就是那一章本身，或按窗口分批，调低只会截掉要整理的东西。
- 窗口小的模型上「完整」不一定带得更多：历史与近章全文先占了预算，更靠后的层会更早被挤掉，明细里看得到。
- 原来的「注入完整原文章数」「上一章结尾字数」两项并进了这里；配置文件里的旧值不再读，下次保存设置时自动清掉。

**讨论不会顺手改写产物**：直接打字聊（包括让它挑刺、对设定）时系统提示里明写「只回答，不要输出改写后的完整产物」。少了这一条，模型会一边回答一边把整份细纲重写一遍，而界面上那一版是不能采纳的，你只会困惑。

**不静默截断**：任何被降级或丢弃的条目都会留在明细里，标明原因（「预算不足，需 800 token，剩 200」「这一章有正文，但还没有细纲（定稿之后才有）」「历史对话预算已满」）。每条回复下方折叠展示，你随时知道这次没带上什么。

**去重**：如果上一章整章原文能完整放下，P0 那份结尾片段会自动撤掉，同一段文字不会在 prompt 里出现两次。

## 拆书：导入原稿与参考书

借鉴自 [AI-Novel-Writer](https://github.com/EthanYoQ/AI-Novel-Writer)（GPL-3.0）的「小说拆解与仿写」，分两件事：**自己的稿子接上来**，**别人的书学写法**。两件都只读**工程里**的 txt——先把文件放进工程目录（不要放进 `.novelforge/` 这类隐藏目录，也别起数字开头的名字放进 `chapters/`，那会被当成一章）。UTF-8、UTF-16、GBK 都认，一本最大 64 MB。

### 导入原稿

「章节」组右键 **导入原稿（选一本 txt）…**：在本机任意位置挑一本（独立版是网页里的目录选择器，插件是 VS Code 的打开对话框；txt 不必先放进工程），工具按章标题切开，确认框里写清认出几章、导入成第几到第几章、开头几章与最后一章的标题，以及丢掉了什么——第一个章标题之前的书名简介、`第一卷 ……` 这种卷标题、目录里那一串没有正文的标题。**这一步不调模型。**

- 认的章标题：单独一行的 `第一章 雪夜`、`第12章：雪夜`、`第三回 夜奔`、`Chapter 7`，以及序章、楔子、引子、尾声、终章、番外。一个都认不出就不导入。
- 每章新建一个 `chapters/NNN-标题.md`，一段一行、去掉行首空格；**接在已有章节之后**，章号按顺序重编；同名文件已经在就停下，不覆盖。原 txt 不动。
- 切得不对？改 txt 里的章标题再导入一次——切的结果不能在界面上手调。

导入完会问一句要不要接着补齐。

### 从已写正文补齐

已经有正文、却缺架构或大纲没覆盖到它们时，主按钮就是 **从已写正文补齐…**（「故事架构」组右键也有）。它照着第 1 章起连续写好的正文，按链路顺序**只补空白**：

```
细纲（没定稿的、定稿之后正文又改过的）  →  小说配置 → 故事前提 → 角色卡 → 世界观 → 设定条目  →  情节大纲  →  全文大纲
```

- **问两次**：细纲没齐时先只报细纲要调几次（按钮「先整理细纲」）；细纲出来之后再报其余几样——建卡、建设定条目要调几次得看细纲里认出了谁、各出现几章。
- **细纲**就是定稿的第一步：一章一次调用，照正文整理出这一章的细纲（`summaries/` 下与正文同样的相对路径），连同连续性事实、实际出场与这一章出现了哪些设定，这几章随之算定稿过；不更新角色状态，不判叙事线，新整理出来的细纲也不记目标字数。已经有细纲的章拿着它与正文对照着改，旧版先复制一份进 `.novelforge/.trash/`。
- **架构**看全书梗概与均匀抽出的 5 章开头；小说配置没写总章数时问你一句，每章字数取已写各章的平均。
- **角色卡**给定稿过的细纲里出场两章以上、还没有卡的人建，读的是他们出场的那几章正文，「当前状态」写到最后一次出场。
- **设定条目**在还一条都没有时，给定稿过的细纲里出现两章以上（一个都没有就降到一章）的设定各建一条，读的是细纲里提到它们的那几句，不重读正文；这一步没建成不挡后面几样，挂黄 ❗。
- **情节大纲**每次照 20 章定稿过的细纲整理（分节格式与平常一样，每节最多 5 章），只写已经发生的事。
- 细纲之后那几件，已经有的一件不动；一件失败就停，已经写好的留着，失败挂在那一行上。
- **叙事线不排、不补记**：从情节大纲排线、从已写正文补记事件是叙事线重做后面几期的事（四期把这两样接到这里）；眼下可以在工程页「叙事线」页签手动「从大纲排出」。
- 绑在「规划」阶段的写作技能这一次不带：照实整理，不按技能的排法改写已经发生的事。

补完之后主按钮变成「续写情节大纲（第 N+1 章起）」，接下来和新书一样往下走。

### 从参考书学写法

「文风与摘要」组的文风指南那一行 **从参考书学**：挑一本，选学**文风**、**写法**还是两样都学，各 1 次调用（走「提取文风」那一档）。

- **文风** → `style.md`：均匀抽 5 章（随[上下文详细度](#上下文详细度)，3–8 章）各取开头 2500 字，用与「从正文提取文风」同一份提示词（只学技法，不复述情节、人名、地名、专有设定）。`style.md` 已经有内容时，按钮写着「覆盖 style.md 并开始」。
- **写法** → 一份写作技能 `.novelforge/skills/<书名>-写法/SKILL.md`（`stage: planning`）：看开头 3 章与全书 30% 处的连续 3 章（各取开头与结尾），加上程序数出来的篇幅统计，写成章节结构、场景推进、钩子与悬念、节奏与爽点、信息投放、开篇写法、规划时怎么用七节。写完问你要不要绑到「规划」阶段——绑上之后架构、大纲、细纲的每一次生成都带着它。
- **原文不进工程的任何文件**，也不反推它的设定、角色与细纲。

## 写作技能

写作技能是一份**补充的写作方法**：一个目录里一份 `SKILL.md`，开头几行 frontmatter，下面是正文——「每个场景围绕角色的主动选择、选择的代价……」这样的话。给本工程的某个阶段绑上一份，这个阶段往后的**每一次生成**都会把它放在提示词最前面：对话页、外部 agent（MCP）、工程页批量都一样。

```markdown
---
name: scene-craft
display_name: 场面写法
description: 写场面的办法
stage: drafting          # 建议绑在哪个阶段：planning / drafting / review / refinement（只是建议）
---
每一场都要有一个选择……
```

| 阶段 | 什么时候带 |
|---|---|
| **规划** | 架构、大纲、细纲的生成与落定（含补齐架构、批量拆细纲；「从已写正文补齐」不带） |
| **写正文** | 写、接着写、重写，以及自动续写那几轮和删修饰（含批量写章） |
| **审稿** | 审稿 |
| **修稿** | 按勾选的审稿意见修稿 |

讨论、定稿（含同步细纲）、全文大纲、文风提取都不带。每个阶段最多绑一份，同一份可以绑几个阶段；**没绑就什么都不带**，内置的也不会自动绑上。

**它只能补充写法**：消息里它的第一句就是「作者事实和后续输出合同始终优先」，你的设定、细纲、已写的正文和输出格式都比它说了算。**放不下就整份不带**，不截半截——明细里写着需要多少 token、还剩多少。绑着的那份后来找不到了、或者变得不兼容了，生成照常，明细里写明这次没带、为什么。

**三个来源**，都在设置页「技能」里看得到：

| 来源 | 在哪 | 怎么来 |
|---|---|---|
| 内置 | 随应用发布：「长篇连续性与场景推进」「自然语言润色」 | 删不掉 |
| 我的技能库 | `~/.novelforge/skills/<名字>/SKILL.md`，所有工程共用 | 从 GitHub 装，或者自己放一个目录进去 |
| 本工程 | `.novelforge/skills/<名字>/SKILL.md`，跟着这本书走、可以进 Git | 自己放 |

目录名就是技能的名字（可以是中文）。手放进去的，切回「技能」页就会出现。

**从 GitHub 装**：设置页「技能」里贴一个地址（仓库首页、`/tree/分支/目录`、`/blob/分支/…/SKILL.md` 或 raw 地址都行），先点「检查」——只下载来看，不写任何文件——看过正文再点「确认安装」；安装时会重新下载一遍，与刚才看的那一份核对一致才装。**只收自包含的纯提示词**：要跑脚本、装 hook、派子代理、调工具，或者引用旁边别的文件的，一律装不了（这里没有能执行它们的地方，装进来只会让模型以为自己能做一件做不了的事）；超过 64 KiB 的也不收。同名的已经装了就不装，要换新版先卸载旧的。**卸载**把整个目录挪进 `~/.novelforge/.trash/skills/`，不真删。

**外部 agent 也会**：对它说「装一下这个技能，绑到写正文上」，它会先检查、再装、再绑——**安装与绑定每一次都先在对话页问你**；卸载它不会，那由你在设置页做。

这套做法移植自 [AI-Novel-Writer](https://github.com/EthanYoQ/AI-Novel-Writer)（GPL-3.0）的「写作 Skill」。

### 定稿后的细纲

定稿时模型手上有这一章的当前细纲（连续性事实那一节不给）与正文，以正文为准改：一致的保留原措辞，写偏的改成正文写的，没写到的删掉。还没有细纲的章（导入的原稿、手写的正文）照正文从头整理一份。模型输出 JSON、再由插件渲染成 Markdown 写回同一份细纲——你读到、改到的仍然是普通 Markdown：

```markdown
---
no: 2
title: 客栈里的女人
targetWords: 650
upstreamHash: b0eec8f7b4a4a79c
writtenFrom: b582e0a84cbbacdb    # 刷成更新之后的细纲指纹
sourceHash: a26b6dc8fb924aa7     # 定稿时正文的指纹
cast: [林昭, 沈氏(那个女人), 客栈掌柜]   # 机器可读的实际出场
generatedBy: novel-forge
---

# 第2章 客栈里的女人

## 梗概
## 出场人物
## 时间地点
## 关键事件
## 看点
## 状态变更
## 连续性事实
- 林昭左臂被青鳞划伤，未愈 〔证据：「血顺着左臂往下淌，他把袖子扎紧了」〕
- 沈氏知道了玉佩的来历 〔证据：「……」〕
```

七节整体换成新的一版，「设定」一节换成这一次记下的；`no`、`title`、`targetWords`、`upstreamHash` 以及 `status`、`preflightOk`、`factCheckOk` 原样留着。旧版先复制一份进 `.novelforge/.trash/`（同名的加序号，不盖掉更早的那份），改坏了能捞回来。这一步失败（比如模型的回答怎么也解析不出来），细纲一个字都不动，章节那一行挂红 ❗。

`cast` 是给程序用的那一份出场人物：角色页的「出场 N 章」、未建卡人物清单、更新角色卡时自动关联出场章，都读它——只读定稿过的细纲。括号里是这一章对该角色的其它称呼。`## 出场人物` 小节是同一份信息给人看的形态，两者写盘时保持一致。

**看点**是这一章读者最爽、最想往下看的地方（谁被打脸、主角凭什么赢、章末吊着什么）。拆书「从已写正文补齐」时，架构那几件靠逐章的看点提炼卖点与爽点循环，情节大纲每节的「本段看点」也照它整理。

**连续性事实**是后面几章要接得上的事：谁受了什么伤、谁知道了什么、什么东西到了谁手里。每条后面挂一句**原文证据**——不是模型写的，是插件拿这条事实回到正文里按字面相似度找出来的那一句（零模型调用）；找不到证据的事实不写进来。写后面几章时，装配器拿这句证据回到原文取段落（见[上下文是怎么装配的](#上下文是怎么装配的)），而不是信细纲的转述。

老工程 `summaries/` 下的单章摘要本来就是这几节（多出来的「新增伏笔」当认不出的小节，不读）、本来就镜像正文的路径（包括按卷分子目录的，如 `summaries/第二卷/003-夜访.md`），直接当成定稿过的细纲读，不用迁移；frontmatter 里的 `chapter:`（更老的写 `plot:`）不认，章号取文件名前缀。手写的细纲、以及 0.2.x 之前生成的摘要没有 `cast` 字段，插件会从 `## 出场人物` 小节的文字里反解出名字，不会因此在角色页上少人；重新定稿一次就会补上这个字段。

模型没按 JSON 格式回答时（会发生）插件逐层降级：JSON → 认 `## 小节` → 实在不行把全文塞进「梗概」。无论哪一层，这一章的剧情都不会凭空丢掉。

### 定稿对不上：重新定稿

正文写盘 → 重算内容 hash → 与细纲里记录的 `sourceHash` 比对 → 不一致就在工程页把那一章标成 `○`、状态回到「待定稿」，主按钮也会落回「定稿第 N 章」——点它就是重新定稿。在那之前，这一章的连续性事实不进上下文（写紧接着的下一章时明细里会写明），出场统计仍按上一次定稿算。

反过来，定稿之后再改细纲（比如手修了一句关键事件）不算对不上：这一章仍是已定稿，只在正文上挂一个 ⟳，提醒你看看正文要不要跟着改。

细纲**不会自动照正文重新更新**（避免后台偷偷烧 token），但工程页「概览」顶部会提示有几章写了正文还没定稿（或定稿之后正文又改过），一键同步；切到别的页时，活动栏「工程」上会留一个小圆点提醒还有这件事没做。同步只做定稿的第一步——照正文更新细纲、补上连续性事实，旧版照样先进回收站——不更新角色状态、不判叙事线，那两样要逐章「定稿」。各章之间没有先后依赖，所以同步按 [`novel.concurrency`](#默认模型列表并发与-fallback) 并发跑（默认 3 路）。同步过程中任务条上有进度（已完成几章/共几章、已用时、可停止），每一章的成败、耗时与用的哪个模型都记在[日志页](#日志页)里；个别章失败不会中断整批，结束时会点名是哪几章，去日志里能看到具体原因。

### 角色卡不会被静默覆盖

`提取/更新角色卡` 与角色行右键的「更新角色卡」对已存在的角色一律先让你对比确认：插件打开 diff 编辑器，你可以在右侧直接改完再点采纳；独立版是一张只读的对比，采纳或放弃。模型留空的小节保留原文，别名和标签取并集。

批量更新时几张卡是并发分析的，但 **diff 一次只弹一张**，按完成顺序排队——同时弹三个 diff，谁也说不清自己在看哪一张。

不走 diff 的只有两种：**给还没有卡的人物新建角色卡**（包括角色图谱与细纲带出的新角色）——那张卡是刚建的，没有你写过的内容可覆盖；以及**定稿时更新「当前状态」那一节**——只在它自上次机器写入之后没被你改过时才直接写，改过就不写、挂黄 ❗（见[角色卡格式](#角色卡格式)）。

## 配置

设置页（侧边栏 → 设置）分为「模型配置」「上下文管理」「通用」「技能」几个二级页签（「通用」只有独立版有，放「新窗口中打开项目」）。「技能」页管写作技能（见上面「写作技能」），改了当场生效，不用点「保存设置」。模型页管理服务商、模型预算、分档与请求参数；上下文页单独管理[上下文详细度](#上下文详细度)、全文大纲分批和「写完正文删修饰」。API Key 按服务商存在 `~/.novelforge/secrets.json`，不写进配置文件。「模型配置」页里「模型分档 / 任务档位 / 请求与调度」这几块日常不常动的配置收在「高级设置」折叠开关下，展开才能看到。

### 服务商与模型

**两种协议，各认一条路**：`kind: "openai"` 走 OpenAI 的 **Responses 接口**（`/responses`，也就是 Codex 用的那一套），`kind: "anthropic"` 走 Anthropic 的 **Messages 接口**。这是「思考深度」这个开关唯一的落点——老的 `/chat/completions` 里「想多深」不是一个字段。

> **只认 `/chat/completions` 的服务商（DeepSeek、智谱、Kimi、通义、本地 Ollama 等）在 `openai` 这种 kind 下会 404**，报错里会点明这一点。要用它们，得在 `baseUrl` 填一个自己那侧的 `/responses` 兼容网关。

可以同时配置多个服务商，每个服务商下挂多个模型。模型用 **`前缀/模型名`** 引用，前缀就是服务商的 id：

```jsonc
"novel.providers": [
  {
    "id": "glm",                                              // 引用前缀
    "label": "智谱 GLM",
    "kind": "openai",                                         // openai / anthropic / vscode-lm
    "baseUrl": "https://open.bigmodel.cn/api/paas/v4",
    "models": [
      { "name": "glm-4-plus", "contextWindow": 128000 },
      { "name": "glm-4-air" }
    ]
  },
  {
    "id": "openrouter",
    "kind": "openai",
    "baseUrl": "https://openrouter.ai/api/v1",
    "models": [
      { "name": "z-ai/glm-4.6", "contextWindow": 200000 }     // 模型名自带斜杠
    ]
  }
],
"novel.model": "glm/glm-4-plus"
```

于是：

| 引用 | 含义 |
|---|---|
| `glm/glm-4-plus` | 智谱官方的 glm-4-plus |
| `openrouter/z-ai/glm-4.6` | OpenRouter 上的 GLM |
| `ollama/qwen2.5:14b` | 本地 Ollama |

**引用只在第一个斜杠处切分**，后面的都属于模型名——OpenRouter 的模型名本就是 `厂商/型号`，不这样切就没法引用。所以服务商前缀不能含斜杠，设置页会挡住。

同一个模型走不同渠道就是两条独立的引用，各有各的 baseUrl、各有各的 API Key，切换只要在输入框旁的下拉框里选一下（或用命令 `Novel: 选择模型`）。

**窗口与输出上限按模型单独设置**。同一家的 32k 和 200k 模型常常并存，装配器按真正执行任务的模型计算预算，所以切模型或切档位时预算会跟着变。设置页不再提供全局默认预算；模型留空时使用内置兼容值（窗口 128000、输出 4096）。旧配置里已有的 `novel.contextWindow` / `novel.maxOutputTokens` 仍作为兼容兜底读取，但不再作为新配置项展示。

设置页备了 3 个预设（OpenAI / Anthropic / Copilot），点一下**添加一整个服务商**（含常用模型和窗口大小），不会覆盖已有的。只认 `/chat/completions` 的那几家不再列进预设——点了就 404 的按钮比找不到更让人恼火，但手工添加仍然可以（填自己那侧的网关地址）。**协议类型在服务商配置弹窗里可以直接改**（从前只能由预设决定，手工加的服务商永远是 openai），换协议时接口地址会跟着填成对应的默认值。每个模型行右边有「测试」，当场发一个最小请求验证——比写半段才发现 Key 填错强。

API Key 按服务商 id 分开存。本地 Ollama 随便填一个非空值即可；`vscode-lm`（Copilot）不需要 Key，但模型有硬性输入配额，装配器会自动按其 `maxInputTokens` 收紧预算，明细里会标注「已按模型配额压缩」。

### 默认模型列表、并发与 fallback

设置页的「默认模型」是一份**排好序的清单**，不是单选。它管两件事：对话页当前用哪个模型（= 第一项），以及工程页后台任务里**没有配置档位的那些**用哪些模型——同步细纲、重建全文大纲、更新/批量更新角色卡、批量建卡、生成设定、提取文风、提取角色。配了[模型分档](#模型分档简单的活省钱难的活花钱)之后，下面这些规则在**每一档内部**同样成立：

- **串行时**（`novel.concurrency = 1`，或本来就只有一件事要做）恒用第一个模型；报错就在**其余模型里随机挑一个**重试，最多 `novel.fallbackAttempts` 次。同一个模型不会被试两遍，只有一个模型时不重试。
- **并发时**在整份清单里**轮转**取模型，把请求摊到几个服务商上——这往往是并发跑得起来的前提，单个服务商的限流额度撑不住几路并发。
- 用户点「停止」时立刻停，不会换模型重试。
- 备选模型缺 API Key 或当前环境不支持（如独立版里的 Copilot 模型）会被**排除在池外并写进日志**，不会为此连弹几个输入框。只有第一个模型缺 Key 时才会引导录入。

**对话页的单次生成不走这套**：你在输入框旁的下拉框里选了哪个模型，就必须是哪个模型写的正文——中途偷偷换人会让文风断掉。那个下拉框切换模型等于把它**提到列表首位**，所以设置页与对话页看到的「当前模型」始终是同一个。

并发只作用于**彼此无先后依赖**的条目：同步细纲时各章（照正文更新细纲；之后的角色状态与叙事线按章号串行）之间、角色卡之间、全文大纲的各个阶段批次之间。补齐架构、批量拆细纲、批量写章一律串行——后一件要吃前一件的产出。同一张角色卡内部的分批仍然严格按顺序来（后一批要看到前一批的产出）；批量更新角色卡选「逐张确认」时，分析照样并发，但 diff 会按完成顺序**一张一张弹出**。

并发不改变总调用次数，确认框里报的「预计调用模型 N 次」在并发下依然准确；但它更容易撞上服务商的限流（429），配了多个模型时 fallback 正好接住这种情况。

> 从 0.1.x 升级：旧的 `novel.provider` / `novel.openai.*` / `novel.anthropic.*` / `novel.vscodeLm.family` 仍然生效——`novel.providers` 为空时会自动按它们生成一份服务商列表（前缀分别是 `openai` / `anthropic` / `copilot`），旧的 API Key 也会迁到新键上，不用重新输。在设置页保存一次即转为新结构。

### 模型分档：简单的活省钱，难的活花钱

工程页那几件事的难度差得很远。「照 76 章正文各更新一遍细纲」是 76 次调用，每次只看一章和它的细纲、输出固定结构；「把几十份阶段摘要合并成一份全文大纲」全书只调一次，却要跨几十万字取舍主线。用同一个模型干这两件事，你只能在「贵而好」和「省而糙」之间二选一。

所以设置页把模型分成**三档**，每档各是一份有序清单（用法和「默认模型」完全一样，可排序、可多填几个做 fallback）：

| 档位 | 放什么模型 | 内置默认包含的任务 |
|---|---|---|
| **快速档** | 便宜、快的模型 | 定稿 · 照正文更新细纲、全文大纲 · 分批汇总、设定 · 记设定 |
| **均衡档** | 折中的模型 | 设定 · 建条目与整合、角色卡 · 更新 / 建卡、剧情细纲、批量写正文、批量审稿 |
| **精标档** | 最聪明的模型 | 故事架构、全文大纲 · 最终合并、提取角色、提取文风 |

归档的判据是「调用次数 × 单次难度」：次数多而单次简单的归快速档；一次定调、错了代价大的归精标档（故事架构全书只跑一次，后面每一章都吃它；提取角色决定「谁是谁」，判错会污染整个角色体系；文风指南和角色卡每次写正文都要注入上下文，写砸了会一路影响下去）。

剧情细纲值得单说：它每批 5 章一次调用，量不算大，但**决定这几章讲什么、怎么转，写歪了那几章的正文整篇跟着歪**，而正文是最贵的一项——这一格省下来的钱会在下一格翻倍还回去，所以归均衡档而不是快速档。

**批量写正文**也在均衡档：它是量最大也最贵的一项，但正文的文风与语气直接决定成品质量，压到快速档等于用便宜模型写整本书。归均衡是折中——真要省钱或真要质量，改一格就行，默认值不该替你做这个取舍。

设置页的「任务档位」表里每项都是一个下拉框，不认同哪条默认改掉即可，标「默认」的就是内置推荐值。

几条要点：

- **不配就是不分档。** 某一档留空，归在该档的任务就沿用「默认模型」；三档都不配，行为和没有这个功能时**完全一样**。不会有任务被偷偷降级到便宜模型。
- **换模型只在档内。** 快速档的模型失败了，只在快速档里换人，绝不会自动升级到精标档——否则你以为在省钱，账单却按贵的算。
- **每档按自己的窗口切批。** 分批读正文时用的是**这一档首选模型**的上下文窗口，不是对话页那个模型的。所以快速档放 32k 的小模型也安全，不会因为你在对话页选了 200k 的模型就把一大堆正文硬塞进去。
- **确认框会说清这次用谁。** 动手前的弹窗里，模型下拉框选着「按分档」时下面写着「定稿 · 照正文更新细纲 → 快速档：glm/glm-4-air」，档位没配时会明说「未配置，沿用默认模型」。也可以在那里只为这一次换一个模型，见下一节。
- **叙事线跟着它最像的那一档走**：「从大纲排出」走剧情细纲档（与拆细纲同一种活）；批量定稿（「立即同步」、批量写章「写完即定稿」）里认事件、更新当前进度、归并那几次走「定稿 · 照正文更新细纲」档（与更新细纲同一种活）。单章定稿用的是你在对话页选的那个模型。
- **对话页的单次生成不受影响**，永远用你在输入框旁选的那个模型。外部 agent 经 MCP 生成架构与细纲时不一样：它们走「故事架构」「剧情细纲」两档，与工程页补齐架构、批量拆细纲是同一个模型；正文与大纲仍用你选的那个。工程页「待完善」的「全部展开」（以及拆细纲顺带展开）也走「故事架构」档——展开是创作，与设定清单同一种活。

一个典型配法：快速档放 `glm/glm-4-air` 或 `deepseek/deepseek-chat`，精标档放你写正文用的那个好模型，均衡档留空（自动沿用默认模型）。一部几十万字的书跑一轮全量同步细纲，光这一项就能省下大头。

### 确认框上临时换模型与详细度

工程页那些要调模型的动作（补齐架构、拆细纲、批量写章、排叙事线、立即同步、更新 / 建角色卡、建 / 整合 / 展开设定、记设定、从已写正文补齐、学写法……），动手前那个报调用次数的确认框上多两个下拉框；「批量拆细纲…」「批量写章…」两张表单末尾也有：

- **模型**：缺省「按分档」——每项活照「任务档位」走，下拉框下面一项一行写着交给谁；也可以挑一个具体的模型（与对话页下拉框同一份清单），**这一次的每次调用都只用它，失败也不换人**（与对话页同一条规矩）。
- **上下文详细度**：缺省是设置页那一级。只有这一次的上下文看它时才有这个下拉框——建卡、整合设定、记设定、全文大纲这些的输入就是那一章本身或按窗口分批，跟详细度无关，就不给你一个调了也白调的开关。从参考书学写法、提取文风也没有：抽哪几章在确认框之前就定了。

几条要点：

- **只管这一次**：不改设置，下次打开还是「按分档」与设置页那一级。
- **接着问的那一句跟着这一次**：拆完展开本批新设定、批量写章开跑前要补建角色卡、重建全文大纲选了「先同步细纲」、从已写正文补齐的第二步——这些后面再弹的确认框，缺省就是你刚才挑的。
- **调用次数不重算**：确认框上那个数是按「按分档」时那个模型的窗口估的，换了窗口小的模型可能多切几批，估计本来也只是估计。
- **VS Code 里**原生对话框放不了下拉框：多一颗「换模型 / 详细度…」，点了依次挑模型与级别，选完回到确认框，补充说明末尾写着「这一次：……」。
- 外部 Agent 经 MCP 调批量动作时，弹给你的也是这个确认框，你在这里挑的就是它这一次用的。

### 代码结构

核心与壳分离：`src/core/` 零 vscode 依赖，三个壳并排放在 `src/shells/`，各实现一个 `Host` 窄接口。
壳只做三件事——实现 `Host`、传输与生命周期、平台专属入口；业务逻辑、页面内容、以及
「我是哪个壳」的分支都不属于壳（契约见 [src/shells/README.md](src/shells/README.md)）。

```
src/
├── core/                  ★ 宿主无关核心（永不 import vscode）
│   ├── host.ts            Host 窄接口（弹窗/进度/监听/打开文件），双壳各实现一份
│   ├── controller/        ★ ChatController：面板逻辑，经 ViewHost 与视图解耦
│   ├── protocol/          前后端消息协议（+ 独立版 prompt/promptResult、编辑器消息）
│   ├── config.ts          readConfig/updateSettings，数据源由 ConfigStore 注入
│   ├── stores.ts          FileConfigStore/FileSecretStore（~/.novelforge/）
│   ├── actions.ts         初始化工程、新建细纲、新建章节等工程级流程
│   ├── choices.ts         「让用户挑一个」的清单构造（角色卡 / 章节）
│   ├── watchPolicy.ts     哪些文件改动值得刷新界面（策略在这里，机制在壳里）
│   ├── model/             ★ 纯领域模型：流水线状态机、细纲 / 架构 / 大纲格式、审稿报告、预检、段级 diff、会话……
│   ├── workspace/         ★ 工程的唯一读写网关：路径 → 种类 → 守卫 → 渲染 / 记账 / 伴生
│   ├── files/             类文件操作、@ 引用候选、内置编辑器读写、「文件」页的目录列举
│   ├── views/             只读聚合与界面快照：工程页、单章流水线、出场人物索引、「转到…」的索引、名词补全的名词表
│   ├── context/           tokenizer + 分阶段预算装配 + 提示词
│   ├── generation/        创作的一次单步与几条链：续写、审稿、修稿、结构化产物的修复；落盘分派

│   ├── skills/            写作技能：内置 / 我的技能库 / 本工程三个来源、从 GitHub 先检查再安装、阶段绑定
│   ├── tools/             工具层（读三件 + generate + 写三件），不认识 mcp/
│   ├── mcp/               把工具经 MCP 端给外部 agent（协议 + HTTP 传输）
│   ├── llm/               provider / openai / anthropic / registry / 模型池（vscode-lm 经工厂钩子）
│   └── runtime/           日志、工程库（失败记录 + 日志历史）、长任务、有界并发
└── shells/                三个壳

    │   ├── migrate.ts         settings.json/SecretStorage → ~/.novelforge 一次性迁移
    │   ├── webviewHtml.ts     页面模板（纯函数，不碰 vscode API）
    │   ├── webview.ts         webview 接线：localResourceRoots 与 asWebviewUri
    │   └── vscodeLmProvider.ts、chatViewProvider.ts、chatPanel.ts
    ├── standalone/        独立壳（Bun）
    │   ├── main.ts / cli.ts   入口与参数解析（目录可空）
    │   ├── server.ts          Bun.serve：静态页 + /ws WebSocket
    │   ├── workspaceHub.ts    同时开几个工程，每个窗口各绑一个
    │   ├── windowState.ts     ~/.novelforge/window.json
    │   ├── hostFs.ts          本机列目录（打开文件夹用，不进 core）
```

面板逻辑集中在 `core/controller/`，两个视图宿主（侧边栏 / 编辑器）与独立版 WebSocket 各自只负责收发消息，因此同一个会话能在多处同时打开且保持同步。

界面不使用 VS Code 自带的 TreeView 等控件，全部由 webview 渲染：一套 UI 同时供侧边栏和编辑器标签页使用，工程页与对话页共享同一个 tabbar，不再上下分栏。`projectView.ts` 只产出一份可序列化快照（任意深度的 `ProjectNode` 目录树），展开/折叠状态留在前端。

关于 token 计数：默认实现是按字符类别加权的粗估（中文 ×1.5、拉丁 ÷4），没有引入 tiktoken——体积大、要 wasm，且各家分词器本就不同，粗估只要保证不低估，加上 512 的安全余量就够用。

但计数本身是**可替换**的：`context/tokenCounter.ts` 定义了 `TokenCounter` 接口与一张注册表，想接 tiktoken 或某家服务商的 count_tokens 接口，写一个实现注册进去、切过去即可，装配器一行都不用改。切换失败（加载不了词表之类）会退回默认实现并返回 false——数不了 token 不该把写作流程带停。

服务商返回真实用量时（OpenAI 的 `stream_options.include_usage`、Anthropic 的 `message_start` / `message_delta`）插件会记下「估算 / 实测」的比值，写进日志里供你判断这个数字靠不靠谱。这份统计**不会反过来自动修正估算值**：估算必须是纯函数，否则同一份上下文两次装配会得出不同的预算判断，上下文明细也就不可复现了。
