## 现状

细纲有「时间地点」一节（`plotFile.ts:104`），拆细纲时模型写「本章的时间点（与上一章的相对关系亦可）」（`context/prompts.ts:1228`），
定稿照正文改写时同样写一句（`summarizePrompt.ts:17`）。写出来的都是「第 2 章当夜三更」「次日清晨」这样的相对说法，**没有人把它们
累加成日期**：看不出故事里过了多久，写到第 80 章时模型也不知道现在是哪一天，季节、「三天后」很容易前后打架。

## 总览

```
同步第 N 章 ── 认事件那一次（+0 次）顺带报：本章比上一章晚几天、跨了几天、时段、原文依据
                 │
                 ▼
 threads/时间线.md：一章一行「第 N 章：+2 天，清晨〔依据：「两日后的清晨」〕」（机器只写相对的「+N 天」）
                 │  作者把哪一行改成具体日期（「八月十五」「第 200 天」），哪一行就是锚点，后面的跟着顺延
                 ▼
 model/timelineFile.ts 现算（不落盘）：每章开头是第几天 → 按历法换成日期
                 │
   ┌─────────────┼────────────────────┬──────────────────────────┐
   ▼             ▼                    ▼                          ▼
工程页叙事线页签   叙事线总览              写正文 / 拆细纲的上下文         从正文补推（已判过叙事线、
「时间线」一行     「故事时间」一行与月份带   「上一章结束于三月十四傍晚」    还没有时间的章；几章 1 次）
```

- **机器只写相对量，日期一律现算**：文件里机器写的是「比上一章晚几天」，日期在显示时从第 1 章往后累加出来。这样作者定死第 12 章是
  八月十五，第 13 章往后机器推的日期**自动跟着挪**，不用机器回头改一串行。
- **状态不落盘**（第 18 条）：每章是第几天、推不出的有几章、还没推的有几章，都从这份文件与章节现算。

## 数据格式：`.novelforge/threads/时间线.md`

```markdown
---
calendar: 简单历
start: 大衍三年三月初七
generatedBy: novel-forge
---

# 时间线

> 一章一行，写的是这一章开头比上一章结尾晚多久。日期在叙事线页签和总览里看（按 start 往后推算）。
> 要定死哪一章，把「+N 天」改成具体日期（如「八月十五」）或「第 N 天」；你改过的行机器不再动，后面的章跟着顺延。

- 第 1 章：+0 天，傍晚〔依据：「连日大雨的第三天傍晚」〕
- 第 2 章：+0 天，夜里〔依据：「当晚」所在的那一句〕
- 第 4 章：+1 天，清晨，历时 2 天〔依据：「次日清晨，雨停了」〕
- 第 7 章：回忆，约二十年前〔依据：「那是二十年前的冬天」〕
- 第 9 章：+?〔推不出：正文没交代过了多久〕
- 第 10 章：+0 天，上午〔推测：紧接上一章的审讯〕
- 第 12 章：八月十五，傍晚
- 第 13 章：+3 个月
```

### frontmatter

| 键 | 值 | 缺席 |
|---|---|---|
| `calendar` | `简单历` / `公历` | 简单历 |
| `start` | 第 1 天是哪天：`大衍三年三月初七`、`三月初七`、`2026-03-07`、`2026年3月7日` | 只显示「第几天」 |

- frontmatter 的键只认英文（`model/markdown.ts`），值可以是中文。行内不写 `#` 注释（解析器不剥），说明放在正文开头的引用块里，解析时忽略。
- **简单历**：每月 30 天、一年 12 个月。起点认「[年号][N 年]M 月[D 日]」：年号、年、日都可以缺（缺日当初一）；数字认阿拉伯数字与
  汉字（「十四」「廿一」「初七」「正月」「腊月」「冬月」）。输出照起点的写法：起点写「三月初七」就出「三月十四」「次年三月十四」，
  写「3月7日」就出「3月14日」，有年号就带年号、年份往上加。
- **公历**：真实的月份长短与闰年。起点认 `2026-03-07`、`2026年3月7日`、`2026/3/7`；输出照起点的写法。
- 起点认不出：照「没填」处理（只显示第几天），工程页那一行说一句「起点认不出」。

### 一行的写法

`第 N 章：值[，时段][，历时 M 天][〔依据：「原文」〕 | 〔推测：理由〕 | 〔推不出：理由〕]`，项目符号与线的「进展」同一套认法。

| 值 | 意思 | 谁写 |
|---|---|---|
| `+N 天`（`-N 天`、`+N 周`、`+N 个月`、`+N 年`、`+半个月`；汉字数字也认） | 本章开头比上一章结尾晚多久。月按 30 天，年按历法（简单历 360 天、公历 365 天） | 机器写天，作者也可以写 |
| `同日` / `当天` / `次日` / `第二天` / `翌日` | 等于 `+0 天` / `+1 天` | 作者 |
| `+?` | 推不出：按「紧接上一章」（`+0 天`）算，界面上标出来等作者补 | 机器 |
| `回忆[，约二十年前]` | 整章是回忆或倒叙：不推进时间，下一章接着上一章算 | 机器、作者 |
| 一个日期（`八月十五`、`大衍四年正月初一`、`2026-08-15`） | **锚点**：这一章开头就是这一天。没写年份的，取上一章结尾当天或之后最近的那一个 | 作者 |
| `第 N 天` | 锚点：这一章开头是故事第 N 天 | 作者 |

- **时段**只认一个短词（凌晨 / 清晨 / 早上 / 上午 / 中午 / 午后 / 下午 / 傍晚 / 黄昏 / 夜里 / 晚上 / 深夜 / 半夜 及「三更」这类），
  只显示。**历时**缺席是 1 天（同一天里写完）。
- **认不出的行**（值认不出、日期在没填起点时写了月日）：原样留着、不当这一章的时间（第 1 条），算法上按「这一章没推」处理，工程页说
  「几行认不出」。

### 推算（现算，`computeTimeline`）

从第 1 章往后走到文件里出现过的最大章号：

```
上一章结尾 E（第 1 章之前当 0）
第 N 章：
  没有这一行      → 开头 = E（按紧接上一章算），标「没推」
  回忆            → 不改 E，这一章标「回忆」
  锚点（日期/第几天）→ 开头 = 那一天
  第 1 章的相对值  → 开头 = 第 1 天（差值不算：第 1 章就是起点）
  +N              → 开头 = E + N
  +?              → 开头 = E，标「推不出」
  结尾 = 开头 + 历时 − 1；E = 结尾
```

一章的状态：有依据（实心）/ 推测（淡）/ 推不出（黄）/ 没推（灰虚）/ 锚点（作者定的）/ 回忆 / 认不出。「故事里过了几天」= 最后一章的结尾。

## 谁能写什么

| 内容 | 谁写 | 怎么写 |
|---|---|---|
| 这份文件 | 同步、补推 | 第一次要写时按模板新建（只追加：新文件） |
| 第 N 章那一行 | 同步第 N 章、补推 | **只填空**：没有这一行就按章号插到对的位置 |
| | | ⚑ 已有这一行时**只在两种情况下换**：值还是 `+?`、标着〔推不出〕（作者没动过）；或者〔依据〕里那句原文已经不在正文里了（正文改过，旧版先存历史，同叙事线「证据不在正文里的机器事件」） |
| | | 其余一律不动：作者写的锚点、作者改过的值、〔推测〕的行、〔依据〕还在正文里的行 |
| frontmatter、引用块、作者写的任何行 | 作者 | 机器一个字不动 |

- ⚑ **没有指纹**：一行一章、几百上千章，逐行记指纹太重；改用上面「只填空」的规矩——机器从不改写一行已有、还站得住的记录。要机器重推
  哪一章，删掉那一行再同步（或补推）。代价：正文改了、〔依据〕那句还在、时间却变了的，旧记录留着（保守，宁可不改）。
- ⚑ **日期不写进文件**：文件里只有相对量与锚点，日期在叙事线页签、总览、上下文里现算。写进去的话，作者改一个锚点，后面几百行的日期
  就全是旧的，机器还得分清「哪一个是作者改的、哪一个是没刷新的」。文件开头的引用块说清这一点。

## 一、同步时推（认事件那一次，+0 次）

- **输入**多一段「【上一章的时间】」：`第 11 章：三月十四 傍晚（故事第 8 天，历时 1 天）〔依据：「…」〕`；上一章没有记录写「上一章的
  时间还没记，按正文判这一章比上一章晚几天」；第 1 章写「这是第 1 章，days 写 0」。按「写到第 N 章时」算（只看第 N 章之前的行）。
- **输出**多一个字段（`THREAD_FIND_SYSTEM`）：

  ```json
  "time": { "days": 1, "span": 1, "part": "清晨", "flashback": "", "evidence": "次日清晨，雨停了", "reason": "" }
  ```

  - `days`：本章开头比上一章结尾晚几天，同一天 0、第二天 1，往回跳写负数；正文没交代、也看不出写 `null`；
  - `span`：本章从头到尾跨了几天（同一天里是 1）；
  - `part`：本章开头的时段，看不出不写；
  - `flashback`：整章是回忆或倒叙时写大约多久以前（「约二十年前」），否则空；
  - `evidence`：正文里交代时间的那一句，逐字；没有这样一句（靠场面接续判的）就空着、在 `reason` 里写为什么这么判（≤30 字）。
- **校验**（`verifyTime`）：`days` 是整数、绝对值不超过 3650 万天（约十万年，修仙够用）；`span` 是 1 起的整数（同上限），缺了当 1；
  证据照事件的口径逐字校验，找不到就在正文里找最接近的一句（`nearestSentence`），还找不到就丢掉证据、改记〔推测：依据在正文里找不到〕。
  `days` 是 `null` → `+?`〔推不出：reason 或「正文没交代过了多久」〕；有 `flashback` → `回忆，…`。模型根本没给 `time`：**不写这一行**、
  记一笔日志（之后补推能补上）。
- **写盘**：在认事件落盘之后、当前进度之前（与推水位同一处），按上表「只填空」写这一行。写不进去只记日志、不算认事件失败。
- **完成提示**跟在叙事线那一句后面：「时间：第 12 章 +2 天（依据「两日后」）」、「时间推不出（按紧接上一章算，可以在时间线里补）」、
  「时间：第 12 章的时间你定过，没改」。
- 从已写正文补记（`threadsBackfill.ts`）走的是同一个 `recordThreads`，补记的章顺带也有时间。

## 二、从正文补推（叙事线判过、还没有时间的章）

本稿之前就判过叙事线的章（水位以内的、`threadsJudged` 里的）不会再走认事件，它们的时间要另补。

- **入口**：工程页「叙事线」页签「时间线」那一行有「⚠ 第 3–30 章还没推」时，标题旁给「补推时间」（右键标题、那一行也有）；补推在跑时不给。
- **范围**：⚑ 定稿过、正文没再改过、**叙事线判过**、时间线里还没有这一行的章。叙事线还没判的章不归它管——「从正文补记」会一起推时间，
  省得同一章花两次钱；它们在那一行里说「叙事线补记时会一起推」。
- **一次几章**：⚑ 按章号串行，一次最多 5 章，放不下就少放（每章正文放不下截尾，证据仍对整章校验）。输入是这几章的正文与「这一批之前
  那一章的时间」，输出 `{"times":[{"chapter":12, …同上}]}`。后一批要看前一批的结果（上一章的时间），所以串行。
- **次数**：⌈章数 / 5⌉ 次左右（按字数切批，确认框写明上限），「定稿」档（`plotSummary`），经 `askCall`，先存一个存档点。
- **失败**：一批没成就停（同补记 ⚑10），已写的留着，失败挂在时间线文件上（红 ❗），再点一次从那一章接着补。
- ⚑ **不给外部 agent**：这是一次性的补课，补记（`extract threadsFromText`）已经顺带推时间。以后要再加。

## 三、用在哪

### 叙事线总览

- **表头多一条月份带**（有起点时）：同卷名那一行的画法，连着几章在同一个月就并成一段「大衍三年三月」；跨年、跨月处断开。
- **线的上面多一行「故事时间」**：每章一格，写这一章开头是几号（简单历「十四」、公历「14」、没起点「46」）；和上一章同一天的画一个点，
  推不出的标黄「?」，没推的灰、回忆的写「忆」。悬停看全文：`第 12 章 · 三月十四 清晨 · 故事第 8 天 · 上一章后 +2 天 · 历时 3 天`，
  依据 / 推测 / 推不出的理由。**点格子打开 `时间线.md`**（这一行是拿来改时间的；点章号照旧打开那一章）。
- 线与伏笔格子的悬停，标题后面带上那一章的日期；伏笔名的悬停多一句「埋下至今 46 天」（还没收的，按叙事线判到的那一章算）。

### 写正文、拆细纲的上下文

- `threads` 层（P1）多一个条目「故事时间」（id `timeline:<路径>`），**单独成一节**放在叙事线那一节前面：
  - 写第 N 章：`上一章（第 11 章）结束于大衍三年三月十四傍晚（故事第 8 天）。本章的时间要接得上；细纲「时间地点」写了的照它。`
  - 拆第 a–b 章：`已写到第 11 章，结束于大衍三年三月十四傍晚（故事第 8 天）。细纲「时间地点」写清本章比上一章晚多久。`
- 按「写到第 N 章时」算（只看第 N 章之前的行）：重写前面的章不带后面的时间。没有时间线、或第 N 章之前一行都没有：不出。
- 一行几十个字，不占叙事线的条数与字数（不和线抢名额），明细里照常列出、可以取消勾选。审稿、续写、修稿不带。
