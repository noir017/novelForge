## 为什么推不准（v0.2.6 的代码）

1. 认事件只送本章正文与一句「上一章是哪天」（`features/threads.ts` 的 `recordThreads`）：上一章停在哪个时刻模型看不到，结尾时段也没记。
2. `time` 排在事件、新线、新伏笔后面，是捎带的一个字段。
3. 提示词写「不要算日期」：正文明写的「八月十五」「除夕」「入冬」都丢了；天数一路累加，没有校准点，一处判错后面全歪，也没人发现。
4. 章内跨了几天让模型估一个 `span`；补推只送每章前 1.2 万字，后半章的「三日后」看不到。
5. 机器只填空，推错了只能手删行；补推只管叙事线判过的章；界面上只是「叙事线」组里的第一行。

## 一、文件格式（老写法照认）

一行多三样，都可以没有：**结尾时段**、**文中日期**、**季节**。

```markdown
- 第 1 章：+0 天，傍晚 → 深夜〔依据：「连日大雨的第三天傍晚」〕
- 第 4 章：+1 天，清晨 → 夜里，历时 3 天〔依据：「次日清晨，雨停了」〕〔文中：八月十五（中秋），开头后 2 天「今夜便是中秋」〕
- 第 9 章：+30 天〔依据：「一月后」〕〔季节：冬「北风卷着碎雪」〕
```

值仍然不能缺（`第 10 章：→ 夜里` 照旧算「认不出」）。

- **时段**一格写成 `开头 → 结尾`（`->` 也认）；只知道结尾写 `→ 夜里`。结尾时段只显示，也交给下一章判「当晚」「次日」用。
- **〔文中：日期[（节日）][，开头后 K 天]「原文」〕**：正文明写本章某一天是几月几日（或某个节日）。`开头后 K 天` 缺席是 0（就是本章
  开头那一天）。日期的写法同锚点（`八月十五`、`大衍四年正月初一`、`2026-08-15`）。
- **〔季节：春 / 夏 / 秋 / 冬「原文」〕**：正文明写或明摆着的季节，只拿来对账，不改日期。
- 行尾几段从后往前认，先后不限；`〔依据〕〔推测〕〔推不出〕` 仍是那一行「谁写的」的记号（上一稿 ⚑11）。

## 二、推算（`computeTimeline`）

上一稿的走法不变，多一步**按正文写明的日期对齐**：

```
第 N 章（不是回忆）：
  先照上一稿算出开头 A（锚点就是那一天；+N 是上一章结尾 + N；+? / 没有这一行 是上一章结尾）
  有〔文中〕、填了起点、这一行不是你写的锚点：
      M = 文中那一天里离 A + K 最近的那一个（没写年份的，取前后一年里最近的）− K
      开头 = M；偏差 = M − A（记下来，对账要用）
  有〔文中〕、这一行是你写的锚点：不对齐，两边对不上的话对账里说一句
```

- ⚑1 **没写年份的文中日期取「离推算最近」的那一个**，不取「之后最近」：累加推多了几天时，「之后最近」会把它推到明年。作者写的锚点
  照旧取上一章结尾当天或之后最近的那一个（上一稿 ⚑10）。
- ⚑2 **`+?` 遇上文中日期就不算推不出**：日期是正文给的，状态记「正文写明」；这种章的偏差是预料之中的（`+?` 本来就按 +0 算），对账不报。
- **一章的状态**多一种「正文写明」（`dated`）：开头是照文中日期对齐的。
- **起点建议**：没填起点、正文里出现过文中日期时，按第一次出现的那一处倒推第 1 章是哪天（「第 3 章写了『三月初七』→ 第 1 章是三月初五」），
  工程页一键填上。填了起点，文中日期才对得齐（没起点不知道「第 46 天」是几月）。

### 对账（现算，0 次，只提醒不拦）

| 一类 | 什么时候报 |
|---|---|
| 文中日期对不上 | 对齐时偏差 ≥ 2 天（⚑3：差 1 天多半是「深夜算不算第二天」，只在悬停里说）；说清「前面推下来是七月廿一，正文写八月十五，已按正文对齐」 |
| 你定的和正文对不上 | 作者锚点那一章的〔文中〕日期和锚点不是同一天 |
| 季节对不上 | 这一章开头到结尾没有一天落在那个季节（前后各宽一个月）里。简单历按农历口径（正月到三月是春），公历按 3–5 月是春 |
| 往回跳 | 机器写的 `-N 天`、又没标回忆 |
| 连着推不出 | 连着 3 章以上 `+?` |

节日换日期（⚑4）只在简单历里做，按农历口径：元日（春节）正月初一、元宵正月十五、上巳三月初三、端午五月初五、七夕七月初七、中元七月十五、
中秋八月十五、重阳九月初九、腊八腊月初八、小年腊月廿三、除夕腊月三十。公历只认元旦、国庆、圣诞、平安夜这几个公历节日；农历节日在公历里
换不出日子，不当校准点。清明、冬至这类节气年年漂，不换。

## 三、认时间：同步时单独一次

`updateStateAndThreads` 在叙事线那一步之后加一步「故事时间」（`features/storyTime.ts`），**和叙事线各算各的**：认事件没成不挡它，它没成也不挡叙事线，
没成挂黄 ❗ 在章节上（op `timeline`）。模型用「定稿」档，同叙事线那一步。

### 输入

```
【历法与起点】简单历（每月 30 天、一年 12 个月）；第 1 章开头是大衍三年三月初七。      （没填：没填起点，只按天数算）
【前面几章的时间】（程序按时间线推算的，帮你接上）
第 8 章：三月十二 清晨 → 夜里（故事第 6 天）
第 9 章：同一天 → 深夜
第 10 章：+?（推不出，按紧接上一章算）
第 11 章：三月十四 傍晚（故事第 8 天）
【第 11 章的结尾】（上一章最后约 1000 字：本章开头接着哪个时刻，看这里）
……
【第 12 章 标题】
（细纲记的时间地点：次日清晨，青崖镇）
正文（太长的截中间，留头留尾）
请给第 12 章判一次时间，按要求输出 JSON。
```

- 「前面几章的时间」最多 5 章，按「写到第 N 章时」算（只看第 N 章之前的行）。第 1 章写「这是第 1 章，days 写 0」。
- ⚑5 **细纲的「时间地点」也送**：同步第一步刚照正文改过它，模型自己写的那句时间常常就是答案；标明「只当提示」。
- ⚑6 **正文截中间、留头尾**（一章最多 1.2 万字：前 8000、后 4000）：时间的线索在开头（晚了多久）和结尾（停在哪），中间最不要紧。

### 输出（补推、重推几章一批用同一份，`times` 一章一项）

```json
{ "times": [ {
  "chapter": 12,
  "days": 1, "part": "清晨", "evidence": "次日清晨，雨停了", "reason": "",
  "jumps": [ { "days": 2, "evidence": "两日后的夜里" } ],
  "endPart": "夜里",
  "flashback": "",
  "date": { "date": "八月十五", "festival": "中秋", "offset": 2, "evidence": "今夜便是中秋" },
  "season": { "season": "秋", "evidence": "满院桂花开了" }
} ] }
```

- `jumps`：本章里往后跳的每一处，按先后；同一天里换场景不算。**历时由程序加**（1 + 各处天数），不让模型估。
- `date`：正文明写的才写；`offset` 是那一天在本章开头之后第几天（开头当天 0）。**不许从起点自己算日期。**
- 其余（`days` 判不出写 null、`flashback`、证据逐字）同上一稿。

### 校验（`verifyTime`）

- `jumps` 每一项天数是 0 起的整数、证据逐字（找不到换最接近的原句，还找不到这一跳不算、记日志）。老的 `span` 照收（没给 `jumps` 时）。
- `date`：证据要在正文里，**而且证据里要写着这个日期或这个节日**（防编）；日期认不出、节日换不出日期的不收。`offset` 夹在 0 到历时 − 1。
- `season`：春夏秋冬之一（「春天」「冬季」也认），证据要在正文里。

### 写盘（谁能写什么）

| 情况 | 同步 | 补推 | 重推 |
|---|---|---|---|
| 没有这一章的行 | 写 | 写 | 写 |
| 机器写的行（带〔依据〕〔推测〕，或 `+?` 带〔推不出〕） | **换** | 只换 `+?`、依据已经不在正文里的 | **换** |
| 你写的行（日期、「第 N 天」、没有行尾那一段的、改过值却还挂着〔推不出〕的） | 不动 | 不动 | 不动 |

- ⚑7 **同步时机器写的行一律照新推的换**（上一稿是只填空）：同步就是「照正文重新整理这一章」，认时间现在是单独、带足上下文的一次，
  新的比旧的可信；你写的照旧一个字不动。改过值又留着〔依据〕〔推测〕的行分不出是你改的——想保住就删掉行尾那一段，或者在界面上改
  （界面上改的不带那一段）。时间线文件开头的说明写清这一句。
- 写之前那一刻重读（`updateThread`），覆盖前存历史版本（网关照旧）。

### 完成提示

同步的完成提示里，时间那一句从叙事线后面挪到自己的一句：「时间：+2 天（依据「两日后」）」「时间：正文写明八月十五」「时间推不出（按紧接上一章算，
可以在时间线里改）」「时间线里这一章是你定的，没改」。

## 四、补推与重推

- **补推**（上一稿就有）：范围改成「同步过、正文没再改过、时间线里还没有这一行（或还是机器写的 `+?`）」的章，**不再要求叙事线判过**。
- **重推**（新）：同步过、正文没再改过、这一行不是你写的章。三个入口：组标题旁「重推」（全部）、右键一章「从这一章起重推」、「重推这一章」。
  确认框写明章数、会换掉几行机器写的、你写的几行不动、调用次数；开跑前存存档点（同补推）。
- 都是按章号串行、几章一批（一批最多 5 章、合计 2.4 万字），每批带「前面几章的时间」与上一章的结尾；一批没成就停（同上一稿）。
- 「从正文补记叙事线」只补叙事线，不再推时间（作者定的第 4 条）；它的完成提示里那一句「推了 N 章的故事时间」删掉。
- ⚑8 **不给外部 agent**（同上一稿 ⚑7）：MCP 的同步本来就会推；补推、重推是工程页上的维护动作。

## 五、工程页：叙事线页签里单独一组「时间线」

叙事线页签分两组，「时间线」在上、「叙事线」在下；「叙事线」组里那一行时间线去掉。

```
▾ 时间线  推到第 30 章 · 故事第 46 天（大衍三年四月十九 夜里）      [补推时间] [重推] [总览]
   ◷ 简单历 · 起点 大衍三年三月初七（第 1 章那一天）                          ← 点了改起点与历法
   ⚠ 第 12 章：前面推下来是七月廿一，正文写八月十五（差 24 天），已按正文对齐   ← 对账，一条一行，点了打开那一章的那一行
   ⚠ 第 9–11 章连着推不出
   ▸ 大衍三年三月 · 第 1–12 章 · 14 天
   ▾ 大衍三年四月 · 第 13–30 章 · 32 天
      ● 第 13 章 夜袭 · 初一 清晨 → 夜里 · +2 天 · 依据「两日后的清晨」
      ◆ 第 14 章 中秋 · 十五 · 正文写明「今夜便是中秋」
      ? 第 15 章 · +? 推不出
```

- **组标题**：推到第几章、故事第几天（现在是哪天、结尾时段）。旁边：「补推时间」（有还没推的章时）、「重推」（有机器写的行时）、「总览」；
  补推 / 重推失败的红 ❗ 也在这里。没填起点时「故事第 46 天」，后面不带日期。
- **第一行：历法与起点**。点了弹两问：历法（简单历 / 公历）、起点（第 1 章那一天，可以空）；只改 frontmatter 的这两个键。没填起点、正文出现
  过文中日期时，这一行说「第 3 章写了『三月初七』，第 1 章是三月初五」，右键「填为起点」。
- **对账一条一行**（⚠），点了打开时间线文件。还没推、推不出、认不出的计数也放这里（同上一稿那几个 ⚠）。
- **章按月分段**（填了起点；回忆的章跟着前一章的月）、没起点按卷分段、卷也没有就每 20 章一段。段头写这一段是哪个月、哪几章、几天，
  点了折叠。⚑9 **最后一段默认展开，其余默认收起**（几百章一下摊开没法看；折叠状态同别的组，只在前端）。
- **一章一行**：状态点（● 有依据、○ 推测、? 推不出、· 没推、◆ 正文写明、★ 你定的、↺ 回忆、✕ 认不出）、章号与标题、那一天（开头 → 结尾时段）、
  比上一章 +几天、依据 / 理由。悬停看全文。
  - 点一行打开那一章的正文（⚑10：这一组是一章一行，点章就是看章；改时间走右键）。**同日作者推翻**：「找时间线难道要回头看每一章正文」——
    点一章改成打开时间线总览、展开这一章，打开正文挪到右键；第一行「历法与起点」也去掉了（点了就弹设置，反人类），见
    [2026-10-24-timeline-page.md](2026-10-24-timeline-page.md)。
  - 右键：**改时间…**（输入框，写法同文件：`八月十五` / `第 N 天` / `+3 天` / `回忆`；清空就是删掉这一行，留给机器重推）、**重推这一章**、
    **从这一章起重推**、打开时间线、打开正文。
  - 改时间写下的是你定的：不带行尾那一段，时段、历时、文中、季节照留（⚑11：值是你的，原来机器认出来的时段与正文写明的日期还有用）。
- 文件不在、也没有要补推的章：整组不画（同上一稿）。

**叙事线总览**：「故事时间」那一行挪进自己的一组「时间线」（排在主线组前面，组名后写「故事第 46 天」）；对账报了的章，格子标红、悬停说为什么；
「正文写明」的格子画成实心。

## 六、写正文、拆细纲带的「故事时间」

一句扩成几行（只看第 N 章之前的行，单独成一节，不占叙事线名额，同上一稿）：

```
上一章（第 11 章）：大衍三年三月十四 傍晚 → 深夜（故事第 8 天）。眼下是春天。
最近几章：第 8 章 三月十二；第 9 章 同一天；第 10 章 推不出；第 11 章 三月十四（+2 天）。
本章的时间要接得上；本章细纲「时间地点」写了的照它。
```

拆细纲那一句同样带上「眼下是什么季节」，要求「时间地点」写清比上一章晚多久。没填起点时不说季节（不知道）。

## 调用次数

| 动作 | 次数 |
|---|---|
| 同步一章 | **2–5 → 3–6**（故事时间单独 1 次） |
| 从正文补记叙事线 | 不变（每章 1–3），不再推时间 |
| 补推 / 重推 | 每批 1 次（一批最多 5 章），确认框写明 |
| 改时间、改起点、工程页、总览、对账、写正文 / 拆细纲 | 0 |

## 规则的改动（AGENTS.md）

- **第 28 条**时间线那一句改成：机器写相对量（`+N 天`）、时段、历时，正文明写的日期与季节记在行尾（〔文中〕〔季节〕）；同步与重推时机器写的
  行照新推的换，补推只填空；作者写的日期、「第 N 天」、没有行尾那一段的行是作者的，机器不动；推算时作者的 > 正文写明的 > 累加的。
- 开头「往回记住」那一段：定稿的几步里，叙事线与故事时间分成两样。
- 存档点的清单（`features/checkpoint.ts` 顶上那一段的「十处」）补上「补推 / 重推故事时间」：上一稿的补推就存了，清单漏写。
