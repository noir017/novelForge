# Novel Forge

**把一个脑洞养成一本完整的书。**

从一句「如果……」开始，先把它展开成小说配置、故事前提、角色图谱与世界观，再排出情节大纲、拆成一章一份的细纲，最后一章一章写成正文。每一层的产物都摊在屏幕上，可编辑、可重写，**确认后才落盘**——AI 负责把上一层展开成下一层，拍板的始终是你。

写长篇卡住的地方通常不是写不出字，而是**越写越记不住自己写过什么**：小说越写越长，模型窗口装不下全文，续写时人物走形、伏笔丢失、文风漂移。所以这里同时做两件事：**往下展开**（把一个念头逐层填成成品）与**往回记住**（把已经写下的东西压成模型每次都带得动的记忆）。

具体是三件事：

1. **逐层展开** —— 一句话 → 故事架构（配置 / 前提 / 角色图谱 / 世界观）→ 情节大纲 → 细纲（一章一份）→ 正文。每一层都可以停下来讨论、重做，写到一半发现前面不成立，回上一层改了再往下走。正文按细纲的目标字数自动续写，写完还可以审稿、按审稿意见修稿。
2. **按创作阶段装配上下文** —— 定架构、排大纲、拆细纲、写正文是四件不同的活，需要的东西完全不同。工具按你当前在哪一层，只装那一层用得上的东西，并把装了什么、没装什么明明白白列给你看。
3. **整合总结** —— 每写完一章就「定稿」：生成单章摘要与连续性事实（每条事实挂一句原文作证据），把出场角色的「当前状态」更新到这一章，并记下这一章推进了哪几条叙事线（跨章的伏笔与线索）；再加上全书摘要、角色卡与设定整合，让「记忆」始终有限且可人工校正。

所有数据都是工作区里的普通 Markdown，可以 Git 版本管理，可以直接用编辑器改，程序挂了数据也还在。

三种用法共用同一套核心：浏览器里的[独立 Web 版](#独立-web-版不装-vs-code-也能用)、双击就开的[桌面 App](#桌面-app-windows--linux)、以及 [VS Code 插件](#快速开始)。

### 从脑洞到成书

```
一句话  →  故事架构  →  情节大纲  →  细纲  →  正文  →  定稿
如果……    配置 前提     第 1–20 章    一章一份   自动续写    摘要 + 连续性事实
          角色 世界观   第 21–40 章…  每批 5 章  到八成      + 角色当前状态
```

**跟着主按钮走就行。** 对话页输入框上方永远只有一个主按钮，写着这本书现在该做的那一步：没有配置时是「生成小说配置」（弹出一个小表单，写下你的脑洞、总章数和每章字数），接着依次是故事前提、角色图谱、世界观，然后是「生成情节大纲（第 1–20 章）」「拆细纲（第 1–5 章）」，再往后就是「写第 1 章」「定稿第 1 章」「写第 2 章细纲」……每一步要调几次模型写在按钮旁边，点之前就知道。

**为什么先定架构。** 直接从一句话写正文，模型手上只有那句话，写到第三章人物就开始走形。所以先把这句话展开成几份短文档：配置（类型、结构、视角、规模与「全局要求」）、前提（核心冲突与悬念骨架）、角色图谱（主角、盟友与对手各一张卡）、世界观（规则、阶层、深层危机）。它们几百字到一两千字，后面每一章都带着它们写。

**大纲按章号区间分段写。** 一次写一百章的大纲，后半段会稀得像目录；所以大纲按「第 a–b 章：标题」分节，总章数超过 20 时先写前 20 章，写到哪里不够了，主按钮会变成「续写情节大纲」。六种故事结构（三幕、英雄之旅、节拍表、起承转合、多线、自由）都按总章数算好了章号区间。

**细纲号就是章号。** 细纲一章一份（`plots/012-夜入青云.md` 就是第 12 章），三节：本章目的、关键事件、章末钩子。关键事件写到具体场面——落在哪几个场面上、谁对谁做了什么——但不写成正文；章末钩子必填，每一章都要留一个让人翻下一页的东西。从大纲拆细纲每批 5 章，一批里前后有因果，又不至于长到后几章潦草。细纲里排了新角色，写入时一并建卡。

**正文直接写进 `chapters/`，写够了才停。** 写第 N 章时，模型手上有这一章的细纲、上一章结尾（并被要求不许重演）、后 5 章的细纲（被要求不许提前写）、出场角色卡、前几章定稿时留下的原文片段。一次没写够目标字数的八成，就自动接着写（最多再续 7 轮）；结尾收得太早时先退回到收尾那一段之前再续，免得越过章末钩子。最后仍不够的，已写的照样留着，卡片上写明「未写够」。

**定稿是唯一要你点头的闸口。** 写完一章不会自动定稿：主按钮变成「定稿第 N 章」，点了才生成摘要、连续性事实，更新出场角色的「当前状态」，并记下这一章推进了哪几条叙事线。后面几百章靠它们记住这里发生过什么。

**跨章的伏笔记在叙事线里（可选）。** 拆出细纲之后，工程页「文风与摘要」组的「叙事线」一行可以**从细纲排出** 3–8 条跨章的伏笔与线索（1 次调用），写进 `.novelforge/threads.md`：每条写着类型、计划在第几章埋下、第几章前回收、意图。之后每定稿一章，就判一次这一章推进了哪几条（埋下 / 推进 / 回收 / 放弃），证据要在正文里逐字找得到才记，只往那条线的末尾追加一行。写正文时挑最多 6 条和本章有关、还没收的线带上，并写明「没到回收章的线不许提前揭开」。这份文件随你改，工具只追加、不改你写的字。

每一层都可以**讨论**（直接打字就行——想挑刺、想对设定，说出来就是；AI 不动你的文件），也可以**生成**、**落定**（细纲层：把刚才讨论出的结论整理成细纲）。正文层另有**审稿**：逐条引原文挑出问题、逐项核对细纲里的关键事件，只出报告；你勾选之后，按勾选的条目修稿。

各层产物串成一条**指纹链**：改了大纲的某一节，那一节覆盖的几章细纲挂一个 ⟳；改了某一章的细纲，那一章的正文挂 ⟳；改了正文，摘要过期。已经定稿的章不会被拉回「待写」——那是你认可过的文字，工具只挂一个 ⟳ 提醒，不催你重写。这件事**零模型调用、零 token**——它只是比对 hash。

老工程（从前的卷、剧情段、中转站那一套）磁盘上的 `volumes/`、`manuscripts/`、`scenes/` 一个字节都不会动——那是你的文件；工具只是不再读它们。已有的 `chapters/` 照常是章节。

**已经写了一部分？** 把整本 txt 放进工程，「导入原稿」切成一章一份；主按钮随后变成「从已写正文补齐…」，照着写好的正文把摘要、角色卡、架构、大纲与细纲整理出来，再接着往下写。想学别人的书怎么写，就把那本书放进来「从参考书学写法」。见[拆书：导入原稿与参考书](#拆书导入原稿与参考书)。

## 快速开始

```bash
git clone <this-repo> && cd novel-forge
npm install
npm run compile
```

在 VS Code 里打开本仓库，按 `F5` 启动 Extension Development Host（会自动打开 `sample-novel/` 示例工程）。

用在自己的小说上：

1. 打开一个空文件夹作为工作区
2. 命令面板 → `Novel: 初始化小说工程`
3. 点活动栏的 Novel Forge 图标 → 「设置」页点一个预设添加服务商 → 填 API Key → 点该模型的「测试」
4. 回到「对话」页，在下拉框里选模型（想让它多想一会儿就顺手调一下旁边的「思考深度」），然后跟着主按钮走：第一步「生成小说配置」会弹出一个小表单，写下你的脑洞即可

## 独立 Web 版（不装 VS Code 也能用）

同一套核心逻辑另有一个独立壳：在本机起一个 Web 服务，浏览器里操作，写作仍在你自己的编辑器里完成。

```bash
# 方式一：源码直接跑（需要 Bun）
npm run standalone                                   # 空窗口；上次没关文件夹则恢复
npm run standalone -- sample-novel                   # 打开该目录
npm run standalone -- sample-novel --no-open --port 4000
npm run standalone -- sample-novel --verbose         # 终端也打调试级日志
npm run standalone -- init [目录]                    # 终端交互式初始化（缺省才是当前目录）

# 方式二：编译成单文件可执行
npm run dist                                   # 产出 dist/novelforge（当前平台）
./dist/novelforge                              # 空窗口
./dist/novelforge sample-novel

# 方式三：npm 包
npm i -g novel-forge && novelforge             # 空窗口
novelforge sample-novel                        # 打开该目录
```

服务只绑定 `127.0.0.1`，无鉴权——设计上只服务本机作者。WebSocket 额外校验 `Origin`（只认本机同端口），挡住恶意网页跨源写入。配置与 API Key 存在 `~/.novelforge/config.json` / `secrets.json`（不再用 VS Code 的 settings.json / SecretStorage；插件壳首次激活时会把旧配置一次性迁移过去）。

独立版是一个 VS Code 式的工作台：左边活动栏切「对话 / 工程 / 文件 / 历史 / 日志 / 设置」，右边是**内置文件编辑器**，中间的分隔条可拖拽（双击复位）。深浅主题用标题栏右上角的按钮切换，选择记在浏览器里。不带目录启动时是空窗口（Get Started + 文件 / 编辑 / 帮助）；文件 → 打开文件夹在同一进程里开工程，不必重启服务。**每个浏览器窗口各开一个工程**，几个工程可以同时开着、互不干扰：设置 → 通用 →「新窗口中打开项目」（默认开）开着时，在已经开着工程的窗口里再打开别的工程会开一个新窗口，关掉则换掉当前窗口里的那个。窗口的网址上带着 `?project=<工程目录>`，刷新、收藏都回到这个工程；标签页、展开的目录、输入框里没发出去的草稿也按工程分开记。上次关窗口时工程还开着，下次会恢复；先「关闭文件夹」再退出则仍进空窗口。记忆在 `~/.novelforge/window.json`。

### 文件（资源管理器）

活动栏第三个页签，独立版专属——插件形态里这件事由 VS Code 自己的资源管理器承担。

它列的是**工程目录的原样结构**，与「工程」页那个整理过的视图不同：这里一个文件都不藏，**包括 `.novelforge/` 这类点开头的文件夹**。摘要（`summaries/`）、会话记录（`sessions/`）、`project.json`、`style.md` 都在里面——想手改它们，这里是唯一入口。

- 点文件夹展开/折叠，按需加载（几百章的工程不会一进来就扫全盘）；展开状态记在浏览器里，刷新后还在
- 点文本文件在右侧编辑器打开；图片、压缩包这类打不开的文件名字置灰，点了交系统默认程序
- 编辑器里当前编辑的那个文件在树上高亮，工具栏的 ◎ 可以定位到它
- 右键：展开/折叠、在系统中打开、复制相对路径

这一页**只看不改**：新建、改名、删除仍然在「工程」页做（那里的操作锁在章节/角色/设定三个区内，删除也是搬进回收站而非真删）。

### 内置编辑器

在「工程」页点任意章节、角色卡、设定条目，或在「文件」页点任意文本文件，即可在右侧打开；产物落盘后也会自动打开写入的那一章。

- 多标签页，未保存的标签带圆点标记
- `Ctrl`/`Cmd` + `S` 保存，「还原」丢弃修改重新读盘
- 底部状态栏显示字数、字符数、行列位置与保存状态
- Markdown 可切「预览」；frontmatter 单独框出，不混进正文
- 刷新页面不丢未保存的草稿（存在浏览器本地，磁盘内容变过则丢弃并提示）
- 关闭有未保存修改的标签、或带未保存内容离开页面，都会先问一句
- 打开的是章节正文时，工具栏多一个「草稿」按钮——点它在右边再开一块编辑区，草稿与正文并排（见 [章节草稿](#章节草稿)）
- 打开的是一章的正文或细纲时，编辑区上方多一条**章节条**：这一章写了多少、走到哪一步，以及「写这一章 / 接着写 / 重写 / 审稿 / 定稿」几颗按钮（按这一章的状态亮哪几颗，说明里写着调用次数）和「并排看细纲 / 并排看正文」

**两块编辑区**：主区放正文，草稿区在它右边，各有自己的标签条、工具栏与状态栏，中间的分隔条同样可拖拽、双击复位。`Ctrl`+`S` 保存的是**有焦点的那一块**。草稿区里关掉最后一个标签就整块收起。同一个文件不会同时出现在两块里——从另一块打开时会连同未保存内容一起搬过去。窄屏（≤900px）放不下并列，草稿区自动隐藏。

**不静默覆盖**：保存带内容 hash 乐观锁。如果文件在你编辑期间被别处改过（你在真编辑器里改了、或插件写入了内容），保存会被拒绝并给出取舍——「用磁盘版本覆盖编辑器」或「用编辑器内容强制保存」，绝不悄悄盖掉任何一边。

进内置编辑器的条件：在工程目录内、不超过 2 MB，且是纯文本——扩展名在 `.md` / `.markdown` / `.txt` / `.json` / `.yml` / `.yaml` 里，**或者**它本身就是一份章节（数字前缀 + 非二进制扩展名，所以 `001-楔子` 这种无扩展名的章节也打得开）。其余仍交系统默认程序；工具栏上的「外部打开」可随时切到你自己的编辑器。

与插件版的差异：

| 能力 | 插件 | 独立版 |
|---|---|---|
| 加入选区 | 读编辑器选区 | 弹粘贴框 |
| 覆盖前对比 | diff 编辑器，可在右侧直接改 | 段级合并视图：正文与修稿逐处「采用新版 / 保留原文」，结果可手改；角色卡、设定只读对比 |
| 打开文件 | VS Code 文档 | 内置编辑器（非文本回落系统默认程序） |
| 打开草稿 | 开在正文旁边一栏（`ViewColumn.Beside`） | 右边第二块编辑区 |
| 浏览工程目录 | VS Code 的资源管理器 | 侧栏「文件」页（含点开头的文件夹） |
| vscode-lm（Copilot） | 支持 | 隐藏（无 Copilot 授权） |
| 弹窗（输入/确认/选择） | 原生对话框 | 网页 modal（WebSocket 往返） |
| 主题 | 跟随 VS Code | 页内切换深/浅 |

断线时页面顶部出现红色重连条，恢复后自动重放全量状态。

## 桌面 App（Windows / Linux）

不想开终端、不想面对浏览器地址栏的话，还有一个桌面壳：双击图标就是一个普通桌面应用。
不带工程也能启动（空窗口 Get Started）；上次关窗口时工程还开着则恢复。打开/关闭文件夹
走页面里的 File 菜单，不重启窗口、不杀 sidecar。

```bash
npm run app:dev      # 开发运行（需要 Rust 工具链）
npm run app:build    # 出安装包（Linux: AppImage / deb，Windows: NSIS）
```

它是**一层纯壳**：里面装的就是上面那个独立 Web 版的单文件可执行，壳负责把它悄悄起起来、
把窗口导航过去、退出时收掉。所以界面、功能、数据落点与独立 Web 版**完全一致**——
文件仍是工作区里的普通 Markdown，仍然可以用你自己的编辑器改、用 Git 管。

换工程用标题栏「文件 → 打开文件夹…」。服务起不来时闪屏给出原因和「查看日志」
（壳看到的进程输出在 `<应用日志目录>/sidecar.log`，与网页里那个「日志」页不是一回事）。

Windows 安装包必须在 Windows 上构建（sidecar 能交叉编译，Tauri 的 Rust 壳不能），
见 [.github/workflows/app.yml](.github/workflows/app.yml)。细节与已知坑见
[src/shells/desktop/README.md](src/shells/desktop/README.md)。

## 界面

活动栏里只有一个侧边栏视图，全部内容都在这个 webview 里，顶部 tabbar 切五页：

| 页签 | 内容 |
|---|---|
| **对话** | 跟着主按钮一步步写：选层 → 生成 → 流式预览 → 就地编辑 → 当场点头才落盘。直接打字是讨论，`/` 挑其它命令；也是外部 agent（MCP）落盘前问你的地方 |
| **工程** | 故事架构 / 章节 / 角色 / 设定 / 文风与摘要，以及补齐设定、拆细纲、批量写章这几个批量入口 |
| **历史** | 本工程的所有会话，可打开、重命名、删除 |
| **日志** | 运行日志：每一次模型调用、每一章摘要、每一次文件操作都留痕 |
| **设置** | 服务商与模型清单、API Key、上下文预算 |

正在跑的长任务（批量写章、定稿、同步摘要……）显示在页签上面的**任务条**里，五个页签都看得见，见[任务条](#任务条)。

侧边栏太窄时，点右上角 ⧉ 可以把同一个面板作为标签页在编辑器区打开——两边是同一个会话，内容实时同步。

（[独立 Web 版](#独立-web-版不装-vs-code-也能用)在「工程」后面多一个「文件」页，即工程目录的资源管理器；插件形态里这件事由 VS Code 自己的资源管理器承担。）

### 工程页

顶上一行工具栏：**补齐设定**、**拆细纲…**、**批量写章…**，以及「＋ 新建细纲 / 角色卡 / 设定 / 文件夹」。下面是五个可折叠分组（「出场人物 · 未建卡」只在确有其人时出现）。行上只有内容——图标、名字、字数与状态——**操作都在右键菜单里**，和文件管理器一样；例外只有「去生成」「去写这一章」两颗按钮，全页各只有一颗。

- **故事架构** —— 五行：小说配置、故事前提、角色图谱、世界观、情节大纲，行首圆点说填过没有（`●` 填过、`○` 待生成），组标题写着填了几件（`4/5`），情节大纲那一行写着覆盖到第几章。**第一件还没填的那一行在行尾有一颗「去生成」**：小说配置那一行打开一句话表单，其余几行把对话页切到那一层（主按钮就是生成它）。点名字在编辑器里打开那份文件；角色图谱没有自己的文件，点它进入那一层，角色卡在下面「角色」那一组。分组标题右键有「从一句话生成小说配置…」「补齐设定（只补空白）」与「从已写正文补齐…」。
- **章节** —— **一个章号一行**，细纲与正文是同一行的两面：`第12章 夜入青云　待写正文　2980 / 3000`。
  - 行首圆点说定稿没有（`●` 已定稿、`○` 待定稿或摘要过期、`·` 还没写正文）；状态徽章说这一章该做哪一步（待写细纲 / 待写正文 / 待定稿，已完成的不挂）；字数写成「写了多少 / 目标多少」，后面的「· 草稿」表示有草稿；细纲或大纲在正文之后改过时挂一个 ⟳。
  - **下一个该写的章在行尾有一颗「去写这一章」**——全书只有这一行有。点了把对话页切到这一章当前该做的那一步；真正花钱的那一下仍是对话页的主按钮。
  - 点名字**打开这一章**：正文在主编辑区，细纲并排在旁边（独立版是两块编辑区，插件用 `ViewColumn.Beside`）。右键有「打开正文 / 打开细纲 / 进入这一章 / 细纲 · 正文（各带完成度，点了直接切到那一层）/ 定稿 / 看摘要 / 草稿」，以及重命名与删除。**没有「移动到…」**：顺序由章号决定。
  - **鼠标悬停在行上会浮出这一章的摘要**：悬停约半秒后出现，按小节分块；摘要过期会标「已过期」，没有摘要时说明原因（还没定稿，或者还没写正文）。**鼠标可以移到浮窗上去**——那样它会一直留着，长摘要可以滚动，也能选中复制；移开才收。浮窗始终夹在窗口内，屏幕矮时自动翻到行的上方或压低高度改用滚动。
  - 在**分组标题**上右键有「新建细纲（接在最后一章之后）」「新建章节文件（直接粘正文用）」「导入原稿（选一本 txt）…」与两条批量动作「批量拆细纲…」「批量写章…」。
  - 分组还空着、或者下一章还没有细纲时，组里写着「下一步：……」——就是对话页主按钮那一句——旁边一颗按钮直接可点（打开一句话或拆细纲的表单，或者把对话页切到那一层）。
- **角色** —— 副标题除标签别名外，还给出「状态截至第 K 章」（定稿时把「当前状态」更新到了哪一章）。这个人在摘要里出场了几章写在后面（「出场 12 章」），上次更新角色卡之后又出场了几章，会以 `＋N` 标在行尾。右键除「打开」与三个类文件操作外，多两项：**更新角色卡**（只读新增的那几章）与**重新通读全部 N 章**，详见下一节。定稿时如果「当前状态」那一节被你改过，工具不会覆盖它，而是在这张卡上挂一个黄色 ❗，右键「对比第 N 章给出的状态…」看机器那一版要不要用。
  在**分组标题**上右键另有两条不调模型的整理动作：**清理别名**——删掉 aliases 里不是专属称呼的词（`她`、`姐姐`、`少女`、`这位小姐` 这类泛称，以及被误填成别名的其他角色的名字）；**查找并合并重复角色卡**——同一个人被建成两张卡时（摘要里一会儿写「方源」一会儿写「古月方源」就会这样），逐组问你保留哪一张，其余的搬进 `.novelforge/.trash/`。两者都只改文件头部的 frontmatter，**你手写的正文一个字都不会动**。
  如果有两张卡抢同一个称呼，这一组顶部会出现一条黄色提示——出场统计只会算给其中一张，另一张必然是错的，而这件事光看界面看不出来。
- **出场人物 · 未建卡** —— 摘要里出现、但还没有角色卡的人物，按出场章数从多到少排。点名字（或右键「创建角色卡」）会建一张卡，并立刻通读他出场的那几章把档案填出来。在分组标题上右键还有「给全部 N 人建卡」，一次把这一组清空（动手前会报清人数、章数与预计调用次数）。这一组只在确实有这种人时出现。
- **设定** —— 点开对应的 Markdown 文件；副标题显示 keywords。右键可「从已写正文生成/更新设定」：首次会逐章通读，随后为每条设定做一次跨章整合；新条目按分类目录创建，已有条目逐条审阅后才覆盖。
- **文风与摘要** —— 全书摘要（写着覆盖到第几章）与文风指南两行，全书摘要带「重建」，文风指南带「从正文提取」「从参考书学」；**叙事线**一行写着几条、几条进行中、几条已收，过了计划回收章还没收的标「⚠ n 条已过回收章」，行内与右键是「从细纲排出 / 从细纲补充」（先弹确认框，写明 1 次调用；还没有细纲时不给）；底下一行工具是「同步过期摘要」「提取/更新角色卡」，右键还有「批量拆细纲（只补缺）」「批量写章…」。这几行是工程的固定文件，**不能**重命名或删除。分组副标题给出摘要覆盖情况（如「已总结 62/76 章 · 14 章待总结」）。

**出错的行会挂一个感叹号。** 角色卡、章、设定条目一旦生成失败，那一行的名字前面会出现 ❗，鼠标移上去说清楚发生了什么：**红色**表示这次整体失败、磁盘上的东西一个字都没改（比如模型没按要求返回 JSON，角色卡原样不动）；**黄色**表示部分完成，或者写出来了但需要你看一眼（批量写章写出来的这一章开头重演了上一章、把后面几章的人提前写了进来、或者没写够八成）。浮窗里能看到时间、原因与建议，鼠标可以移进去选中复制。这个标记会**一直挂着直到那一项成功为止**，成功之后自动消失——你不必守着日志页，也不会因为错过一条 toast 就拿着一张没更新的角色卡继续写下去。（完整记录仍然在日志页，那里能翻到每一批的细节。）

有过期摘要时这一页顶部会出现黄条，写清「有几章缺失或过期」「已总结多少 / 共多少章」，并画一条进度条；点「立即同步」批量补齐，跑起来后由页头的任务条接手。**这条提示只长在工程页**——对话页那点宽度留给正文；人在别的页时，活动栏「工程」上的小圆点负责留个记号。工作区还不是小说工程时，这一页显示初始化入口。

#### 三个批量入口

都在工具栏上，**都只补空白**：已经有的一律跳过，不问也不覆盖（一次弹几十个对比框没人看得完，跳过是那条路上唯一安全的做法）。要重做某一章，去对话页单独重做。动手前的表单或确认框都写清要调几次模型、走哪一档。

- **补齐设定** —— 配置 → 前提 → 角色图谱 → 世界观，缺哪件补哪件，按顺序一件一件来（每件都吃前面几件的产出），一件失败就停。小说配置要有「一句话」可以展开。已经写了正文的，用「故事架构」组右键的**从已写正文补齐**（见[拆书](#拆书导入原稿与参考书)），照正文整理而不是从一句话编。
- **拆细纲…** —— 选一段章号（缺省从下一个该写的章起 5 章，不越过大纲覆盖的范围），已有细纲的章跳过，每批 5 章一次调用，一批失败就停。表单上实时写着跳过几章、分几批、预计与最多几次调用。
- **批量写章…** —— 选一段章号（缺省从下一个该写的章起 3 章，最多 10 章）与模式：**只写正文**，或**写完即定稿**；另可勾「写完即审稿」，每写完一章先审一遍，报告放进一个新会话「批量审稿 · 第 a–b 章」，你回头在报告卡上逐章勾选、修稿。
  - **一章一章串行写**：后一章要接着前一章的结尾写，写完即定稿时还要读前一章更新过的角色状态。
  - 写不出来就停；写出来但开头重演了上一章、把后面几章才登场的人提前写了进来、或者没写够八成的，照样落盘，然后停下、挂黄 ❗，等你看过再继续。
  - 开跑之前做一次一致性预检：细纲把角色卡上写着已经死了的人排进了某一章，就先问你一句（「仅本次忽略，照写」）。
  - 任务条上有「写完这一章就停」：这一章照常写完、落盘（定稿），然后收工。

#### 任务条

批量写章、定稿、同步摘要、重建全书摘要、提取角色卡/文风这类要连着调几十次模型的动作，会在页签上面出现一条任务条，**五个页签都看得见**——从对话页点的定稿，切到工程页照样看得见进度：**任务名 · 当前那一章 · 第几项/共几项 · 百分比 · 已用时 · 停止**。

- 计时每秒自己走，不等后端推——一次模型调用可能安静一分钟，秒数停住会让人以为卡死了。
- 不知道总量的阶段（比如提取文风的「分析中」）画一条来回扫的条，不给假的百分比。
- 「停止」立刻中断，已完成的部分**保留**（摘要是一章一写盘的，停在第 30 章就有 30 份摘要；批量写章停下时，正在写的那一章不落盘）。批量写章另有「写完这一章就停」。
- 做完时弹一条提示，按钮直接打开产物：「打开第 N 章」，批量审稿时是「打开审稿报告」。
- 刷新页面或重连后任务条自动接上，任务不会因为你关了标签页而消失。

同一时刻可以有多个任务并存，各占一行。

### 日志页

第四个页签。上面说的每一步都在这里留痕，用来回答「刚才那 76 章卡在哪了」：

| 能做什么 | 说明 |
|---|---|
| 按级别过滤 | 调试 / 信息 / 警告 / 错误，默认「信息及以上」。逐章请求这类细节在「全部（含调试）」里 |
| 关键字过滤 | 对来源、消息、详情一起匹配 |
| 展开详情 | 带 ⏵「详情」的行可以点开，里面是耗时、文件路径、失败原因、堆栈等 |
| 加载更早 | 往前翻**重启之前**的日志。日志页平时只显示本次会话的几百条（存在内存里，关掉就没了），更早的存在 `.novelforge/novelforge.db` 里，保留 30 天。点一次往前翻一页，翻到头按钮会变成「没有更早的了」 |
| 复制 | 把**当前筛选出的**日志按纯文本复制，方便贴进 issue |
| 清空 | 清掉**内存缓冲**（库里的历史不动，仍然翻得到）。会留一条「日志已清空」——「日志是空的」和「日志被清过」是两回事 |
| 自动滚动 | 默认开。翻上去看东西时不会被新日志拽回底部 |

两条安全约定：

- **日志里绝不出现 API Key**。所有文本都过一遍脱敏，`sk-…`、`Bearer …`、`api_key=…` 一律抹成「…〔已隐去〕」。可以放心整段复制出来求助。
- **不记 prompt 与正文全文**，只记条数、字数与 token 估算。一次续写的 prompt 有十万字，记下来会把此前所有日志挤没。

日志只存在内存里（最近 800 条），不落盘、不上传，关掉进程就没了。插件版另外把同一份日志写到 VS Code 的**输出面板**（「Novel Forge」通道，命令 `Novel: 显示输出面板日志`），可以和其他扩展的日志并排看；独立版则打在启动服务的终端里（`--verbose` 连调试级一起打）。

其它页面（对话、历史、设置）以及独立版的编辑区，右键给一个「刷新」。

#### 文件夹与文件操作

章节、角色、设定三个区都能像文件管理器一样用：**建文件夹、往里塞东西、随便嵌几层**。文件夹默认折叠，点一下展开，折叠状态记在界面上，刷新数据不会把你收好的树又摊开。（细纲不在其中：它的文件名由章号与标题共同决定，所以走章节那一行的右键——见下。）

新建有三个入口：页面顶部工具栏的「＋ 新建细纲 / 角色卡 / 设定 / 文件夹」建在区根目录；在分组标题或分组空白处右键「在此新建…」同样落在区根目录；**在某个文件夹上右键，落点就是那个文件夹**。

新建细纲**不问标题**：文件按纯序号命名（`007.md`），接在最后一章之后、平铺在 `plots/` 根下，建完直接把你送到这一章当前该做的那一步——刚建出来是空的，所以那一步是「写第 7 章细纲」。标题要等细纲排完、知道这一章到底发生什么之后再起，走「重命名」（或对话页顶上那支 ✎）。

任意文件或文件夹上右键，还有这三个操作：

| 操作 | 说明 |
|---|---|
| 重命名 | 章节的 `NNN-` 序号前缀自动保留，只让你改标题部分。正文首行的 `# 标题` 只在它原本与文件名一致时跟着改——你要是单独改过它，那是你手写的东西，改名不动。草稿跟着搬 |
| 移动到… | 弹出同一个区里的目录列表（含根目录）选落点 |
| 删除（移到回收站） | 搬进 `.novelforge/.trash/`，保留原来的相对路径，随时能手动捞回来。文件夹连里面的东西一起搬，删之前会告诉你里面有多少个文件 |

**细纲的改名与删除是另一回事**：它的文件名由章号与标题共同决定，所以改名只改标题、章号前缀不动；删除细纲只把细纲搬进回收站，**同号的正文与摘要不受影响**。细纲没有「移动到…」：挪进子目录只会让它从章节列表上消失。章节改名时摘要与草稿跟着搬（见下）。

几条不会被打破的规矩：**不跨区**（章节挪不进角色目录，任何操作也出不了工程目录）、**不覆盖**（目标位置已有同名文件就直接报错退出，绝不悄悄盖掉）、**不真删**（一切删除都是搬进回收站）。

改名与移动都**不会让这一章的产物变旧**：跟着改的只有 frontmatter 与标题行，参与新鲜度判断的指纹一个字节都不碰——给一章起个名字不该让它写好的正文显示「上游已变更」。

章节分子目录不影响任何逻辑：章节序号仍然全书连续。

### 章节草稿

每一章都可以有一块**和正文并排的涂改区**：放废弃的段落、备选的写法、给自己的批注。草稿是普通文本文件，跟着工程走、可 Git、可手改，和别的东西一样。

在章节上右键点「新建草稿」（已有草稿时显示「打开草稿」），或者在内置编辑器里打开正文后点工具栏的「草稿」按钮。**首次点的时候才创建**——不会给一个已经二百章的工程凭空撒二百个空文件。

草稿存在工程根的 `drafts/` 下，路径镜像章节在 `chapters/` 之下的那一段，文件名（含扩展名）原样沿用：

```
chapters/001-楔子.md        →  drafts/001-楔子.md
chapters/第二卷/003-夜访.md  →  drafts/第二卷/003-夜访.md
chapters/005-手记.txt       →  drafts/005-手记.txt
```

几条要记住的：

- **草稿不进 LLM 上下文。** 装配器任何阶段都不读它——想让模型看见，就在 `@ 引用` 里手动挑（草稿单列一组，只列已经建过的）。
- **绝不覆盖。** 第二次点「打开草稿」只是打开，不会把你写的东西换成模板。
- **草稿跟着章节走。** 章节改名或移动，草稿一并搬过去；如果新位置已经有草稿了，两份都留着并提示你自己去合。
- **删章节不删草稿。** 确认框里会说明草稿留在哪儿。
- 草稿**不是**可管理区：它不出现在工程页的树上，也不能在界面上重命名/移动/删除——它的位置由章节路径推导，直接改它只会让下次点「打开草稿」建出一个新的空文件。要清理就在文件管理器里删。
- 草稿字数不计入章节字数，也不影响摘要新鲜度。

### 对话怎么用

对话页从上到下分四块：**流水线条**（我在哪一章、走到哪一步）、**工作区卡**（我正在改的那份东西）、消息区、**下一步**（我接下来该干什么）。

打开一章的正确方式是**在工程页点「去写这一章」或右键「进入这一章」**，或者在输入框旁的下拉框里选它。选中之后界面会自动落到**这一章当前该做的那一层**：还没排细纲就落细纲层，细纲排好了就落正文层。你不需要自己判断该从哪儿接着做。

#### 流水线条

顶上一行只报你在哪：`第 4 章《夜入青云》`（**信息条不是按钮**，切层靠下面那两格）；行尾一格徽章说这一章走到哪了（`待写细纲`、`待写正文`、`待定稿`）。右侧两个小按钮：**✎ 给当前这一章的细纲起名/改名**（新建出来的细纲只有序号，起名就在这儿），**＋ 开始一段新对话**。下面一行是这一章的两层与定稿状态：

```
细纲 ●  正文 ◐ ⟳   待定稿
```

- 状态点是**实打实算出来的**：正文写到目标字数的一半就是「进行中」，不是一个存在文件里的状态字段（那种字段在你手删半段正文之后就开始撒谎）。
- **⟳ 表示上游改过**。改了细纲，这一章的正文就挂上它；改了大纲里覆盖这一章的那一节，细纲挂上它——不是错误，是提醒你回头看一眼。手写的产物永远不会挂 ⟳（拿一个凭空的过期标记催你重做，你会学会无视所有标记）。
- 定稿只报状态（未写正文 / 待定稿 / 已定稿），不是一层：它是写完之后的一步。

两层都可以点——**流水线不是单行道**。写正文时发现细纲不成立，点回细纲层改了再回来，比自己去 `plots/` 里翻文件快得多。目标是架构或大纲时这一行只剩名字。

#### 工作区卡

流水线条上挂着一个入口，鼠标移上去（或点一下钉住）浮出**当前这一层的产物本身**：架构层是那份文档，大纲层是开头一段，细纲层与正文层是这一章细纲的三节（正文层另报字数与目标字数——三千字正文摊在浮窗里没人读，要读点「打开」）。聊到第十轮它还在——回头确认「这一章到底要收在哪」不用往上翻。

#### 下一步

输入框上方只有**一个主按钮**，写着这本书现在该做的那件事，旁边的说明里写着要调几次模型：

| 当前状态 | 主按钮 |
|---|---|
| 还没有小说配置 | 生成小说配置…（先弹出一句话表单：脑洞、总章数、每章字数） |
| 前提 / 角色图谱 / 世界观缺哪件 | 生成故事前提 → 生成角色图谱 → 生成世界观（一件一件推） |
| 没有大纲，或下一章超出了大纲覆盖的范围 | 生成情节大纲（第 1–20 章）/ 续写情节大纲（第 21–40 章） |
| 下一章还没有细纲 | 拆细纲（第 N–N+4 章） |
| 选中的这一章细纲还空着 | 写第 N 章细纲 |
| 有细纲、没正文 | 写第 N 章 |
| 正文还没写够目标字数的八成 | 接着写 |
| 细纲在正文之后改过 | 重写第 N 章 |
| 正文写够了、还没定稿 | 定稿第 N 章 |
| 这一章都齐了 | 落到下一章的那一步 |

**点了就跑，不必先输入什么**——该说的都在架构、大纲与细纲里了。输入框里有字就当补充要求一起带上（「多写点雨里的细节」）。次数写在动手之前：写一章是「预计 1–2 次调用，最多 9 次」（开着删修饰时写完再删一次；没写够时自动续写），定稿是 1–3 次（摘要一次，有出场角色卡时再一次，有还没收的叙事线时再一次）。**单章写完不会自动定稿**——要你点那一下。

**写完删修饰**（设置 → 上下文管理，缺省开）：开着时正文按目标字数的 1.2 倍去写，一章写完，同一个模型再过一遍，只删名词前堆的形容词、动词前的程度副词这类多余修饰——不加字、不动对白，删坏的段落自动退回原文，删完不到目标字数的八成就把删得最多的段退回去。对话页点「写入」之后会弹出删前 ↔ 删后的逐段对照，删错的段可以退回原文（VS Code 插件里没有这一步，直接用删后的）。

写正文的提示词只给篇幅的大概（「约 N 字，不必精确」），够不够由续写按实际字数判断；另要求多让人物开口——交代、对峙、讨价还价写成对白，续写时已写部分对白偏少（不到四分之一的段）会被点名提醒。

其余动作收在 **`/` 命令**里：**在输入框里直接打 <kbd>/</kbd>**（和 Cursor、Claude Code 一样），候选列表就浮在输入框上方；也可以点输入框下面那颗「/ 命令」。接着往下打字就是过滤，中文和拼音首字母都认（`/ld` → 落定细纲）。<kbd>↑</kbd><kbd>↓</kbd> 选，<kbd>Enter</kbd> 确认——命令变成输入框里的一枚标签，那几个字符自动收走，剩下的空间留给补充要求。按 Enter 执行，用完即清：命令是一次性的选择，不是模式。各层的命令：

| 层 | 命令 |
|---|---|
| 架构 | `/生成这份架构文档` |
| 大纲 | `/生成情节大纲` |
| 细纲 | `/写细纲`、`/落定细纲` |
| 正文 | `/写正文`、`/审稿` |

**`/落定细纲` 只有细纲层有**，它是「先跟人聊、聊出结论再落文件」的那条路：跟 AI 来回讨论几轮这一章该怎么走，谈拢了打 `/落定细纲`，它把讨论中**已经达成的结论**整理成细纲——不会塞进被你否掉的方案，也不会临时发明新走向；还没定下来的地方留空并在细纲之外说一句。为此这条命令装配上下文时**会把整段讨论都带上**（历史预算从三成抬到六成，优先级提到最高）：要沉淀的就是那段对话，按常规由远及近截掉等于把结论截没了。另一条入口是 **`/写细纲`**：你在输入框里描述这一章的走向，它按你说的填，你没说到的地方顺着已有设定与前后章补上。改写也不是另一条命令：目标已经有内容时再点「生成」，你输入框里的话就是修改意见，它会在那一版的基础上重做。

`/` 在中文正文里是普通字符（日期、比值、网址），所以只有「整个输入框就是一个 `/词`」才当成在下命令——`子时 3/4 刻` 和 `/ 这是一句话` 都不会弹面板。面板里会写文件的命令后面挂一枚「写文件」标签：点它们要花钱，而且会在磁盘上留下东西；`/审稿` 挂的是「只出报告」。命令都可以留空发出——消息气泡里显示的是 `/写细纲` 这样的命令名，不是一片空白。

**直接打字就是讨论。** 没挑命令时，你说的话按当前阶段的「讨论」发出去：想聊、想挑刺、想跟设定对账，直接说。

**多步的活交给外部 agent（MCP）。** 「第 9 章里主角说过他没去过北境吗」「把第 5–8 章写完并定稿」这类要读好几份文件、分几步做完的事，用 Claude Code、Codex 之类的通用 agent 接进来做。独立版启动时会在同一个端口上挂一个 MCP 入口，终端日志里那一行就是接入命令：

```
claude mcp add --transport http novelforge http://127.0.0.1:3000/mcp
```

它拿到的是和对话页同一套工具（读、搜、生成、写、改、工程动作），落在你**最近操作的那个网页窗口开着的工程**上；同时开着几个工程时，可以在地址后面加 `?project=<工程目录>` 把它钉在某一个工程上（如 `http://127.0.0.1:3000/mcp?project=D:/books/北境`），那个工程得在某个窗口里开着。它调 `generate` 产出的正文流进对话页里一个标着 MCP 的气泡，**不回到它那里**；要不要落盘照样在对话页当场问你，你点了才写，它等你答完才继续。改一段文字、装 / 绑写作技能这类没有 diff 可看的动作，动手前也先在对话页问你；覆盖已有内容照旧先让你逐行过目。「下一步该做什么」它从同一个状态机拿结论（附在工具结果末尾）。审稿它不做——在正文层打 `/审稿`。VS Code 插件暂时没有这个入口。

输入框下面还有：**模型**（切换即时生效，预算按新模型的窗口重算）、**思考深度**、**当前章**。目标字数不在这里：只认细纲里的 `targetWords`，没写就取小说配置的每章字数。

**思考深度**有五档：不思考 / 浅思考 / 中思考 / 深思考 / 极限思考。它**跟着这个会话走**，不是一条全局设置——排一份大纲值得让模型想透，改一个错别字不值得，而这两件事往往就是相邻的两个会话。点「新对话」时它跟着继承（多半是换个话题接着做同样难的事），关掉面板再回来还在。

缺省是**不思考**：思考的 token 按输出计费，一句「帮我看看这段」可能因此贵好几倍，所以得你主动选。选了之后模型想的那段过程会流进气泡上方的「思考过程」折叠块——它**不是正文**，采纳写入章节时只取正文。

同一个档位在两家的接口上是两套字段（OpenAI 的 `reasoning.effort`、Anthropic 的 `output_config.effort` 或老模型的思考预算），插件替你映射；某个模型不认最高那一档时会自动降一档重发，而不是给你一句报错。**只有对话页这条路吃这个档位**——工程页的批量任务（批量写章、摘要、角色卡、设定）一律不带，不然一次同步七十六章的账单会翻好几倍。

#### 写一章：看得见进度，也看得见问题

写正文时气泡上方有一条进度：「第 2 轮 · 已写 1860 / 目标 3000 字」。一次没写够八成就自动接着写；结尾收得太早（已经落在章末钩子上了，却还不到八成）时，先把收尾那一段拿掉、把这一章还没写足的事件写足，再重新落到钩子上——不会往钩子后面硬接。写完的卡片上写明「2980 / 3000 字 · 已达标」或「未写够（不到目标的八成）」，已写的不会丢。

卡片上还会写出这几样，**不拦你，但说清楚**：

- **重演**：开头把上一章最后一场又演了一遍——标红，写出重合的原句，「写入」要点两下。
- **后面几章的人提前登场**：后 5 章细纲里才排的人，在这一章写到了。
- **比喻词超标**：「仿佛」「犹如」「宛如」全章合计超过 3 次。
- **英文缩写**：民国背景里冒出 PTSD 这种词时提醒一句（都市、科幻题材里的 CEO、AI 当然正常）。

写之前还有一次**零调用的一致性预检**：细纲把角色卡「当前状态」里写着已经死了的人排进了这一章，先亮一张卡——「先不写」「仅本次忽略，照写」，或者填一句理由「记为刻意安排，照写」（回忆、幻象、托梦都算），理由记进这一章细纲的 frontmatter（`preflightOk`），以后写这一章不再为这个人亮卡。

#### 审稿与修稿

在正文层打 `/审稿`（或独立版章节条上的「审稿」），一次调用出一份报告，不改任何文件：

- **问题**按严重 / 建议分组，每条带一句**逐字引文**——点引文，编辑器里就选中那一句。引文在正文里找不到的条目直接丢掉（模型编的「问题」最容易让你去改一段根本不存在的话），丢了几条写在报告底下。
- **目标核对**：本章细纲的关键事件与章末钩子冻结成一张清单，逐项判「已完成 / 未完成 / 待核实」。判「完成」或「未完成」都得给得出正文里找得到的引文，给不出就降成待核实——「正文里没提」只能是待核实。
- 严重、建议、未完成缺省勾上，待核实缺省不勾。点「编辑」可以改条目、加一条你自己的（「新增问题」）；模型给的不能删，不想修就不勾。

勾好之后点「按勾选的 n 条修稿」：只把勾选的那几条连同整章原文交给模型，要求改动越少越好；被截断时最多续 3 次，改完比原稿短太多就报错、不出卡片（修稿是拿它覆盖一章已经写好的正文，半截比没有更糟）。写入之前先对比：独立版是一张段级合并视图，逐处「采用新版 / 保留原文」，中间的结果可以手改，手改过的那一处不会被「采用」冲掉，顶上写着「已处理 k / n 处」；插件用 VS Code 的 diff 编辑器。

#### 落盘：当场问你一句

产出结构化产物时，**生成一结束就在对话里问你要不要写进工程**——一张卡片，写清落点与分量：

```
🔒 把这份产物写入到「第 12 章《夜入青云》 · 细纲」
   细纲 · 3/3 节
   [ 写入 ]   不采纳
```

回复本身可以直接点进去改，**改完再点「写入」，落盘的就是你改过的那一版**。目标已经有内容时按钮是 **[覆盖并写入]**，点了还会再让你对比一遍新旧两版。点「不采纳」就一个字都不写，气泡末尾留一行「未采纳」，翻回来看得出这一轮产出过什么、你没要。细纲里排了还没有卡的新角色时，卡片上会列出写入时一并新建哪几张。

**只是讨论的回复不会问**——一段闲聊没有该落的地方；审稿报告也不问，它随会话保存，不写文件。每条回复下面折叠着这次的上下文明细，点开就知道带了什么、丢了什么。

> 这一问和外部 agent 动手前那一问长得一模一样、在同一个位置：**要动你的磁盘，一律先在对话里问**。

### 引用上下文（Cursor 式）

两种方式往当前这轮对话里塞内容：

- 点 **@ 引用**（或在输入框直接敲 `@`）——列出所有章节、角色卡、设定条目，也能浏览工作区任意文件。
- 在编辑器里选中一段文字，按 <kbd>Ctrl+Shift+L</kbd>（macOS 为 <kbd>Cmd+Shift+L</kbd>），或右键「将选中文本加入对话上下文」。

引用会以标签形式挂在输入框上方，发送前可以逐个移除。**选区存的是快照**——你选的时候是什么样，历史记录里就一直是什么样，之后改了原文也不会让过去的对话跟着变；整文件引用则每次都读最新的。

### 对话历史

发出第一条消息后自动保存到 `.novelforge/sessions/<id>.json`，跟着工程走，可以提交到 Git。空会话不落盘，历史列表里不会堆一排没说过话的占位。

## 目录结构

初始化后的工作区：

```
chapters/                    正文。**唯一真相**：摘要从这里生成，上下文里的前文也从这里取
├── 001-楔子.md               细纲号 = 章号：第 1 章的细纲是 plots/001-*.md
├── 002-客栈里的女人.md
└── 第二卷/                   可以分子目录收纳，随便分几层；章号仍然全书连续
    └── 003-夜访.md
drafts/                      章节草稿，路径镜像 chapters/，按需创建
├── 001-楔子.md
└── 第二卷/
    └── 003-夜访.md
.novelforge/
├── project.json             章节索引 + 摘要新鲜度指纹
├── config.md                小说配置：frontmatter 是规模参数，正文八节（一句话 / 核心梗概 / 核心卖点 / 世界观要点 / 金手指 / 主角档案 / 全局要求 / 参考作品）
├── premise.md               故事前提（一句话前提 / 核心冲突链 / 爽点循环 / 悬念骨架）
├── world.md                 世界观（规则与漏洞 / 阶层与资源 / 深层危机）
├── outline.md               情节大纲，按「第 a–b 章：标题」分节，可以只覆盖到一部分章
├── style.md                 文风指南 —— 写正文时必注入
├── threads.md               叙事线（可选）：跨章的伏笔与线索，一条一个「## 名字」，事件由定稿追加
├── skills/<名字>/SKILL.md    本工程的写作技能（可选，手放；见「写作技能」）
├── skills.json              每个阶段绑了哪份写作技能（在设置页「技能」里绑）
├── characters/<名字>.md      角色卡（同样可分子目录，如 characters/主角/林昭.md）
├── lore/<条目>.md            世界观设定（同上）
├── plots/                   细纲，一章一份，平铺不分子目录
│   ├── 001-楔子.md
│   ├── 002-客栈里的女人.md
│   └── 003-夜访.md
├── summaries/
│   ├── 001-楔子.md          单章摘要（按**章节**文件名镜像）
│   └── global.md            全书滚动摘要
├── sessions/                对话历史，一次会话一个 .json
├── novelforge.db            失败记录与日志历史（SQLite，可随时删，见下）
└── .trash/                  工程页删掉的东西搬到这里，可手动找回
```

**`chapters/` 是这条链的终点。** 正文直接写进这里，它就是这本书的唯一真相：摘要从它生成，上下文里的前文从它取，工程页那一行的字数也报它。摘要与草稿跟着章节的文件名走：`chapters/003-夜访.md` 的摘要在 `summaries/003-夜访.md`、草稿在 `drafts/003-夜访.md`，改名时各自跟着搬——所以起个名字不会让写好的东西凭空消失。

**细纲带 frontmatter，章节不带。** 细纲长这样：

```markdown
---
no: 12
title: 夜入青云
role: 小高潮               # 本章在结构里的功能
characters: [林昭, 沈青]     # 计划出场，只用来挑角色卡，不算进出场统计
targetWords: 3000           # 没写就取小说配置的每章字数
upstreamHash: …             # 生成时大纲里覆盖这一章那一节的指纹
writtenFrom: …              # 正文据以写成的细纲指纹，正文落盘时记
---
# 第12章 夜入青云
## 本章目的
## 关键事件        ← 100–300 字，可以写到具体场面，但不写成正文
## 章末钩子        ← 必填
```

界面上那个 ⟳ 就是靠 `upstreamHash` 与 `writtenFrom` 比对出来的。手写的细纲（没有这两个字段）永远不会被标 ⟳。「这一章的正文依据的是哪一版细纲」记在细纲这一侧，因为 `chapters/` 下的文件是你的东西——可以是 `.txt`、可以没有扩展名、可以没有 frontmatter，插件写进去的只有正文本身。

老工程直接把已有的章放进 `chapters/` 就行：没有细纲不影响，`chapters/` 里有文件就算写过那一章，可以直接定稿、直接进上下文。稿子是一整本 txt 的，用工程页的「导入原稿」切成一章一份；之后「从已写正文补齐」把新链路上缺的东西照正文整理出来（见[拆书](#拆书导入原稿与参考书)）。从前那一套（卷、剧情段、中转站）留在磁盘上的 `volumes/`、`manuscripts/`、`scenes/` 一个字节都不会动，工具只是不再读它们。

**分子目录只是收纳。** 章节的顺序永远由文件名前面的数字决定，跟它在第几层没关系——`第二卷/003-夜访.md` 就是第 3 章。分子目录不重置编号，全书连续编号。细纲则是扁平的：`plots/` 下不分子目录，序号即章号。

**摘要按章节的文件名对应。** `summaries/001-楔子.md` 对着 `chapters/001-楔子.md`。因此同序号但不同标题的两章（手改文件名撞车时会出现）各有独立摘要，互不覆盖；给一章改名时摘要跟着搬到新名字下。**还没写正文的章没有摘要是正常的**——没有正文就无从定稿，工具不会为此催你。

**章节不挑扩展名。** `chapters/` 下凡是「数字前缀 + 不是二进制文件」的都算章节：`001-楔子.md`、`001-楔子.txt`、`001-楔子`（没有扩展名）、`004.json` 都会出现在章节列表上，从别处导入的稿子不用先改名。图片、Office 文档、压缩包、音视频这类打开必然是乱码的会被挡在外面——往 `chapters/` 里丢一张 `001-封面.png` 不会凭空多出「第 1 章」。

只有 `.md` / `.markdown` 的章节会把正文首行的 `# 标题` 当成章节标题（并在注入上下文时剥掉）。其余格式的章节标题一律取自文件名，正文一个字节都不动——`.txt` 里写一行 `# 什么什么` 就只是正文里的一行字。

角色卡与设定条目不跟着放宽，仍然只认 `.md`：那是插件自己的数据格式（frontmatter + 固定小节）。

**`novelforge.db` 是可以删的。** 它只存两样东西：**失败记录**（哪张角色卡/哪一章/哪条设定生成失败了，工程页上那个红色感叹号就是读它）与**日志历史**（让日志页能看到重启之前的记录，超过 30 天自动清理）。你的作品内容一个字都不在里面——正文、细纲、摘要、角色卡、设定永远是纯 Markdown。删掉它不会丢任何内容，只是丢掉这些历史痕迹，下次需要时会自动重建。它已经在 `.gitignore` 里（连同 WAL 模式产生的 `-wal` / `-shm` 两个附属文件），不会进版本库。

> 从 0.1.x 升级：元数据目录由 `.novel/` 改名为 `.novelforge/`。插件启动时检测到旧目录会问一次是否重命名，不会静默改动。

### 角色卡格式

```markdown
---
name: 林昭
aliases: [阿昭]        # 纲要里出现别名也能命中
tags: [主角]           # 标 "主角" 的角色始终注入
firstAppear: 1
lastSeen: 3
appearsIn: [1, 2, 3]   # 出场的章（由摘要自动聚合，可手改）
updatedThrough: 3      # 上次更新角色卡时读到第几章
stateThrough: 3        # 「当前状态」更新到第几章（定稿时写）
stateHash: …           # 机器最后一次写「当前状态」时那一节的指纹
---

# 林昭

## 身份
## 外貌
## 性格          ← 最重要，决定模型能不能把这个人写像
## 语言习惯      ← 对保持角色声音最关键
## 人物关系
## 当前状态      ← 由定稿维护；预算不足时优先保留
## 未收伏笔      ← 预算不足时优先保留
```

小节名固定。预算紧张时角色卡会降级为只保留「身份 / 当前状态 / 未收伏笔」三节。

`appearsIn` 与 `updatedThrough` 是插件自己维护的两个字段：前者是这个人出场过的章，后者是上次更新角色卡时读到了哪一章（增量更新的起点）。**它们只是缓存**——真正的出场记录始终在各章摘要里，插件每次刷新工程页都从摘要重新聚合。手删掉这两行不会丢数据，只会让下一次「更新角色卡」变成全量重读。

**「当前状态」归定稿维护。** 每定稿一章，就用一次调用把本章出场角色的「当前状态」更新到这一章，记下 `stateThrough` 与这一节的指纹 `stateHash`。下次定稿时如果这一节和 `stateHash` 对不上——说明你手改过——就不写，在那张卡上挂一个黄色 ❗，右键可以对比机器给出的那一版再决定用不用。写下一章时，装配器据此知道角色状态截至第几章（还没定稿的前一章会在明细里说清）。

### 更新角色卡

角色行右键有两个更新入口：

| | 读哪些章 | 什么时候用 |
|---|---|---|
| **更新角色卡（新增 N 章）** | 只读 `updatedThrough` 之后这个人出场的章 | 日常。写了几章之后把新进展补进档案，最省 token |
| **重新通读全部 N 章** | 这个人出场的所有章 | 角色卡被改乱了、或者想彻底重来 |

出场章由摘要自动关联，你不用再手输章号——所以**这个功能依赖摘要**：某个角色没有任何摘要提到过他，菜单里会直接说「未在摘要中出现，无法自动更新」，先去同步摘要即可。

主角可能在几十章里出现，一次装不进上下文窗口。插件会按输入预算把这些章切成若干批，**并在动手前告诉你要调几次模型**：

> 全量重建「林昭」的角色卡：需要通读 34 章，分 4 批，预计调用模型 4 次。现在开始？

后一批看得到前一批已经归纳出的内容，是逐批精炼同一张卡，不是各写各的然后拼起来。分批过程中任务条上有进度，可以随时停止（已归纳的部分不会写坏原卡——最后一步才落盘，且照旧走 diff 确认）。

角色卡会在**每次续写时注入上下文**，所以它必须精炼。更新用的提示词给每一节都定了字数上限，并明确要求优先写好「性格」和「语言习惯」，外貌和人物关系写个梗概就行；「未收伏笔」里已经在正文中解决的会被删掉。反复更新十几次也不会让角色卡膨胀成一篇论文。

## 上下文是怎么装配的

这是插件的核心。**每一层带的东西不一样**——定架构时读三章正文既没用又昂贵，而写正文时前几章是必需的：

| 阶段 | AI 是谁 | 带什么 | 明确不带 |
|---|---|---|---|
| **架构** | 网文策划编辑 | 配置 / 前提 / 世界观、角色图谱一览、已有角色卡 | 正文原文、大纲 |
| **大纲** | 策划编辑 | 架构四件、**按总章数算好章号区间的故事结构指导**、大纲全文、全书摘要与各章摘要 | 正文原文 |
| **细纲** | 剧情编剧 | 架构四件、**大纲里覆盖这几章的那几节**、前序细纲一览（最近 100 章，一行一章）、前 3 章与后 1 章的细纲、结构指导、更早章的正文摘要；单章时还有本章细纲 | 正文原文 |
| **正文** | 作者 | **文风指南、全局要求、本章细纲、上一章结尾（不许重演）、后 5 章细纲（不许提前写）、执行卡（放在最后）**；出场角色卡、前提与世界观、大纲里本章那一节、进行中的叙事线；**定稿原文片段**、全书摘要、命中关键词的设定；近 2 章正文；更早章的摘要 | —— |
| **审稿** | 审稿编辑 | **这一章正文全文、本章细纲（冻结成目标清单）**、后 5 章细纲（标「非既定历史」）；出场角色卡、架构、上一章结尾；前几章定稿留下的连续性事实 | 历史对话、文风 |
| **修稿** | 作者 | **整章原文 + 勾选的审稿意见、文风、全局要求**；本章细纲、出场角色卡、上一章结尾、后 5 章边界；定稿原文片段 | 写一章的那套法则、篇幅合同、执行卡 |

前三层不带正文原文，token 因此降一个数量级。几处刻意的安排：

- **写正文时文风指南与本章细纲永远保证注入**。前者是「读者感觉不到换人执笔」的唯一保障，后者少了的话，模型手上只有文风与前文的尾巴，会自己编一段剧情出来。
- **执行卡放在消息最末**：本章必须写到的事件、章末钩子、哪几个人这一章不出场、比喻词还剩几次——模型对最后读到的东西最听话。
- **定稿原文片段（evidence）**：摘要里的每条连续性事实挂着一句原文证据，写新一章时拿这句话回到那一章的正文里逐字定位，带所在段落与前后各一段——前 5 章全取，更早的只取提到本章角色的，最多 12 章、6000 字。摘要是转述，原文才是事实；作者改过正文、找不到那句话时，退回那条事实的文字，并在明细里写明。
- **进行中的叙事线（threads）**：`threads.md` 里还没收、和本章有关的线，最多 6 条、1200 字，一条一行——本章细纲提到的排最前，其次是本章在计划区间里的、已过回收章的、已经埋下的。计划在后面才埋、细纲也没提的线不带，免得模型提前埋；状态按「写到这一章时」算，重写前面的章时后面几章才发生的事不算。放不下的在明细里写明。
- **写作技能**：给这个阶段绑了一份技能的话，它排在消息最前面，作者事实和输出格式都排在它后面、说了算；放不下就整份不带，明细里写明（见下面「写作技能」）。
- **`/落定细纲` 时历史对话的预算从三成抬到六成，且提到最高优先级**。这条命令要沉淀的就是那段讨论，按常规由远及近截掉等于把结论截没了。
- **已经写入的产物不随历史再带一遍**：同一个会话跟着主按钮一路走，前面落过盘的配置、大纲、细纲、正文都有专门的层按磁盘带；历史里那一轮跳过，明细里写「已写入 xxx，以磁盘上那一份为准」——落盘之后你手改过的话，历史里的还是旧版。

每一层内部按优先级填预算：

| 层级 | 内容 | 预算不足时 |
|---|---|---|
| **P0** | 系统提示、你这一轮的话、**@ 的引用**、本层产物（正文层：文风、细纲、上一章结尾、后 5 章边界、执行卡） | 永远保留；引用超限时截断 |
| **P1** | **本会话历史对话**、出场角色卡、架构与大纲切片、进行中的叙事线 | 角色卡先降级为「身份+当前状态+未收伏笔」，其余整块丢弃并标注 |
| **P2** | 定稿原文片段、全书滚动摘要、命中关键词的设定 | 丢弃并标注 |
| **P3** | 最近 N 章完整正文（默认 2 章） | 降级为该章摘要 → 丢弃 |
| **P4** | 更早章的摘要 | 由近及远填充，填满即止 |

预算 = `contextWindow - maxOutputTokens - 512`。完整的配方表见 [src/core/context/README.md](src/core/context/README.md)。

**引用为什么在 P0**：你特意点了它，就不该被自动装配挤掉。但单条封顶预算的 35%，超出从头部截断——@ 一个大文件不能把前文全挤没。

**历史对话怎么带**：作为真正的多轮消息发出（role 交替），不是塞进一段「以下是我们之前的对话」。整体封顶预算的 30%、单轮 12%，由近及远填充；单轮过长时取结尾，因为越靠后越接近当前进度。

**角色卡怎么选**：本章细纲里计划出场的（`characters:`）→ 你这句话里出现姓名/别名的 → 前两章出场的（读摘要的「出场人物」）→ 标签含「主角」的。取并集去重。

**讨论不会顺手改写产物**：直接打字聊（包括让它挑刺、对设定）时系统提示里明写「只回答，不要输出改写后的完整产物」。少了这一条，模型会一边回答一边把整份细纲重写一遍，而界面上那一版是不能采纳的，你只会困惑。

**不静默截断**：任何被降级或丢弃的条目都会留在明细里，标明原因（「预算不足，需 800 token，剩 200」「这一章还没写正文，只带目标」「历史对话预算已满」）。每条回复下方折叠展示，你随时知道这次没带上什么。

**去重**：如果上一章整章原文能完整放下，P0 那份结尾片段会自动撤掉，同一段文字不会在 prompt 里出现两次。

## 拆书：导入原稿与参考书

借鉴自 [AI-Novel-Writer](https://github.com/EthanYoQ/AI-Novel-Writer)（GPL-3.0）的「小说拆解与仿写」，分两件事：**自己的稿子接上来**，**别人的书学写法**。两件都只读**工程里**的 txt——先把文件放进工程目录（不要放进 `.novelforge/` 这类隐藏目录，也别起数字开头的名字放进 `chapters/`，那会被当成一章）。UTF-8、UTF-16、GBK 都认，一本最大 64 MB。

### 导入原稿

「章节」组右键 **导入原稿（选一本 txt）…**：在本机任意位置挑一本（独立版是网页里的目录选择器，插件是 VS Code 的打开对话框；txt 不必先放进工程），工具按章标题切开，确认框里写清认出几章、导入成第几到第几章、开头几章与最后一章的标题，以及丢掉了什么——第一个章标题之前的书名简介、`第一卷 ……` 这种卷标题、目录里那一串没有正文的标题。**这一步不调模型。**

- 认的章标题：单独一行的 `第一章 雪夜`、`第12章：雪夜`、`第三回 夜奔`、`Chapter 7`，以及序章、楔子、引子、尾声、终章、番外。一个都认不出就不导入。
- 每章新建一个 `chapters/NNN-标题.md`，一段一行、去掉行首空格；**接在已有章节之后**，章号按顺序重编；同名文件已经在就停下，不覆盖。原 txt 不动。
- 切得不对？改 txt 里的章标题再导入一次——切的结果不能在界面上手调。

导入完会问一句要不要接着补齐。

### 从已写正文补齐

已经有正文、却缺架构或大纲没覆盖到它们时，主按钮就是 **从已写正文补齐…**（「故事架构」组右键也有）。它照着第 1 章起连续写好的正文，按链路顺序**只补空白**：

```
摘要（缺的、过期的）  →  小说配置 → 故事前提 → 角色卡 → 世界观  →  情节大纲  →  细纲  →  全书摘要
```

- **问两次**：摘要没齐时先只报摘要要调几次；摘要出来之后再报其余几样——建卡要调几次得看摘要里认出了谁、各出场几章。
- **架构**看全书梗概与均匀抽出的 5 章开头；小说配置没写总章数时问你一句，每章字数取已写各章的平均。
- **角色卡**给摘要里出场两章以上、还没有卡的人建，读的是他们出场的那几章正文，「当前状态」写到最后一次出场。
- **情节大纲**每次照 20 章的摘要整理（分节格式与平常一样，每节最多 5 章），只写已经发生的事；**细纲**每批 5 章，照正文的开头与结尾提取，标题用章节自己的，目标字数记那一章的实际字数。
- 已经有的一件不动；一件失败就停，已经写好的留着，失败挂在那一行上。
- **叙事线不排**：那是给后面的章的计划。之后照常拆细纲时会接着排。
- 绑在「规划」阶段的写作技能这一次不带：照实整理，不按技能的排法改写已经发生的事。

补完之后主按钮变成「续写情节大纲（第 N+1 章起）」，接下来和新书一样往下走。

### 从参考书学写法

「文风与摘要」组的文风指南那一行 **从参考书学**：挑一本，选学**文风**、**写法**还是两样都学，各 1 次调用（走「提取文风」那一档）。

- **文风** → `style.md`：均匀抽 5 章各取开头 2500 字，用与「从正文提取文风」同一份提示词（只学技法，不复述情节、人名、地名、专有设定）。`style.md` 已经有内容时，按钮写着「覆盖 style.md 并开始」。
- **写法** → 一份写作技能 `.novelforge/skills/<书名>-写法/SKILL.md`（`stage: planning`）：看开头 3 章与全书 30% 处的连续 3 章（各取开头与结尾），加上程序数出来的篇幅统计，写成章节结构、场景推进、钩子与悬念、节奏与爽点、信息投放、开篇写法、规划时怎么用七节。写完问你要不要绑到「规划」阶段——绑上之后架构、大纲、细纲的每一次生成都带着它。
- **原文不进工程的任何文件**，也不反推它的设定、角色与细纲。

## 写作技能

写作技能是一份**补充的写作方法**：一个目录里一份 `SKILL.md`，开头几行 frontmatter，下面是正文——「每个场景围绕角色的主动选择、选择的代价……」这样的话。给本工程的某个阶段绑上一份，这个阶段往后的**每一次生成**都会把它放在提示词最前面：对话页、外部 agent（MCP）、工程页批量都一样。

```markdown
---
name: scene-craft
display_name: 场面写法
description: 写场面的办法
stage: drafting          # 建议绑在哪个阶段：planning / drafting / review / refinement（只是建议）
---
每一场都要有一个选择……
```

| 阶段 | 什么时候带 |
|---|---|
| **规划** | 架构、大纲、细纲的生成与落定（含补齐设定、批量拆细纲；「从已写正文补齐」不带） |
| **写正文** | 写、接着写、重写，以及自动续写那几轮和删修饰（含批量写章） |
| **审稿** | 审稿 |
| **修稿** | 按勾选的审稿意见修稿 |

讨论、定稿、摘要、文风提取都不带。每个阶段最多绑一份，同一份可以绑几个阶段；**没绑就什么都不带**，内置的也不会自动绑上。

**它只能补充写法**：消息里它的第一句就是「作者事实和后续输出合同始终优先」，你的设定、细纲、已写的正文和输出格式都比它说了算。**放不下就整份不带**，不截半截——明细里写着需要多少 token、还剩多少。绑着的那份后来找不到了、或者变得不兼容了，生成照常，明细里写明这次没带、为什么。

**三个来源**，都在设置页「技能」里看得到：

| 来源 | 在哪 | 怎么来 |
|---|---|---|
| 内置 | 随应用发布：「长篇连续性与场景推进」「自然语言润色」 | 删不掉 |
| 我的技能库 | `~/.novelforge/skills/<名字>/SKILL.md`，所有工程共用 | 从 GitHub 装，或者自己放一个目录进去 |
| 本工程 | `.novelforge/skills/<名字>/SKILL.md`，跟着这本书走、可以进 Git | 自己放 |

目录名就是技能的名字（可以是中文）。手放进去的，切回「技能」页就会出现。

**从 GitHub 装**：设置页「技能」里贴一个地址（仓库首页、`/tree/分支/目录`、`/blob/分支/…/SKILL.md` 或 raw 地址都行），先点「检查」——只下载来看，不写任何文件——看过正文再点「确认安装」；安装时会重新下载一遍，与刚才看的那一份核对一致才装。**只收自包含的纯提示词**：要跑脚本、装 hook、派子代理、调工具，或者引用旁边别的文件的，一律装不了（这里没有能执行它们的地方，装进来只会让模型以为自己能做一件做不了的事）；超过 64 KiB 的也不收。同名的已经装了就不装，要换新版先卸载旧的。**卸载**把整个目录挪进 `~/.novelforge/.trash/skills/`，不真删。

**外部 agent 也会**：对它说「装一下这个技能，绑到写正文上」，它会先检查、再装、再绑——**安装与绑定每一次都先在对话页问你**；卸载它不会，那由你在设置页做。

这套做法移植自 [AI-Novel-Writer](https://github.com/EthanYoQ/AI-Novel-Writer)（GPL-3.0）的「写作 Skill」。

### 摘要格式

摘要是定稿的产物：让模型输出 JSON、再由插件渲染成 Markdown 落盘——你读到、改到的仍然是普通 Markdown：

```markdown
---
chapter: 2
title: 客栈里的女人
sourceHash: a26b6dc8fb924aa7
cast: [林昭, 沈氏(那个女人), 客栈掌柜]   # 机器可读的出场人物
generatedBy: novel-forge
---

# 第2章 客栈里的女人 · 摘要

## 梗概
## 出场人物
## 时间地点
## 关键事件
## 新增伏笔
## 状态变更
## 连续性事实
- 林昭左臂被青鳞划伤，未愈 〔证据：「血顺着左臂往下淌，他把袖子扎紧了」〕
- 沈氏知道了玉佩的来历 〔证据：「……」〕
```

`cast` 是给程序用的那一份出场人物：角色页的「出场 N 章」、未建卡人物清单、更新角色卡时自动关联出场章，都读它。括号里是这一章对该角色的其它称呼。`## 出场人物` 小节是同一份信息给人看的形态，两者写盘时保持一致。

**连续性事实**是后面几章要接得上的事：谁受了什么伤、谁知道了什么、什么东西到了谁手里。每条后面挂一句**原文证据**——不是模型写的，是插件拿这条事实回到正文里按字面相似度找出来的那一句（零模型调用）；找不到证据的事实不写进来。写后面几章时，装配器拿这句证据回到原文取段落（见[上下文是怎么装配的](#上下文是怎么装配的)），而不是信摘要的转述。

手写的摘要、以及 0.2.x 之前生成的摘要没有 `cast` 字段，插件会从 `## 出场人物` 小节的文字里反解出名字，不会因此在角色页上少人。重新定稿一次就会补上这个字段。老摘要的 frontmatter 写的是 `plot:`，照样认。

模型没按 JSON 格式回答时（会发生）插件逐层降级：JSON → 认 `## 小节` → 实在不行把全文塞进「梗概」。无论哪一层，这一章的剧情都不会凭空丢掉。

### 摘要过期机制

正文写盘 → 重算内容 hash → 与摘要里记录的 `sourceHash` 比对 → 不一致就在工程页把那一章标成 `○`，主按钮也会落回「定稿第 N 章」。

摘要**不会自动重新生成**（避免后台偷偷烧 token），但工程页顶部会提示「有 N 章摘要缺失或已过期」，一键同步；切到别的页时，活动栏「工程」上会留一个小圆点提醒还有这件事没做。各章之间没有先后依赖，所以同步按 [`novel.concurrency`](#默认模型列表并发与-fallback) 并发跑（默认 3 路）。同步过程中任务条上有进度（已完成几章/共几章、已用时、可停止），每一章的成败、耗时与用的哪个模型都记在[日志页](#日志页)里；个别章失败不会中断整批，结束时会点名是哪几章，去日志里能看到具体原因。

### 角色卡不会被静默覆盖

`提取/更新角色卡` 与角色行右键的「更新角色卡」对已存在的角色一律先让你对比确认：插件打开 diff 编辑器，你可以在右侧直接改完再点采纳；独立版是一张只读的对比，采纳或放弃。模型留空的小节保留原文，别名和标签取并集。

批量更新时几张卡是并发分析的，但 **diff 一次只弹一张**，按完成顺序排队——同时弹三个 diff，谁也说不清自己在看哪一张。

不走 diff 的只有两种：**给还没有卡的人物新建角色卡**（包括角色图谱与细纲带出的新角色）——那张卡是刚建的，没有你写过的内容可覆盖；以及**定稿时更新「当前状态」那一节**——只在它自上次机器写入之后没被你改过时才直接写，改过就不写、挂黄 ❗（见[角色卡格式](#角色卡格式)）。

## 配置

设置页（侧边栏 → 设置）分为「模型配置」「上下文管理」「通用」「技能」几个二级页签（「通用」只有独立版有，放「新窗口中打开项目」）。「技能」页管写作技能（见上面「写作技能」），改了当场生效，不用点「保存设置」。模型页管理服务商、模型预算、分档与请求参数；上下文页单独管理近期原文注入、全书摘要分批和「写完正文删修饰」。API Key 按服务商存在 `~/.novelforge/secrets.json`，不写进配置文件。「模型配置」页里「模型分档 / 任务档位 / 请求与调度」这几块日常不常动的配置收在「高级设置」折叠开关下，展开才能看到。

### 服务商与模型

**两种协议，各认一条路**：`kind: "openai"` 走 OpenAI 的 **Responses 接口**（`/responses`，也就是 Codex 用的那一套），`kind: "anthropic"` 走 Anthropic 的 **Messages 接口**。这是「思考深度」这个开关唯一的落点——老的 `/chat/completions` 里「想多深」不是一个字段。

> **只认 `/chat/completions` 的服务商（DeepSeek、智谱、Kimi、通义、本地 Ollama 等）在 `openai` 这种 kind 下会 404**，报错里会点明这一点。要用它们，得在 `baseUrl` 填一个自己那侧的 `/responses` 兼容网关。

可以同时配置多个服务商，每个服务商下挂多个模型。模型用 **`前缀/模型名`** 引用，前缀就是服务商的 id：

```jsonc
"novel.providers": [
  {
    "id": "glm",                                              // 引用前缀
    "label": "智谱 GLM",
    "kind": "openai",                                         // openai / anthropic / vscode-lm
    "baseUrl": "https://open.bigmodel.cn/api/paas/v4",
    "models": [
      { "name": "glm-4-plus", "contextWindow": 128000 },
      { "name": "glm-4-air" }
    ]
  },
  {
    "id": "openrouter",
    "kind": "openai",
    "baseUrl": "https://openrouter.ai/api/v1",
    "models": [
      { "name": "z-ai/glm-4.6", "contextWindow": 200000 }     // 模型名自带斜杠
    ]
  }
],
"novel.model": "glm/glm-4-plus"
```

于是：

| 引用 | 含义 |
|---|---|
| `glm/glm-4-plus` | 智谱官方的 glm-4-plus |
| `openrouter/z-ai/glm-4.6` | OpenRouter 上的 GLM |
| `ollama/qwen2.5:14b` | 本地 Ollama |

**引用只在第一个斜杠处切分**，后面的都属于模型名——OpenRouter 的模型名本就是 `厂商/型号`，不这样切就没法引用。所以服务商前缀不能含斜杠，设置页会挡住。

同一个模型走不同渠道就是两条独立的引用，各有各的 baseUrl、各有各的 API Key，切换只要在输入框旁的下拉框里选一下（或用命令 `Novel: 选择模型`）。

**窗口与输出上限按模型单独设置**。同一家的 32k 和 200k 模型常常并存，装配器按真正执行任务的模型计算预算，所以切模型或切档位时预算会跟着变。设置页不再提供全局默认预算；模型留空时使用内置兼容值（窗口 128000、输出 4096）。旧配置里已有的 `novel.contextWindow` / `novel.maxOutputTokens` 仍作为兼容兜底读取，但不再作为新配置项展示。

设置页备了 3 个预设（OpenAI / Anthropic / Copilot），点一下**添加一整个服务商**（含常用模型和窗口大小），不会覆盖已有的。只认 `/chat/completions` 的那几家不再列进预设——点了就 404 的按钮比找不到更让人恼火，但手工添加仍然可以（填自己那侧的网关地址）。**协议类型在服务商配置弹窗里可以直接改**（从前只能由预设决定，手工加的服务商永远是 openai），换协议时接口地址会跟着填成对应的默认值。每个模型行右边有「测试」，当场发一个最小请求验证——比写半段才发现 Key 填错强。

API Key 按服务商 id 分开存。本地 Ollama 随便填一个非空值即可；`vscode-lm`（Copilot）不需要 Key，但模型有硬性输入配额，装配器会自动按其 `maxInputTokens` 收紧预算，明细里会标注「已按模型配额压缩」。

### 默认模型列表、并发与 fallback

设置页的「默认模型」是一份**排好序的清单**，不是单选。它管两件事：对话页当前用哪个模型（= 第一项），以及工程页后台任务里**没有配置档位的那些**用哪些模型——同步摘要、重建全书摘要、更新/批量更新角色卡、批量建卡、生成设定、提取文风、提取角色。配了[模型分档](#模型分档简单的活省钱难的活花钱)之后，下面这些规则在**每一档内部**同样成立：

- **串行时**（`novel.concurrency = 1`，或本来就只有一件事要做）恒用第一个模型；报错就在**其余模型里随机挑一个**重试，最多 `novel.fallbackAttempts` 次。同一个模型不会被试两遍，只有一个模型时不重试。
- **并发时**在整份清单里**轮转**取模型，把请求摊到几个服务商上——这往往是并发跑得起来的前提，单个服务商的限流额度撑不住几路并发。
- 用户点「停止」时立刻停，不会换模型重试。
- 备选模型缺 API Key 或当前环境不支持（如独立版里的 Copilot 模型）会被**排除在池外并写进日志**，不会为此连弹几个输入框。只有第一个模型缺 Key 时才会引导录入。

**对话页的单次生成不走这套**：你在输入框旁的下拉框里选了哪个模型，就必须是哪个模型写的正文——中途偷偷换人会让文风断掉。那个下拉框切换模型等于把它**提到列表首位**，所以设置页与对话页看到的「当前模型」始终是同一个。

并发只作用于**彼此无先后依赖**的条目：各章摘要之间、角色卡之间、全书摘要的各个阶段批次之间。补齐设定、批量拆细纲、批量写章一律串行——后一件要吃前一件的产出。同一张角色卡内部的分批仍然严格按顺序来（后一批要看到前一批的产出）；批量更新角色卡选「逐张确认」时，分析照样并发，但 diff 会按完成顺序**一张一张弹出**。

并发不改变总调用次数，确认框里报的「预计调用模型 N 次」在并发下依然准确；但它更容易撞上服务商的限流（429），配了多个模型时 fallback 正好接住这种情况。

> 从 0.1.x 升级：旧的 `novel.provider` / `novel.openai.*` / `novel.anthropic.*` / `novel.vscodeLm.family` 仍然生效——`novel.providers` 为空时会自动按它们生成一份服务商列表（前缀分别是 `openai` / `anthropic` / `copilot`），旧的 API Key 也会迁到新键上，不用重新输。在设置页保存一次即转为新结构。

### 模型分档：简单的活省钱，难的活花钱

工程页那几件事的难度差得很远。「把 76 章正文各总结一遍」是 76 次调用，每次只看一章、输出固定结构；「把几十份阶段摘要合并成一份全书摘要」全书只调一次，却要跨几十万字取舍主线。用同一个模型干这两件事，你只能在「贵而好」和「省而糙」之间二选一。

所以设置页把模型分成**三档**，每档各是一份有序清单（用法和「默认模型」完全一样，可排序、可多填几个做 fallback）：

| 档位 | 放什么模型 | 内置默认包含的任务 |
|---|---|---|
| **快速档** | 便宜、快的模型 | 单章摘要、全书摘要 · 分批汇总、设定 · 逐章识别 |
| **均衡档** | 折中的模型 | 设定 · 条目整合、角色卡 · 更新 / 建卡、剧情细纲、批量写正文、批量审稿 |
| **精标档** | 最聪明的模型 | 故事架构、全书摘要 · 最终合并、提取角色、提取文风 |

归档的判据是「调用次数 × 单次难度」：次数多而单次简单的归快速档；一次定调、错了代价大的归精标档（故事架构全书只跑一次，后面每一章都吃它；提取角色决定「谁是谁」，判错会污染整个角色体系；文风指南和角色卡每次写正文都要注入上下文，写砸了会一路影响下去）。

剧情细纲值得单说：它每批 5 章一次调用，量不算大，但**决定这几章讲什么、怎么转，写歪了那几章的正文整篇跟着歪**，而正文是最贵的一项——这一格省下来的钱会在下一格翻倍还回去，所以归均衡档而不是快速档。

**批量写正文**也在均衡档：它是量最大也最贵的一项，但正文的文风与语气直接决定成品质量，压到快速档等于用便宜模型写整本书。归均衡是折中——真要省钱或真要质量，改一格就行，默认值不该替你做这个取舍。

设置页的「任务档位」表里每项都是一个下拉框，不认同哪条默认改掉即可，标「默认」的就是内置推荐值。

几条要点：

- **不配就是不分档。** 某一档留空，归在该档的任务就沿用「默认模型」；三档都不配，行为和没有这个功能时**完全一样**。不会有任务被偷偷降级到便宜模型。
- **换模型只在档内。** 快速档的模型失败了，只在快速档里换人，绝不会自动升级到精标档——否则你以为在省钱，账单却按贵的算。
- **每档按自己的窗口切批。** 分批读正文时用的是**这一档首选模型**的上下文窗口，不是对话页那个模型的。所以快速档放 32k 的小模型也安全，不会因为你在对话页选了 200k 的模型就把一大堆正文硬塞进去。
- **确认框会说清这次用谁。** 动手前的弹窗里写的是「单章摘要 → 快速档：glm/glm-4-air」，档位没配时会明说「未配置，沿用默认模型」。
- **叙事线跟着它最像的那一档走**：「从细纲排出」走剧情细纲档（与拆细纲同一种活）；批量写章「写完即定稿」里判叙事线那一步走单章摘要档（与摘要同一种活）。单章定稿用的是你在对话页选的那个模型。
- **对话页的单次生成不受影响**，永远用你在输入框旁选的那个模型。外部 agent 经 MCP 生成架构与细纲时不一样：它们走「故事架构」「剧情细纲」两档，与工程页补齐设定、批量拆细纲是同一个模型；正文与大纲仍用你选的那个。

一个典型配法：快速档放 `glm/glm-4-air` 或 `deepseek/deepseek-chat`，精标档放你写正文用的那个好模型，均衡档留空（自动沿用默认模型）。一部几十万字的书跑一轮全量摘要，光这一项就能省下大头。

### 代码结构

核心与壳分离：`src/core/` 零 vscode 依赖，三个壳并排放在 `src/shells/`，各实现一个 `Host` 窄接口。
壳只做三件事——实现 `Host`、传输与生命周期、平台专属入口；业务逻辑、页面内容、以及
「我是哪个壳」的分支都不属于壳（契约见 [src/shells/README.md](src/shells/README.md)）。

```
src/
├── core/                  ★ 宿主无关核心（永不 import vscode）
│   ├── host.ts            Host 窄接口（弹窗/进度/监听/打开文件），双壳各实现一份
│   ├── controller/        ★ ChatController：面板逻辑，经 ViewHost 与视图解耦
│   ├── protocol/          前后端消息协议（+ 独立版 prompt/promptResult、编辑器消息）
│   ├── config.ts          readConfig/updateSettings，数据源由 ConfigStore 注入
│   ├── stores.ts          FileConfigStore/FileSecretStore（~/.novelforge/）
```

面板逻辑集中在 `core/controller/`，两个视图宿主（侧边栏 / 编辑器）与独立版 WebSocket 各自只负责收发消息，因此同一个会话能在多处同时打开且保持同步。

界面不使用 VS Code 自带的 TreeView 等控件，全部由 webview 渲染：一套 UI 同时供侧边栏和编辑器标签页使用，工程页与对话页共享同一个 tabbar，不再上下分栏。`projectView.ts` 只产出一份可序列化快照（任意深度的 `ProjectNode` 目录树），展开/折叠状态留在前端。

关于 token 计数：默认实现是按字符类别加权的粗估（中文 ×1.5、拉丁 ÷4），没有引入 tiktoken——体积大、要 wasm，且各家分词器本就不同，粗估只要保证不低估，加上 512 的安全余量就够用。

但计数本身是**可替换**的：`context/tokenCounter.ts` 定义了 `TokenCounter` 接口与一张注册表，想接 tiktoken 或某家服务商的 count_tokens 接口，写一个实现注册进去、切过去即可，装配器一行都不用改。切换失败（加载不了词表之类）会退回默认实现并返回 false——数不了 token 不该把写作流程带停。

服务商返回真实用量时（OpenAI 的 `stream_options.include_usage`、Anthropic 的 `message_start` / `message_delta`）插件会记下「估算 / 实测」的比值，写进日志里供你判断这个数字靠不靠谱。这份统计**不会反过来自动修正估算值**：估算必须是纯函数，否则同一份上下文两次装配会得出不同的预算判断，上下文明细也就不可复现了。
