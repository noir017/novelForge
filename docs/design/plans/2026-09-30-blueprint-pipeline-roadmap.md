## 0. 结论

1. **链路整条搬过来**：一句话 → 设定 → 前提 / 角色图谱 / 世界观 / 情节大纲 → 细纲（一章一份，每批 5 章）→ 正文（自动续写到目标字数的 80%）→ 定稿（摘要 + 连续性事实 + 角色当前状态）→ 审稿（逐字引证 + 目标核对）→ 按勾选的意见最小改动修稿 → 串行批量。只有和「写得好不好」无关的发行级工程不搬，逐项取舍见 §1。
2. **顺手修掉上游自己的四个缺口**：
   - 角色设计原则没发给模型；
   - 英雄之旅、节拍表两种结构没有章号区间；
   - 单章入口的执行卡漏了章末钩子；
   - 精修不带上下文。

   另外不搬它写死的 8192 输出上限。
3. **WebUI 从「对话页驱动」改成「工程页就是进度」**：
   - 工程页每一行都带状态，只有下一章给「写这一章」的按钮；
   - 任务进度在所有页签都看得见；
   - 细纲和正文可以并排看；
   - 覆盖和修稿一律走 diff，并且能逐段采用。

   量化目标：从一句话写到第 3 章，现在约 **44 次点击、3 次手动切页**（推断，见 §3.1）。改完后单步路径 **≤ 22 次**，批量路径 **≤ 10 次**。
4. **分八期（零到七）**：
   - 三期结束是**真实模型验收关卡**：前 3 章读得下去才往下做。
   - 七期做叙事线；导入已有小说延后，不排期。
   - 每期结束 `npm run typecheck` + `npm run test:node` 全绿，工程**始终能跑**，不留半截状态。
5. **量级**：src 删约 1.5k 行、重写约 4.7k 行、新增约 5–6k 行（core 约 3k，前端约 2.5k）；测试重写或新增约 7k 行。

### 2.2 状态机（`model/pipeline.ts` 重写）

- **创作阶段**：`setting | outline | plot | manuscript`。`setting` 下有四个 target：`config / premise / characters / world`。
- **能力**：保留 `discuss / generate / settle`；新增 `review`，只挂在正文层；删掉 `split`。
- **一条轴**：细纲号 = 章号。删掉 `segmentDisplayNo`、`volumeLabel`、`segmentLabel` 等位次和称呼函数。

**全书下一步**（`deriveBookNextStep`，按顺序取第一个不满足的）：

| 状态 | 主按钮 |
|---|---|
| 没有 `config.md` | 生成设定（打开「一句话」弹窗） |
| 前提 / 角色 / 世界观缺哪一件 | 生成前提 → 生成角色图谱 → 生成世界观（按顺序一件一件推） |
| 没有大纲，或下一批细纲超出大纲覆盖的章号 | 生成情节大纲（第 a–b 章） |
| 下一可写章没有细纲 | 拆细纲（第 N–N+4 章） |
| 进入单章状态机 | ↓ |

**单章下一步**（`deriveNextStep`，「下一可写章」= 连续已有正文的最大章号 + 1）：

| 状态 | 主按钮 |
|---|---|
| 有细纲、没正文 | 写第 N 章 |
| 正文不到 `targetWords` 的 80% | 接着写 |
| 细纲在正文之后改过（hash 不符） | 重写第 N 章 |
| 正文写够，摘要缺失或过期 | 定稿第 N 章（摘要 + 角色状态，2 次调用） |
| 都齐 | 跳到下一可写章 |

审稿**不进主按钮**，它是可选动作，放在正文层的 `/审稿` 和章节工作台的工具栏里。第 20 条「只推一个下一步」不变。

**指纹链**（第 18 条重写）：`config / premise / characters / world` → `outline` → `plot` → `chapter` → `summary`。每一环的上游指纹都记在下游：
- 细纲记在 frontmatter；
- 正文记在 `project.json` 的 manifest（沿用从前放 `beatsHash` 的位置）；
- 摘要记 `sourceHash`。

链上不再有「拆分」这道人工闸口：已经定稿的章只挂 ⟳ 提醒，不会被推回「待写」。

### 2.4 生成机制

- **续写循环**：放在 `generation/`，不放进 feature。
  - `generate.ts` 的流式循环接上 `stop` 事件（现在忽略了它，`generate.ts:211-225`）。
  - 停止原因是 `maxTokens`，或者正文不到目标的 80%，就续写。续写提示词带最后 1600 字 + 细纲 + 执行卡。
  - 同一个 Draft 里追加，界面实时显示「第 k 轮 · 已写 x / 目标 y 字」。
  - 最多 7 轮。一轮新增 <300 字且又被截断：丢弃这一轮，只给 1 次恢复机会。
  - 思考把输出预算耗光（截断且正文 <100 字）：直接报「输出上限不够思考」，提示调大 maxOutputTokens 或降低思考深度。
  - 最后仍不到 80%：报「未写够」，**已写的内容不丢**，卡片照样可以「写入」。
- **调用次数写在动手之前**（D16，第 4 条）：
  - 单步按钮和卡片上写「1 次；未写够时自动续写，最多再 7 次」；
  - 批量确认框按上限报。
- **重演检测**：只在续写结束之后跑一次。命中时卡片上标红，写明重合的原句。按钮仍可点，但要二次确认。

### 3.2 从 AI-Novel-Writer 借的交互（按性价比）

1. **工程树就是进度条**：每个节点带计数或状态徽章，比如「设定 3/5」「细纲 25/100」「正文 12/100」（上游 `ProjectTree.tsx:283-336`）。

3. **覆盖语义直接写在按钮或勾选项上**：将覆盖 / 保留 / 待生成（`ArchitectureConfirmDialog.tsx:270-281`）。

### 五期 · 审稿 + 修稿 + 预检（M）

- **`review`**：一次调用出报告 JSON，1–10 条，每条带逐字引文；目标核对清单逐项判定。
- **引文校验**：在正文里逐字找（归一化空白和标点后），找不到的条目丢弃；目标核对里找不到引文的降成「待核实」。「没写到」只能判待核实，不能判未完成。
- **修稿**：只把勾选的条目塞进 `revision` 层，要求最小改动；续写最多 3 次；完整性校验照搬 `refinement-completeness.ts:3-41`；覆盖前走 diff。
- **精修**：补上本章细纲作上下文（修上游的缺口）。
- **一致性预检**：零调用，警告挂在写章卡片上，可以「仅本次忽略」。
- **前端**：W10 审稿报告卡、W11 diff / 合并视图。
- **验收**：伪造引文的条目被丢弃；修稿后长度低于阈值时报错；diff 视图里「采用」不会冲掉手改过的段（DOM 测试）。

### 六期 · 收尾（M）

- **agent 工具**：`generate`、`run`、`list`、`search`、`naming` 的描述和枚举改成新链路的；`TIER_TASK` 的档位表加 `setting` 和 `review`。
- **文档**：
  - README 重写「从脑洞到成书」「工程页」「对话怎么用」「下一步」「目录结构」「摘要格式」这几节；
  - AGENTS.md 第 4、8、14、18、19、20、21、22、23 条按新链路改写。**编号不动**：第 23 条（拆分）原位替换成「定稿是这条链上唯一的人工闸口」一类的新断言，不删号；
  - 各模块 README 同步；
  - 修掉 AGENTS.md 里「卷不是一个阶段」这类早已和代码对不上的说法（代码里卷是真阶段）。
- **清死代码**：卷、段、中转站的 CSS、协议字段、LEGACY 兼容表里已经没人用的分支。
- **前端**：W12；W13 手动走一遍，记录点击数。
- **验收**：全量测试通过（含 e2e）；独立版从一句话手动走到第 3 章（单步、批量各一遍）；桌面壳能起来。

### 七期 · 叙事线（M）

- `threads.md`（每条线：名称 / 状态 / 计划回收区间 / 事件列表）。
- 从细纲生成 3–8 条计划（1 次调用），从定稿生成 ≤5 条事件，证据必须逐字。
- 写作时带 ≤6 条活跃线（≤1200 字）。

「导入已有小说」（从现有 `chapters/` 反推设定和细纲）延后，不排期，等有老工程要接上新链路时再做。

## 7. 测试策略

- **假模型**：零期扩展后能脚本化多轮回复和 stop 原因。续写、截断、修复链全靠它测，不花钱。
- **测试怎么动**：
  - 老流水线的测试**先删后写**，不在旧断言上修修补补；
  - 通用的测试（预算器、agent 循环、工具注册表、runtime、角色卡、lore 等，约 9k 行 src 对应的那部分）一律不动，它们变红就说明改错了。
- **夹具**：sample-novel 重做时 3 章正文不动，只改 `.novelforge/` 下的东西。
- **契约测试**：corePurity、shellPurity、layerBoundary 全程守着分层。
- **真实模型**：只在三期验收时跑一次，之后每期结束可以选跑前 1 章做冒烟（每次约 3–5 次调用，要你点头才跑）。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 提示词搬过来了还是写不好 | 三期设了关卡，不过关不往后做；问题收敛在提示词和配方上，那两处改起来最便宜 |
| 一期改动面最大，中途工程跑不起来 | 一期结束的验收要求独立版能打开、主按钮正确；一期内部按「model → workspace → views → protocol → 前端」自底向上，每个 commit 编译通过 |
| 思考模型把输出预算吃光 | §2.4 专门识别这种情况并报错，提示调大 maxOutputTokens 或降低思考深度 |
| 自动续写把账单拉高 | 上限 7 轮，调用次数写在动手之前；批量不带思考 |
| 从 GPL 项目搬提示词 | AGPL 与 GPLv3 按 §13 可以组合；移植处在注释里注明来源 |
| diff 视图自己写有 bug | 段级 LCS 是纯函数，单测覆盖；VS Code 壳不用它 |
| 老工程打开后什么都没有 | D11 已接受；「导入已有小说」是补救路径（已延后） |
